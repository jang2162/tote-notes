# 성능 측정 규칙 — 사전 등록 사본

tote-notes 안전망 계획 Task 16 의 「사전 등록 규칙」을 **데이터를 보기 전에** 그대로 옮긴 사본이다. 정본은 계획(`docs/superpowers/plans/2026-10-12-tote-notes-safety-net.md` 「Task 16: 성능 계측과 목표치」)이다. 실행 중에 이 파일을 바꾸지 않는다.

맨 아래 「측정 전에 더한 것」은 계획의 사전 점검 판정(M10·M11·L13)이 측정 전에 정한 것이다. 규칙·목표치를 바꾸지 않고, 빌드와 호출 방법·정의의 한 줄만 더한다.

## 사전 등록 규칙(데이터를 보기 전에 고정한다)

- **빌드·기기:** `perf` 프로필(릴리스 최적화 + `debug-assertions`), 내장 디스플레이, 전원 연결, 측정 중 다른 작업 없음. 시작 전 `uptime` 의 1분 load average 가 **3 미만**이어야 시작한다(아니면 기다린다). 기기·macOS 판·디스플레이를 보고서 「환경」에 적는다.
- **반복과 판정:** 시나리오마다 **5회**, 지표는 **중앙값**으로 판정하고 p95 도 적는다. 중앙값 ≤ 목표면 「된다」, 목표의 2배 이하면 「조건부」, 그보다 크면 「안 된다」. 조건부·안 된다는 고치지 않고 **보고서에 적고 사람에게 올린다** — 이 계획은 재는 계획이지 성능 계획이 아니다(고칠지는 다음 계획에서 정한다).
- **유효성:** 한 회의 `perf.jsonl` 에 해당 마크가 없거나 중복이면 그 회는 무효. 무효가 둘 이상이면 시나리오 전체를 다시 5회. 그래도 무효면 「실측 불가」로 적는다.
- **시나리오와 목표치**(지표 = 두 마크의 차):

  | 시나리오                            | 조건                                                                                                                                                 | 지표                               | 목표                                            |
  | ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- | ----------------------------------------------- |
  | 콜드 스타트                         | 빈 워크스페이스 하나, 세션 없음. 앱을 끄고 **10초 뒤** 다시 띄운다(디스크 캐시는 따뜻하다 — 「콜드」는 프로세스 기준이다. 재부팅 콜드는 재지 않는다) | `process-start` → `app-ready`      | **1,500ms**                                     |

- **재지 않는 것(미리 적는다):** 키 입력 지연(스파이크와 2번 계획 Task 14 가 이미 사전 등록 절차로 쟀다; 이번 하이라이트 변경(Task 15) 뒤 **같은 절차** `pnpm measure:long-line` 을 한 번 다시 돌려 `LONG_LINE_LIMIT` 판정이 바뀌지 않는지만 본다), 스크롤 프레임(계측 지점이 없다 — 다음 계획), Zed·Sublime 과의 수동 비교(사람 판단 필요), 한글 조합 키 지연(스펙이 「따로 재는 방법이 필요하다」고 한 것 — 다음 계획).

## 측정 전에 더한 것(사전 점검 판정)

- **M11 — 의존 크레이트의 `debug-assertions`.** `perf` 프로필의 `debug-assertions = true` 는 tote 크레이트에만 건다(`[profile.perf.package."*"] debug-assertions = false`). tauri·wry·tao 의 `cfg(debug_assertions)` 분기가 켜지면 「릴리스 최적화 그대로」라는 전제가 흐려진다. `TOTE_BACKGROUND` 와 `tote-dev` 기본 경로는 tote 크레이트 안의 `cfg!` 라 그대로 먹는다. `TOTE_DATA_DIR` 은 빌드와 무관하게 먹는다.
- **M10 — `tote <파일>` 의 호출 경로.** 측정 스크립트는 `PATH` 의 `tote`(사람의 앱일 수 있다)도, 번들 안의 `tote` 스크립트(`open -n` 이라 환경 변수가 가지 않는다)도 부르지 않는다. **perf 번들의 실행 파일에 `TOTE_DATA_DIR` 과 `--tote-request=<json>` 을 직접 넘긴다** — `tote <파일>` 이 앱에 넘기는 것과 같은 요청이고, single-instance 가 떠 있는 측정 앱으로 넘긴다. 시작 전에 `tote-dev` 가 떠 있으면 멈춘다.
- **L13 ① — 세션 파일 이름.** `sessions/<기기>.json` 의 이름은 `machine.json` 의 `deviceId` 다. 픽스처가 `machine.json` 을 미리 써 두고 그 ID 로 세션 파일을 만든다.
- **배경 창의 rAF(코디네이터 판정 A, 측정 전).** `TOTE_BACKGROUND=1` 창은 화면에 올라오지 않아 WKWebView 가 `requestAnimationFrame` 을 돌리지 않는다(파이프라인 스모크 — 시나리오가 아닌 `code-1mb.ts` 1회 — 에서 60초 동안 `open-first-paint` 가 없었다). 그래서 rAF 로 찍는 `open-first-paint`·`restore-done` 을 쓰는 시나리오(파일 열기 5개, 세션 복원)는 배경 측정에서 **실측 불가**로 적고, 같은 스크립트를 화면에 띄워(`PERF_FOREGROUND=1`) 사람 동의 뒤에 잰다. 마크 정의·목표·판정은 바꾸지 않는다.
- **감시 배치 비용(앞 태스크에서 넘어온 항목, 목표 없음 — 기록만).** 감시 배치는 워크스페이스 잠금을 쥔 채 폴더를 `read_dir` 하므로, 그 시간만큼 같은 워크스페이스의 저장이 기다린다. 지표: 한 회 = 앱을 띄우고 창이 선 뒤 메모 하나를 저장처럼(같은 폴더의 임시 파일에 써서 rename) 바꾸고 2초 기다린 것, 값 = 그 회의 `watch-batch-start` → `watch-batch-done` 쌍의 **합**(배치가 둘로 나뉘어 와도 한 저장의 몫). 쌍이 없거나 짝이 안 맞으면 무효. 워크스페이스 둘: `memos-10k`(1만 개)와 `restore-50`(50개, 비교 기준). 5회, 중앙값·p95, 판정 없이 사람 판단 필요로 올린다.
- **L13 ② — 「콜드 스타트」의 출발점.** `process-start` 는 `main` 의 첫 줄이라 dyld·exec 시간이 빠진다. 지표는 「`main` 진입 → `app-ready`」다.
