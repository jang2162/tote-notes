# tote-notes 편집기 검색 띠(⌘F) — 화면 확인 목록

이번에도 **실제 앱을 띄워 사람 손으로 확인하지 않았다.** 아래는 나중에 사람이나 화면을 쓸 수 있는 에이전트가 하는 절차와 기대값이다. 「결과」 열은 2026-10-25 에이전트가 채웠다. main `1cc500b` 번들로 처음 돌렸을 때는 macOS 권한 확인 창이 키 입력을 막아 모든 행이 보류로 남았고, 같은 날 main `380e535` 디버그 번들로 다시 돌려 「2026-10-25 재개」 로 적었다. 가짜 백엔드 e2e(Playwright WebKit, `tests/e2e/search-bar.spec.ts`)와 vitest 가 이미 덮는 것은 넷째 칸에 적었다. 그 시험은 **실제 WKWebView·실제 네이티브 메뉴·실제 한글 입력기를 보지 않는다.** e2e 는 메뉴 단축키를 누르지 못한다(`docs/guides/development.md` 「e2e 는 메뉴 단축키를 누르지 못한다」).

## 공통 준비

```bash
pnpm tauri build --debug --config src-tauri/tauri.dev.conf.json
S=$(mktemp -d); touch "$S/start-marker"
# 워크스페이스는 앱 밖에서 만든다: $S/workspaces/Alpha/.tote/workspace.json = {"version":1,"id":"<uuid>"}
open --env TOTE_DATA_DIR="$S" src-tauri/target/debug/bundle/macos/tote-dev.app
```

- `~/Tote` 는 쓰지 않는다. `~/Tote-dev`·`~/Library/Application Support/tote-dev` 는 사람의 개발 앱 것일 수 있으니 지우거나 고치지 않는다(`find … -newer "$S/start-marker"` 가 비어 있는지로 판정).
- 화면을 쓰기 전에 `ioreg -n Root -d1 -a | grep -A1 CGSSessionScreenIsLocked` 가 false 인지 본다. 화면 좌표로 클릭하지 않는다(`--element-index` 나 요소 이름으로).
- 다크·라이트는 시스템 설정 › 모양에서 바꾼다. 바꾸기 전 값을 적어 두고 끝나면 되돌린다. 테마 고르기는 설정 › 테마.
- 준비 메모 세 개: **짧은 메모**(`my notes` 가 든 몇 줄), **큰 메모**(줄마다 `a a a a` 가 든 수만 줄, `a` 의 결과가 수만 개. 한 줄이 너무 길면 메모가 안 열리니 줄을 나눈다), **결과가 적은 큰 메모**(C-1b 용. 보통 문장이 든 수십만 줄로 수 MB, 예: 10MB).

## 다음 계획으로 넘기는 것

구현 중 미룬 것. 모두 동작을 막지 않는 Minor 이거나 표본이 모자란 관찰이다.

- **Task 1 Minor:** `src/styles.css` 의 새 변수와 `src/theme/vscode-theme.ts` 의 `DEFAULT_VARIABLES` 가 같은 값인지 고정하는 시험이 없다(둘을 손으로 맞춘다). 대비 계산 도구(`contrast`)가 `hsl()` 색을 읽지 못한다(지금 변수는 모두 hex). (안정화 후속에서 해결, 커밋 `c61b878` `090dc1c`)
- **Task 2 Minor:** 개수 세기의 1000 경계(정확히 1000개에서 `capped:false`, 선택이 1000번째 결과일 때 `current` 1000)를 가르는 시험이 없다. 빈 일치 정규식 시험(`search-count.test.ts`)이 `total <= 상한` 만 단언해 약하다(`^` 는 100줄이면 100 이어야 한다는 식의 기대값을 더한다). 커서 위의 빈 일치가 current 로 잡히는 것이 의도임을 시험 한 줄로 못 박는다. (안정화 후속에서 해결, 커밋 `c61b878`)
- **e2e 잡음:** `Cross-origin script load denied …` 줄이 이 브랜치의 e2e 에서 세 번 중 한 번 보였다. base 표본이 모자라 변경 탓인지 가를 수 없고, Task 5 수정 회차의 전체 e2e(360 개, 부하 37)에서는 나오지 않았다. 표본이 적으니 다음 계획에서 계속 본다.
- **기존 부하성 실패:** `windows.spec` 의 재시작 복원 시험이 부하가 걸린 전체 실행에서 실패한다(이 브랜치 이전부터). (안정화 후속에서 해결, 커밋 `c128a80`)
