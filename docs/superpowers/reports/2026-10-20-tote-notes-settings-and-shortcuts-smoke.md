# tote-notes 설정 화면·줄번호·단축키 설정 — 화면 확인 목록

이번에도 **앱을 띄우지 않았다.** 사용자가 「마우스·키보드가 필요한 작업은 나중에」 라고 해서, 계획에서 화면 확인을 빼고 이 문서에 절차와 기대값만 적어 두었다. 「결과」 열은 2026-10-25 에이전트가 main `1cc500b` 디버그 번들로 확인해 채웠다(「보류」 는 macOS 권한 확인 창이 키 입력을 막아 남긴 행). 가짜 백엔드 e2e(Playwright WebKit)와 Rust 시험이 이미 덮는 것은 각 행의 넷째 칸에 시험 파일을 적었다. 그 시험은 **실제 WKWebView·실제 네이티브 메뉴·실제 키 입력을 보지 않는다.** 특히 e2e 는 메뉴 단축키를 누르지 못한다(가짜 백엔드가 메뉴 id 를 직접 보낸다. `docs/guides/development.md` 「e2e 는 메뉴 단축키를 누르지 못한다」).

## 공통 준비

```bash
pnpm tauri build --debug --config src-tauri/tauri.dev.conf.json
S=$(mktemp -d); touch "$S/start-marker"
# 워크스페이스는 앱 밖에서 만든다: $S/workspaces/{Alpha,Beta}/.tote/workspace.json = {"version":1,"id":"<uuid>"}
open --env TOTE_DATA_DIR="$S" src-tauri/target/debug/bundle/macos/tote-dev.app
```

- 화면을 쓰기 전에 `ioreg -n Root -d1 -a | grep -A1 CGSSessionScreenIsLocked` 가 false 인지 본다. 잠겨 있으면 하지 않는다.
- **화면 좌표로 클릭하지 않는다.** `orca computer` 의 `--element-index` 나 System Events 요소 이름으로만 누른다. 키는 `orca computer press-key`·`type-text` 나 메뉴 항목 클릭(`click menu item "<이름>" of menu 1 of menu bar item "<메뉴>" of menu bar 1`)으로 보낸다. 다만 **단축키가 메뉴에 실제로 걸렸는지는 메뉴 항목을 클릭하는 것으로는 알 수 없다** — 메뉴에 표시된 키(`AXMenuItemCmdChar`·`AXMenuItemCmdModifiers`)를 읽고, 키 입력은 `press-key` 로 따로 보낸다.
- 개발용 폴더 `~/Tote-dev`·`~/Library/Application Support/tote-dev` 는 사람의 개발 앱 것일 수 있다. 지우지 않고 `find ~/Tote-dev "$HOME/Library/Application Support/tote-dev" -newer "$S/start-marker"` 가 비어 있는지로 판정한다.
- 디버그 번들도 `beforeBuildCommand`(`pnpm build`)로 같은 프런트엔드 빌드를 쓰므로 압축·`keepNames` 가 배포 빌드와 같다. 이름 확인(C-1)은 이 번들로 한다.
- 단축키 시험의 「바꿀 키」 는 **⌃⌥⌘J** 를 쓴다(기본값·고정·편집기 키 어디에도 없다).
- `debug_assert`(A-10)를 보려면 앱을 `open` 이 아니라 터미널에서 직접 띄워 stderr 를 읽는다: `TOTE_DATA_DIR="$S" src-tauri/target/debug/bundle/macos/tote-dev.app/Contents/MacOS/<실행 파일>`.
- 다크·라이트는 시스템 설정 › 모양에서 바꾼다. 바꾸기 전 값을 적어 두고 끝나면 되돌린다.

## 미룬 화면 확인 (에이전트)

**보는 순서(최종 리뷰 권고).** A-1(메뉴 표시가 바로 바뀌는가) → A-8·A-9(창 이벤트가 단축키를 되돌리는 연결부, 자동 시험이 없다) → B-3(메뉴 대 편집기 우선순위). B-3 이 「편집기가 먼저 받는다」 로 나오면 「가립니다」 경고와 스펙의 근거가 틀린 것이므로 **설계를 다시 연다.**

**최종 리뷰가 판단하지 않은 것 중 화면에서 볼 것.** ① ⇧+기호 조합(⌘⇧+숫자 등)을 녹음해 실제 NSMenu 에서 눌리는가(기본값 ⇧⌘[·⇧⌘] 는 이미 된다). ② 비 US 자판에서 `event.code`(물리 키)로 녹음한 단축키가 NSMenu 의 글자 기준 매칭과 어긋나는가. 결과와 쓰는 자판을 함께 적는다.
