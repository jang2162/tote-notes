## 다름 둘 — 한글과 커서·선택 여럿

**사람의 결정.** 커서 여럿·선택 여럿에서 한글을 치면 **모든 커서·선택에 같은 글자**가 들어가야 한다(영문 입력·Zed 와 같다). 스펙의 「조합이 시작되면 주 선택만 남긴다」는 기술 제약의 타협이었으므로 목표를 바꾸고, **병합 전에 고친다.**

**근본 원인**(실제 WKWebView 에서 기록한 이벤트 순서, `ime-2-report.md`). macOS 한글 입력기는 글자를 두 경로로 넣는다 — 조합 이벤트 없이 `insertText`·`insertReplacementText` 로 바로 넣는 직접 경로와 `compositionstart/update/end` 의 조합 경로 — 그리고 키마다 어느 쪽을 탈지가 다르다. 직접 경로의 첫 자모는 조합 이벤트가 없어 CodeMirror 가 평범한 입력으로 보고 **모든 커서에 복제**했고, 그 뒤의 음절 갱신(`ㄱ`→`가`)은 CodeMirror 가 주 선택에만 적용했으며, 조합이 열리면 「주 선택만 남기기」가 나머지 선택을 버려 **첫 자모만 다른 자리에 남았다.** 거기에 캐럿 앞 줄에 글자가 들어가면 입력기가 음절을 새로 시작해(`가` 대신 `ㄱㅏ`), 마지막 ⌥클릭이 어디였는지에 따라 결과가 매번 달랐다. 다른 자리의 자모는 입력기가 아니라 CodeMirror 가 넣은 것이다.

**수정.** `11c5c30` — 범위가 여럿이면 주 선택을 항상 맨 앞 범위로 두고(복제한 글자가 캐럿 뒤에만 들어가게), 직접 경로의 음절 갱신을 나머지 범위에도 반복하고, 조합은 주 선택에서만 하되 끝에 확정 글자를 기억해 둔 범위 전부에 넣는다. 기록된 이벤트 순서를 재연하는 E2E 가 옛 코드에서 스모크·기록과 같은 값(`가 ㄱ`, `사과ㄱ`/`배ㄱㅏ나`/`귤ㄱ`)으로 실패하고 새 코드에서 통과한다. `c21d89a` — 스펙 「편집기」 절과 계획의 Task 15 행을 새 목표로.

**실제 입력기로 다시 확인한 결과(사람).**

1. 커서 셋 + `가나` → 세 줄 모두 `가나`. 다른 커서에는 음절이 완성된 뒤에 보인다(미리보기는 주 선택에만).
2. ⌘D 두 선택 + 한글 → 파일 `가나 가나`(두 선택 모두 바뀜).
3. 조합 중 Esc → 세 줄 모두 `ㄱ`. macOS 입력기가 Esc 를 확정으로 처리한다 — 모든 자리가 같으므로 받아들임.
4. 영문 멀티커서·⌥드래그 사각 선택·⌘D → 그대로.

## 확인하지 못한 것·지켜볼 것

- **창 크기 복원**(8행): 사람이 크기를 바꾸지 않아 확인되지 않았다. 위치와 탭은 돌아왔다.
- **한때 사라진 메모 탭 여섯**: `메모` 창의 세션이 어느 시점에 `x.sh` 탭 하나만 남기고 메모 탭 여섯(장보기·긴 메모·quick note…)을 잃었다. 사람은 직접 닫았는지 기억하지 못하고, 창 닫기 → Dock 재열기(14b)로는 재현되지 않았다. 알려진 후보 경로는 시작 때 메모 목록 조회가 실패하면 메모 탭이 빠지는 것(Task 14 리뷰 Minor 1). **3번 계획에서 지켜본다.**
- **⌘⌥⇧T 같은 단축키가 한글 입력기 상태에서는 앱에 닿지 않았다**(진단 기록을 꺼낼 때 영문 입력기로 바꿔야 했다). 입력기가 그 조합을 먼저 가져가는 것으로 보인다. 앱의 단축키는 아니지만 한글 입력기와 수정키 조합을 쓰는 기능을 만들 때 참고.
