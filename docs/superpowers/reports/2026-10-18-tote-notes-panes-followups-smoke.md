## 공통 준비

```bash
pnpm tauri build --debug --config src-tauri/tauri.dev.conf.json   # exit 0, 01:11
S=$(mktemp -d)                                                      # /var/folders/…/T/tmp.8GdDhgjci6
# 워크스페이스는 앱 밖에서 만들었다: $S/workspaces/<이름>/.tote/workspace.json = {"version":1,"id":"<uuid>"}
open --env TOTE_DATA_DIR="$S" --env TOTE_BACKUP_INTERVAL_SECS=600 src-tauri/target/debug/bundle/macos/tote-dev.app
```

- 워크스페이스: `가나다`, `Beta`, 나중에 `Gamma`, E-11 용 `Delta`·`Epsilon`.
- 저장 실패: `chmod a-w "$S/workspaces/<이름>"` 후 편집기에 글. 상태 표시줄 `오류: Permission denied (os error 13)`, 탭 제목에 `⚠`.
- 편집기 입력: `orca computer set-value`(검증됨 `verified`) 또는 System Events `set value of text area 1 of … window "<이름>"`(요소 경로, 좌표 아님).
- 버튼: `orca computer click --element-index` 또는 System Events `click button "<이름>" of …`. 좌표 클릭은 쓰지 않았다.

### 전환 중 CLI 요청 (Task 4)

브리프의 `tote -w <대상> -i <파일>` 의 `-i` 는 CLI 에 없는 옵션이다(`src-tauri/src/cli/mod.rs` 「parse_args」 는 `--import` 만 안다). 같은 뜻의 요청을 `docs/guides/development.md` 대로 번들 실행 파일에 직접 넘겼다.

```bash
TOTE_DATA_DIR="$S" src-tauri/target/debug/bundle/macos/tote-dev.app/Contents/MacOS/tote \
  '--tote-request={"workspace":"Beta","files":["<임시 폴더>/cli-import.md"],"import":true}'
```

## 정리

```bash
osascript -e 'tell application "tote-dev" to quit'   # exit 0, 질문 없음(모든 폴더 chmod -R u+w 뒤)
pgrep -lf tote-dev.app                               # 없음
rm -rf "$S" <CLI 파일 임시 폴더>                       # 둘 다 지움
ls -d ~/Tote-dev "$HOME/Library/Application Support/tote-dev"
```

**불합격: 두 폴더가 있다.** G-2 「그래도 닫기」로 앱이 정상 종료(`osascript` 0, 01:14:41)한 직후 01:14:42 에 `TOTE_DATA_DIR` 없이 tote-dev 가 다시 떠서 만들었다. 내가 띄운 것이 아니다. 그 마지막 클릭에 쓴 `orca computer click … --restore-window` 가 끝난 앱을 다시 띄운 것으로 본다 — 이후 앱을 끝내는 클릭(G-3, 전환 「그래도 바꾸기」)에서 `--restore-window` 를 뺐더니 다시 뜨지 않았다.

- 안의 것: `~/Tote-dev/메모/.tote/{workspace.json,index.json,sessions/<1개>.json}`(메모 파일 없음), `~/Library/Application Support/tote-dev/{state.json,machine.json,backups/<빈 폴더>}`. 모두 01:14–01:15 에 처음 생김. 그 인스턴스는 `osascript … quit` 으로 껐다.
- 코디네이터(사람 승인)가 지우라고 했으나 `rm -rf` 가 Claude Code 권한 분류기에 막혀 지우지 못했다. **사람이 지워야 한다:** `rm -rf ~/Tote-dev "$HOME/Library/Application Support/tote-dev"`. 01:15:11 이후로 두 폴더 안에 바뀐 파일은 없다(`find … -newermt '2026-10-19 01:16'` 결과 없음).
- 모든 `chmod a-w` 는 `chmod -R u+w "$S/workspaces"` 로 되돌린 뒤 `$S` 째 지웠다.

## 도구의 한계

- **`orca computer … --restore-window` 는 끝난 앱을 다시 띄운다.** 그 클릭이 앱을 끝내면 도구가 앱을 다시 활성화하며 LaunchServices 로 실행해, `TOTE_DATA_DIR` 없는 기본 폴더 두 곳에 쓴다. 앱을 끝낼 수 있는 클릭에는 `--restore-window` 를 주지 않는다.
- **`orca computer` 의 창 고르기가 틀린다.** 같은 크기의 창 둘이 겹쳐 있으면 `--window-id`·`--window-index` 를 줘도 다른 창(`Beta`)을 잡거나 `window_not_found` 를 낸다. 이때는 System Events 의 요소 경로(`… of window "<제목>"`)로 대신했다.
- **사람이 쓰는 Orca 가 전체 화면 Space 에 있어** tote 창은 다른 Space 에 있다. 동작마다 `--restore-window`(또는 그와 같은 `get-app-state`)로 데려와야 System Events 가 창을 본다. 그 사이 포커스가 Orca 로 돌아가면 `window "…"` 를 못 찾는다(-1728).
- **네이티브 종료 경고창은 tote 프로세스의 창이 아니다.** `CGWindowList` 로 보니 주인이 `UserNotificationCenter`(pid 37121, layer 8)라 tote 의 접근성 트리·`orca computer list-windows` 에 없다. `tell process "UserNotificationCenter" … click button "취소" of window 1` 로 누를 수 있다. tote 에 보낸 Escape(`key code 53`)는 경고창이 아니라 tote 편집기로 갔다(닫히지 않음).
- `set value` 는 편집기 값을 통째로 바꾼다. 키 입력의 「덧붙기」를 흉내 내지 않으므로 E-10 의 대상 메모는 덮어써졌다. 사람 손의 결과는 E-10a 가 본다.
- `orca computer hotkey`(⌘N)·System Events `keystroke "n" using command down` 은 합성 입력이라 어디로 갔는지 검증되지 않는다. F-5 에서 System Events ⌘N 직후 새 창 `Gamma — 2` 가 하나 더 열렸고 메모는 생기지 않았다(원인 미확인, 쫓지 않음). 그 창을 닫고 `orca computer hotkey` ⌘N 으로 메모를 만들었다.
- **사람의 입력이 섞였다.** 01:24 경 가나다 메모 끝에 `까`, 01:29–01:31 Gamma 메모 제목에 `처`, 01:31 경 D-9 의 편집기 끝에 `ㅎ` 가 붙었다(내가 넣지 않음, 한글 조합 중 글자). 코디네이터에 heartbeat 로 알렸고 쫓지 않았다. `처` 는 디스크에 저장되지 않았고, 판정에 쓴 파일 내용에는 섞이지 않았다.
