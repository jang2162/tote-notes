### 2. 버전 1 → 2

버전 1 세션(메모 `m1`·`m2`, 외부 파일 `x.sh`, `activeTab: 1`)을 두고 켰다 끄니 `version: 2`, `windows` 하나, `panes` 하나(`width: 1`), 탭 순서 `m1, m2, x.sh` 그대로, `activeTab: 1` 그대로였다. 한 칸의 탭 순서·활성은 보존됐다(탭마다 `scrollAnchor`·`selection` 이 더해졌다).

### 3. 창 둘

`openWindows` 에 같은 경로 둘, 세션에 창 배치 둘(창1: `m1` 한 칸 / 창2: `m2`·`m3` 두 칸, 폭 0.5/0.5, `focusedPane: 1`). 끈 뒤 `openWindows` 는 여전히 둘이고 세션은 `version: 2`, 창 둘, 칸 구성·폭·`focusedPane` 이 그대로였다. 실행 중 `backups/wsid-W/` 아래 스냅샷 폴더는 하나(`20261017-091318`)였고 끈 뒤에도 하나였다(워크스페이스당 한 번).

### 4. 다른 워크스페이스의 파일

A(세션에 `a.sh`)·B 를 연 뒤 8초 기다리고(P23) `{"workspace":"B","files":["…/a.sh"]}` 를 보내 5초 뒤 껐다. A 의 세션에만 `a.sh` 가 있고 B 에는 없다. **대조군:** 같은 요청에 새 파일 `c.sh` 를 더해 보내자 B 의 세션에 `c.sh` 만 생기고 `a.sh` 는 여전히 A 에만 있었다 — 요청이 앱에 닿았다는 증거라, 앞의 합격이 「요청이 안 닿아서」가 아니다.

### 5. 정리

앱을 `osascript … quit` 로 껐고 `pgrep -f tote-dev.app` 0건. `/tmp/tote-panes-smoke`·`~/Tote-dev`·`~/Library/Application Support/tote-dev` 모두 없다.

## 확인 못 한 것 · 도구의 한계

- **창 자리·크기가 세션의 `frame` 대로 복원되는지는 확인 못 했다.** 세션에 `frame`(예: x 50 y 50 800×600, x 200 y 150 800×600)을 줬는데 끈 뒤 두 창 모두 `{x:236, y:128, 1101×761}` 로 다시 쓰였다(Step 2 에서도 100,100 900×700 → 같은 값). `frame_visible` 이 모니터를 못 찾아 기본 크기·가운데로 갔거나 백그라운드 창이 화면에 올라오지 않아 값이 다르게 읽힌 것으로 보이지만 원인은 못 가렸다(비백그라운드 실행은 사람 화면을 쓰므로 하지 않았다). 사람 화면 확인 항목으로 넘긴다.
- 백그라운드 창은 화면에 올라오지 않으므로 UI(칸 분할, 드래그, 메뉴, 새로 고침)는 전혀 보지 않았다.
- 스냅샷 개수는 폴더 이름으로만 셌다(내용은 `a.md b.md c.md` 확인).
- P23: 요청 전 「A 창 준비됨」 신호가 없어 8초 대기로 갈음했다. 대기가 모자라면 규칙대로 B 가 먼저 받아 불합격처럼 보일 수 있다.

## Task 15 로 넘기는 것 (사람 화면이 필요한 것)

앞 태스크 보고서가 넘긴 것을 모았다.

1. **창 자리 복원:** 저장된 `frame` 으로 두 창이 각자 자리·크기로 돌아온다(위 「확인 못 한 것」 첫 항목). ⌥⌘N 새 창은 원래 창에서 오른쪽·아래 24px, 같은 크기, 제목에 ` — 2`; 화면 오른쪽 아래 끝이면 기본 크기 가운데.
2. **탭 메뉴(Task 11):** 탭 오른쪽 클릭 → 「탭을 새 창으로 옮기기」(활성이 아닌 탭 포함), Esc·바깥 클릭이면 아무 일 없음, 연달아 열어도 앞 선택이 새지 않음. 「윈도우 › 탭을 새 창으로 옮기기」. 떼어 낸 직후 ⌘Q → 재실행 시 두 창 모두 돌아옴. 미디어 탭은 새 창에서 다시 재생.
3. **칸 끌기(Task 10·9):** 미리보기 칸 위로 탭을 끌어 그 칸 탭 바에 놓으면 옮겨 감, 끌기 중 Esc 로 취소. 미리보기 칸 안을 누르면 그 칸이 포커스 칸이 되고 ⌘W 가 그 칸 탭을 닫음(iframe `blur`). 한글 조합 중 칸 이동은 조합이 끝난 뒤에(P20).
4. **전환(Task 12·12-fix-1):** 띠로 전환 후 창 제목·자리·크기 유지·대상 활성 탭 표시(1,000ms 목표). 글을 치고 곧바로 전환해도 떠난 워크스페이스에 저장되고 대상에 「untitled」가 안 생김. 저장 실패 중 전환 → 시트 「그래도 바꾸기」/「취소」. 전환 라운드 중 ⌘Q → 질문 없이 종료 후 재실행하면 대상 워크스페이스로 열림; 저장 실패 질문에서 「취소」하면 그 창이 대상으로 새로 고쳐지고 이어 친 글이 대상에 저장됨. 전환 대상 폴더를 그사이 지우면 `워크스페이스를 열지 못했습니다: …`.
5. **창 닫기(P22, 허브 안 됨 갈래):** 같은 워크스페이스 창 둘 중 하나를 닫고 앱을 껐다 켜면 남은 창의 배치 하나만 돌아온다. 마지막 창을 닫으면 그 배치는 남는다.
6. **종료 중 창 닫힘(Task 1):** `finish(CloseWindow)` 가 `closing` 을 세우는 것과 `BeginQuit` 의 순서.

## 실행한 명령

```bash
pnpm tauri build --debug --config src-tauri/tauri.dev.conf.json
# 각 시나리오: TOTE_DATA_DIR=/tmp/tote-panes-smoke TOTE_BACKGROUND=1 TOTE_BACKUP_INTERVAL_SECS=600 \
#   src-tauri/target/debug/bundle/macos/tote-dev.app/Contents/MacOS/tote &   (sleep 8–10)
# 요청: 같은 환경 변수로 …/Contents/MacOS/tote '--tote-request={"workspace":"B","files":["…/a.sh"]}'
osascript -e 'tell application "tote-dev" to quit'
rm -rf /tmp/tote-panes-smoke
```

시나리오 파일은 셸 함수로 직접 만들었다: `machine.json`(고정 deviceId), `<워크스페이스>/.tote/workspace.json`·`index.json`, `.tote/sessions/<deviceId>.json`, `state.json`.

지침 문서에서 고칠 것은 찾지 못했다.
