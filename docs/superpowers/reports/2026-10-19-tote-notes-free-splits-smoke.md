# tote-notes 자유 분할·탭 끌어 떼어 내기 — 화면 확인 목록

이번에는 **앱을 띄우지 않았다.** 사람이 화면(마우스·키보드) 작업을 뒤로 미뤘다. 이 문서는 화면 확인을 한 번에 돌릴 수 있게 절차와 기대값을 적어 둔 것이고, 「결과」 열은 비어 있다. 가짜 백엔드 e2e(Playwright WebKit)가 이미 덮는 것은 각 행의 마지막 칸에 시험 파일을 적었다. 그 시험은 **실제 WKWebView·실제 창 좌표를 보지 않는다.**

## 공통 준비

```bash
pnpm tauri build --debug --config src-tauri/tauri.dev.conf.json
S=$(mktemp -d); touch "$S/start-marker"
# 워크스페이스는 앱 밖에서 만든다: $S/workspaces/{Alpha,Beta}/.tote/workspace.json = {"version":1,"id":"<uuid>"}
open --env TOTE_DATA_DIR="$S" src-tauri/target/debug/bundle/macos/tote-dev.app
```

- 화면을 쓰기 전에 `ioreg -n Root -d1 -a | grep -A1 CGSSessionScreenIsLocked` 가 false 인지 본다. 잠겨 있으면 하지 않는다.
- **화면 좌표로 클릭하지 않는다.** `orca computer` 의 `--element-index` 나 System Events 요소 이름으로만 누른다. 키는 `orca computer press-key`·`type-text` 나 메뉴 항목 클릭(`click menu item "<이름>" of menu 1 of menu bar item "<메뉴>" of menu bar 1`)으로 보낸다.
- 개발용 폴더 `~/Tote-dev`·`~/Library/Application Support/tote-dev` 는 사람의 개발 앱 것일 수 있다. 지우지 않고 `find ~/Tote-dev "$HOME/Library/Application Support/tote-dev" -newer "$S/start-marker"` 가 비어 있는지로 판정한다.
- 이 기계는 모니터가 둘이다(주 모니터 `0,0`, 두 번째는 그 왼쪽 `-2560,0`). `system_profiler SPDisplaysDataType` 로 다시 읽는다.

## 미룬 화면 확인 (에이전트)

### A. 창 밖 끌기 측정 (스파이크의 남은 것)

창 밖에서도 포인터 이벤트가 오는지가 창 밖 끌기의 전제다. 아직 한 번도 재지 않았다. 측정은 `src/ui/tab-bar.ts` 의 `follow` 에 임시 로그 패치를 넣고 `TOTE_PERF=1` 로 띄워 한다(`perf_mark` IPC 가 `$TOTE_DATA_DIR/perf.jsonl` 에 쓴다). 로그 항목: `pointerdown`·`pointermove`·`pointerup`·`blur`·`pointercancel` 의 `clientX/Y`·`screenX/Y`·`buttons`, `window.screenX/Y`, `innerWidth/innerHeight`, 웹뷰 창의 논리 `outerPosition`·`innerSize`·`scaleFactor`(`frame_of` 와 같은 계산). 확인이 끝나면 패치를 되돌린다(`git diff` 가 비어야 한다).

**놓는 자리는 왼쪽(두 번째) 모니터의 메뉴 막대 y≈15** 다. 데스크톱에 빈 곳이 없어서 정한 자리이고, **다른 앱 창 위에는 놓지 않는다.** 놓기 전에 눌림이 tote-dev 에 닿았는지 먼저 확인한다(빗나간 눌림이 다른 앱을 누르지 않게).
