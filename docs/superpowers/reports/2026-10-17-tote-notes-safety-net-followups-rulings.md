# tote-notes 안전망 후속 — 코디네이터 판정

계획 `docs/superpowers/plans/2026-10-16-tote-notes-safety-net-followups.md` 를 실행하며 사람에게 묻지 않고 내린 판정이다. 판정마다 이유와 틀렸을 때의 비용을 적었다. 바로잡을 판정이 있으면 이 파일을 보고 다음 계획에 넣는다.

| 판정                                                                                                                                                             | 이유                                                                                               | 틀렸을 때의 비용                                                                                    |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 백업 정기 틱의 따라잡기(`deadline += interval` 이 과거에 남는 것)를 Task 2 에서 `max(deadline + interval, now)` 로 고친다                                        | Task 2 가 같은 루프를 다시 쓴다. 한 줄이다                                                         | Task 2 의 diff 가 한 줄 늘어난다                                                                    |
| 실패 중인 창을 닫았다 틱 전에 다시 열면, 백업 스레드가 깨움을 받을 때 그 라벨의 알림 기록을 잊는다(`FailureNotices::opened`)                                     | 깨움은 새로 연 창에만 온다. 라벨이 경로에서 정해져 닫기만으로는 구별되지 않는다                    | 창을 여는 순간 정기 라운드와 겹치면 같은 실패를 몇 초 사이에 두 번 알릴 수 있다(최종 리뷰 N2, 버림) |
| 종료 라운드가 이미 돌고 있으면 그 라운드가 이긴다. 묻는 창 닫기에 종료를 붙이는 것은 종료 라운드가 없을 때만이다                                                 | 변경 전 동작과 같다. 반대로 하면 Dock 종료 중의 ⌘Q 가 닫기 질문에 붙어 「취소」 뒤에도 앱이 꺼졌다 | Dock 종료 중의 ⌘Q 는 닫기 질문에 붙지 않는다(대화상자는 어쨌든 하나다)                              |
| 스모크 보고서(Task 7)는 따로 태스크 리뷰를 하지 않고 최종 리뷰가 함께 본다                                                                                       | 문서만 바꾼 태스크다                                                                               | 보고서의 잘못이 main 에 들어가고, 최종 리뷰만이 그물이다                                            |
| 최종 리뷰의 결과를 병합 전에 문서 커밋 하나로 옮긴다(개발 가이드의 디버그 번들 빌드 문장, 스모크 보고서의 「사람 스모크에 보탤 것」·「다음 계획으로 넘기는 것」) | 진행 기록과 리뷰 파일은 git 에 남지 않는다                                                         | 문서만 바뀐다                                                                                       |
| 화면 스모크(종료 대화상자 겹침, 충돌 보관 배너)는 사람이 나중에 한 번에 하기로 해 「확인 못 함」으로 남긴다                                                      | 사람의 결정이다                                                                                    | 두 동작이 실제 앱에서 검증되지 않은 채 main 에 있다. 절차는 스모크 보고서에 있다                    |
