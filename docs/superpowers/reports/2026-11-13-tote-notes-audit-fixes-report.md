# tote-notes 2026-11-13 점검 수정 결과 보고서

2026-11-13 전체 점검에서 나온 결함 중 사용자 결정이 필요 없는 것을 여덟 브랜치가 고쳐 `main` 에 병합했다. 일곱은 같은 기준(`main` `5d2bba4`, v0.6.0)에서 병렬로 돌았고(`chore/ci-docs`, `fix/flush-timeout`, `fix/id-validation`, `fix/rust-robustness`, `fix/modal-focus`, `fix/write-guard`, `fix/front-races`), 여덟째 `chore/audit-followups` 는 일곱이 다 합쳐진 트리(`8e1d5e5`)에서 그 일곱이 남긴 작은 것과 문서를 닫았다.

이 문서는 그 묶음의 판단 기록이다 — 무엇을 고쳤나, 사람이 화면으로 볼 것, 이월한 것과 그 이유, 알려진 불안정 시험, CI 첫 실행에서 볼 것, 지침에 반영한 것과 남은 것. 각 브랜치에는 구현 워커와 리뷰어(따로 띄운 워커)가 따로 구분력을 실증했다 — 고친 프로덕션 코드를 되돌려 새 시험이 깨지는 것을 보았다. 실증이 안 된 자리는 아래 해당 줄에 적었다.

## 무엇을 고쳤나

브랜치마다: 결함 → 고친 방식 → 지키는 시험(하나 이상).

- **`chore/ci-docs`** — 시험 CI 가 없어 `cargo test`·e2e·버전 확인이 손으로만 돌았다 → `.github/workflows/ci.yml`(push `main`·pull request, macOS 러너 한 잡, 포맷 → 린트 → 타입 → vitest → 버전 → cargo fmt·clippy·test → e2e, 실패 시 `test-results/` 산출물) → 앱 시험 없음(GitHub 에서 아직 한 번도 돌지 않았다. 아래 「CI 첫 실행에서 볼 것」). 함께: `vite.config.ts` 의 `__dirname` → `import.meta.dirname`, 개발 의존성 취약점은 ruler 판이 아니라 잠금 파일의 `zod` 판이 원인이라 잠금만 4.6.5 → 4.6.7(`pnpm audit` 깨끗), 코어 설계·휴지통 설계의 낡은 문장(범위, 고르개, 설정 구역, 메모 목록, 크기별 단계, 뷰어, 백업 100MB, 세션 「저장하지 않음」, `trash_memo` 의 쓰기 순서), README.
- **`fix/flush-timeout`** — flush 시간 제한(3초)이 「창이 답하지 않음」 을 「쓸 것 없음」 으로 쳐서, 쓰기가 끝나지 않는 창이 묻지 않고 닫히거나 꺼졌다 → 페이지가 쓰기 **전에** 「아직 어느 파일에도 없는 글이 있는 탭 수」 를 `flush_writing` 으로 알리고 다 쓰면 거둔다. `FlushCoordinator::expire` 가 남은 알림을 이유로 옮겨 기존 「저장하지 못한 메모가 있습니다」 질문으로 끝난다 → Rust `a_window_still_writing_at_the_timeout_asks`(`app/flush.rs`), `a_round_that_times_out_on_a_window_still_writing_asks_and_keeps_the_window`(`app/mod.rs`), e2e `save-failure.spec.ts` 「a flush says what is only in memory before a write that does not end」, `switcher.spec.ts` 「a switch whose write does not end is not carried out when its round times out」.
- **`fix/id-validation`** — 디스크에서 읽은 워크스페이스 ID·메모 ID 가 경로 조각이 되어(`backups/<id>/`, `viewed/<id>.json`, `.trash/<id>/`) `../` 로 워크스페이스·앱 데이터 밖을 덮거나 옮겼다 → 두 겹: 읽는 자리에서 UUID 가 아니면 새 ID, 경로를 만드는 자리에서 한 조각짜리 이름이 아니면 경로를 만들지 않는다(`workspace::id`). 손으로 넣은 휴지통 폴더는 새 ID 로 복구. 메모 목록 읽기도 감시기와 같은 inode 짝짓기로 외부 이름 바꾸기를 잇는다 → `workspace::id::tests::a_workspace_id_that_is_not_a_uuid_is_replaced_and_reaches_nothing_outside`, `…::a_memo_id_that_is_not_a_uuid_is_replaced_and_reaches_nothing_outside`, `workspace::memo::tests::a_rename_by_another_app_found_by_listing_keeps_the_memo`.
- **`fix/rust-robustness`** — 깨진 `settings.json`·`machine.json` 이 말없이 기본값으로, 감시 실패가 stderr 로만, `tote -` 실패 때 inbox 파일이 말없이 남음, `--import`·`tote -`·대용량 뷰어 검색이 파일·줄을 통째로 메모리에 올림, `Settings` 가 모르는 필드를 저장 때 버림, 죽은 `ExtensionStore::find` → 치운 파일을 첫 창에 알림(`tell_next_window`), 감시 실패를 그 창 상태 표시줄에 한 번, 실패 알림에 inbox 경로, 흘려 쓰는 복사(`copy_in`·`park`)와 긴 한 줄의 창 단위 일반 글자 검색(정규식은 아님), `#[serde(flatten)] Unknown` → `app::tests::a_broken_settings_machine_or_state_file_is_told_to_the_first_window`(이 묶음에서 이름이 바뀌었다), `a_workspace_that_cannot_be_watched_says_so_in_its_window`, `app::requests::tests::text_piped_to_a_request_no_window_takes_stays_and_is_told_where`, `workspace::ops::tests::a_file_is_copied_in_as_it_is_read_not_held_whole`, `files::text::tests::plain_text_in_one_huge_line_is_found_without_holding_the_line`, `cli::front::tests::piped_text_is_parked_as_it_comes_not_held_whole`, `appdata::tests::fields_a_newer_build_wrote_survive_a_save`.
- **`fix/modal-focus`** — 대화상자가 떠 있어도 Tab 이 밖으로 나가 뒤의 메모에 글이 들어가고, 메뉴 명령이 뒤에서 돌아 질문이 겹치고, 닫으면 포커스가 body 에 떨어졌다 → `modal()` 이 맨 위 모달 밖을 `inert` 로(모달이 건 것만 푼다), 밖으로 나간 Tab 을 되돌리고, 연 자리로 포커스를 돌려준다. `onMenu` 들머리에서 모달 중 명령을 버린다(실행 취소·복귀와 「백업 폴더 열기」 만 예외) → e2e `modal-focus.spec.ts` 「Tab in the rename dialog never reaches the editor behind it」, 「menu commands do nothing behind the unsaved-changes question, which is asked once」, `dialogs.spec.ts` 「Tab and ⇧Tab keep the keys in the dialog, and what is typed off the page behind」.
- **`fix/write-guard`** — 자동 저장·외부 파일 ⌘S 가 알림 전의 다른 앱 수정을 덮고, 빈 새 메모 닫기가 다른 앱이 쓴 글째 지우고, 이벤트를 버린 FSEvents(`MUST_SCAN_SUBDIRS`)를 무시하고, 늦은 다시 읽기 응답이 그사이 친 글을 덮었다 → 백엔드가 파일마다 「편집기가 쥔 내용」(`held`: 해시·길이·스탯)을 들고 쓰기 직전에 견준다. 다르면 `conflict` 로 거절해 충돌 배너로, 「내 버전」 은 그 순간의 디스크를 쥔 것으로 치고 한 번만 강제 쓰기(`x-overwrite`), Rescan 은 쥔 메모 전부를 다시 본다. 탭은 다시 읽기가 나가 있는 동안 저장을 기다린다(`rereadSettled`) → Rust `a_save_over_another_apps_edit_is_refused`(`workspace/ops.rs`), `dropped_events_have_every_target_under_the_folder_looked_at_again`(`watch`), `delete_leaves_a_file_another_app_wrote_into`, e2e `watch.spec.ts` 「a save that meets another app's text before the watcher reports it asks instead of writing」, vitest 「a reread answered late does not replace what was typed meanwhile, nor does its save go out」.
- **`fix/front-races`** — 가져오는 동안 친 글이 저장된 것으로 세어지고 두 번 가져오면 메모가 둘, 늦은 목록 응답이 새 메모를 지우거나 휴지통 메모를 되살림, 닫힌 탭이 하이라이터에 남음, 미리보기 아래 버전 되돌리기의 색 어긋남, 탭 전환·닫기가 한글 조합을 확정하지 않음, 대용량 뷰어 쪽 캐시 무한, 저장 응답의 다시 그리기가 누르던 클릭을 지움, `io` 오류 문구가 영어 원문뿐 → 가져오는 동안 칸을 비움, 읽기 번호와 창 자신의 변경 횟수로 목록 응답을 가림, 칸에 없는 탭은 하이라이트하지 않음, 뷰가 올라올 때 워커의 글과 다르면 다시 보냄, `Pane.settle()`, 64쪽·32MB LRU, 같은 모양의 행·탭 요소를 재사용(`placeChildren`)하고 그리는 동안 전환을 끔, `작업을 마치지 못했습니다: <원문>` → e2e `external.spec.ts` 「keys typed while a file is imported do not end up unsaved in the memo」, `memo-list.spec.ts` 「a memo made while a listing is on its way stays in the list」, `memo.spec.ts` 「a tab closed while its file is read is not kept for the highlighter」, `panes.spec.ts` 「a composition at several cursors lands at all of them before the next tab shows」, `memo-list.spec.ts` 「a row under one a save's answer makes anew still opens when it is let go」, `tab-drag-preview.spec.ts` 「a tab dropped in its own bar is in its place at once, and so are its neighbours」, vitest `errors.test.ts` 「leads an io failure in Korean and keeps the system's own words after it」.

## 이월

### 결정이나 큰 작업이 필요해 남긴 것

- **세션 쓰기가 `inner` 잠금을 쥔 채 디스크에 쓴다**(flush-timeout).
  - 무엇: `AppCore::set_layout` 이 `inner` 를 잡은 채 `write_session` 을 부른다. 워크스페이스 볼륨이 완전히 멈추면 글을 친 약 1초 뒤 이 쓰기가 잠금을 쥔 채 멈추고, 메인 스레드의 `begin_flush` 까지 멈춰 ⌘Q·⌘W 가 질문도 종료도 없이 앱을 얼린다. flush 시간 제한 수정은 이 경우에 닿지 않는다(코드 읽기, 재현하지 않음).
  - 왜 남겼나: 쓰기 순서를 지키려고 잠금 안에서 쓴다(두 창의 쓰기가 온 순서대로 파일에 닿게). 그 보장을 다른 방법으로 세워야 하는 설계 변경이다.
  - 닫으려면: 세션 파일 쓰기를 잠금 밖의 쓰기 대기열로 옮기고 순서는 대기열이 지킨다.
- **`start_quit`·`closed` 가 워크스페이스 뮤텍스에서 멈춘다**(flush-timeout).
  - 무엇: 둘 다 먼저 `save_viewed_now` 로 워크스페이스 뮤텍스를 잡는데, 멈춘 `write_memo` 명령이 그 뮤텍스를 쥔 채 쓰고 있다. 「그래도 종료」 를 골라도 꺼지지 않고, 창을 닫은 뒤 `closed` 가 그 자리에서 멈춘다.
  - 왜: 쓰기 명령 자리(`write_memo` 가 잠금을 쥐고 쓰는 것) 전체를 고쳐야 한다.
  - 닫으려면: 메모 쓰기를 잠금 밖에서 하거나, 종료 경로의 `save_viewed_now` 를 시간 제한 있는 시도로 바꾼다.
- **가려져 멈춘 창의 남는 손실 창**(flush-timeout).
  - 무엇: 페이지가 멈춰 flush 요청을 3초 안에 받지도 못한 창은 지금처럼 「쓸 것 없음」 으로 친다. 포커스를 잃을 때의 즉시 저장이 끝나지 않았거나 실패한 글이 있으면 묻지 않고 사라진다. 정상 볼륨에서는 0 이다.
  - 왜: 백엔드가 직접 아는 정보(그 창의 쓰기 명령이 아직 안 끝났다)가 필요하고, 그때는 메모 개수를 모르므로 질문 문구를 새로 정해야 한다(사용자 결정).
  - 닫으려면: 백엔드가 창별 「진행 중 쓰기 명령 수」 를 세어 시간 제한 때 함께 보고, 문구를 정한다. 사람 확인 「가려진 창에 안 쓴 글이 있는 종료」 에서 거짓 질문이 나오면 같은 방향으로 고친다.
- **정규식 검색이 긴 한 줄을 통째로 올린다**(rust-robustness).
  - 무엇: 대용량 뷰어의 일반 글자 검색은 긴 줄을 창 단위로 찾지만, 정규식은 `^`·`$`·`\b`·`.*` 가 줄 전체를 보므로 끊으면 결과가 달라져 줄 전체를 메모리에 올린다. 취소는 듣는다.
  - 왜: 결과를 바꾸는 결정이다.
  - 닫으려면: 예를 들어 일정 길이를 넘는 줄은 정규식으로 찾지 않고 그렇다고 알린다 — 그 길이와 문구를 정한다.
- **한 줄에 일치가 한 쪽(200개)보다 많으면 나머지를 잃는다**(rust-robustness).
  - 무엇: 다음 쪽이 「마지막 일치의 다음 줄」 에서 시작한다(`TextSearch::done`). 한 줄짜리 큰 파일에서는 처음 200개만 보인다. 원래 그랬다.
  - 닫으려면: 다음 쪽의 시작을 줄 번호가 아니라 (줄, 열)로 잇는다. 프런트의 쪽 넘기기와 함께 바꾼다.
- **notify 의 `SinceNow` 공백**(write-guard).
  - 무엇: watch·unwatch 때 FSEvents 스트림이 `kFSEventStreamEventIdSinceNow` 로 다시 시작해 그 사이의 변경을 모른다. 저장 검사 덕에 그 변경을 덮지는 않지만, 글을 치지 않고 있는 열린 메모는 다음 이벤트·읽기 전까지 옛 글을 보인다.
  - 닫으려면: 마지막 이벤트 ID 를 들고 다시 시작하거나, 다시 걸 때 쥔 파일을 한 번 다시 본다.
- **거친 mtime 파일 시스템의 스탯 지름길**(write-guard).
  - 무엇: 수정 시각 단위가 거친 파일 시스템(HFS+ 1초, exFAT 2초)에서 같은 단위 안에 길이가 같게 제자리에 쓴 것은 감시 이벤트가 올 때까지 저장 검사를 통과한다. APFS 는 ns 단위라 해당 없다. 시험이 이 한계와 이벤트 뒤의 복구를 고정한다.
  - 닫으려면: 그런 볼륨에서는 지름길을 끄고 저장마다 읽는다(볼륨 종류 판정이 필요하다).
- **가져오는 수십 초 사이의 같은 이름 덮기**(rust-robustness 리뷰).
  - 무엇: 수 GB 를 흘려 복사하는 동안 다른 앱이 같은 이름의 파일을 만들면 마지막 rename 이 말없이 덮는다. 경쟁은 원래 있었고 창이 길어졌다(추정, 재현하지 않음).
  - 닫으려면: macOS `renamex_np(RENAME_EXCL)` 이나 `link`+`unlink` 로 「없을 때만」 이름을 붙이고, 실패하면 이름을 다시 고른다.
- **`tote -` 를 중간에 끊으면 inbox 에 반쪽 파일이 남는다**(rust-robustness 리뷰).
  - 무엇: Ctrl-C·SIGKILL 이면 `inbox/<uuid>.txt` 가 반쯤 쓰인 채 남는다. 오류로 끝나는 경로는 지운다. 메모로 들어오지는 않는다 — 쓰레기 파일이고, 실패 알림이 가리킨 파일도 사람이 치워야 한다.
  - 닫으려면: 시작할 때 오래된 inbox 파일을 치우는 정책(언제 지워도 되는가)을 정한다.
- **감시 실패 워크스페이스의 둘째 창은 알리지 않는다**(rust-robustness 리뷰).
  - 무엇: 감시는 그 워크스페이스의 첫 창이 열 때만 걸므로, 같은 워크스페이스로 연 새 창은 외부 변경을 못 받는데 아무것도 안 뜬다. 시험이 이것을 의도로 단언한다.
  - 닫으려면: 감시 실패를 `OpenWorkspace` 에 들고 있다가 그 워크스페이스의 창이 등록될 때마다 알린다.
- **다른 앱의 rename 을 목록이 먼저 알면 다른 창에 `Renamed` 가 안 간다**(id-validation).
  - 무엇: `list_memos` 는 변경을 돌려주지 않으므로 목록을 읽은 창만 새 이름을 안다. 다른 창은 다음 목록 읽기까지 옛 이름을 보인다. 저장은 ID 로 가므로 글을 잃지는 않는다.
  - 닫으려면: `list_memos` 가 따른 이름 바꾸기를 돌려주고 명령이 다른 창에 `tote://outside` 로 낸다.
- **저장이 이어지는 동안 목록 다시 읽기가 되풀이될 수 있다**(front-races F3).
  - 무엇: 목록 응답을 기다리는 사이 창이 목록을 바꾸면(저장 응답의 `upsert`) 그 응답을 버리고 다시 읽는다. 1만 메모에서 쉬엄쉬엄 치면 다른 앱의 메모가 타이핑이 멎을 때까지 안 보이고, 그동안 매번 다시 읽는다. 틀린 목록은 보이지 않는다. 빈도는 재지 않았다.
  - 닫으려면: 버린 응답에 창이 그사이 바꾼 것만 덧입혀 쓴다(새로 만든 id 는 남기고 지운 id 는 뺀다).
- **누르던 행의 순번이 밀리는 다시 그리기는 클릭을 잃는다**(front-races, 의도).
  - 무엇: 저장으로 목록 순서가 바뀌어 누른 행이 포인터 밑에서 벗어나면 아무것도 열리지 않는다. 틀린 메모를 여는 것보다 아무것도 열지 않는 쪽을 골랐다. 기본 정렬에서는 그 메모를 연 뒤 첫 저장 한 번에만 생긴다. 시험이 고정한다.
  - 닫으려면: 「누른 메모를 연다」 를 `mousedown`·`mouseup` 으로 직접 따라가야 하는데, 그것은 틀린 메모를 열 수 있는 쪽이라 사용자 결정이다.
- **Rust 의 `io` 코드가 파일과 무관한 실패까지 덮는다**(front-races).
  - 무엇: `io_code` 의 `_ => "io"` 라 떼어 내기 거절(「the app is quitting」, 「does not hold the tab」), 명령줄 도구 설치 실패도 `io` 로 온다. 그래서 문구를 「작업을 마치지 못했습니다」 로 넓혔다. 이 문구는 사용자가 바꿀 수 있는 자리다(`src/app/errors.ts` 의 `ERROR_LEAD` 한 줄과 e2e 기대값 다섯 줄, vitest 하나).
  - 닫으려면: Rust 가 그런 실패에 다른 코드를 주고 프런트가 문장을 따로 준다.
- **백업 보존이 「지금」 기준이라 오랜만에 켜면 옛 스냅샷이 한 번에 지워진다**(점검).
  - 왜: 보존 기준을 바꾸는 스펙 변경이다.
  - 닫으려면: 보존 기간을 스냅샷 간격으로 셀지(마지막 스냅샷부터) 스펙에서 정한다.
- **Finder 로 복제한 워크스페이스가 백업·본 시각을 나눠 쓴다**(점검, id-validation 이 건드리지 않음).
  - 무엇: 복제한 폴더는 `workspace.json` 의 ID 가 같아 `backups/<id>/`·`viewed/<id>.json` 이 같다.
  - 닫으려면: 같은 ID 를 가진 둘째 폴더를 알아보는 규칙(폴더 inode 를 함께 적는 등)을 정한다.
- **원자적 쓰기가 외부 파일의 확장 속성·태그·하드링크를 잃는다**(점검).
  - 무엇: 임시 파일에 쓰고 rename 하므로 원래 파일의 xattr(Finder 태그 등)과 하드링크가 끊긴다.
  - 닫으려면: 외부 파일에 한해 xattr 복사, 또는 하드링크가 있으면 제자리 쓰기를 고른다(안전성과 맞바꾸는 결정).
- **`add_copy` 와 `add_memo` 가 색인에 넣는 열두 줄이 같다**(rust-robustness). write-guard 와 겹칠까 봐 합치지 않았다. 두 브랜치가 병합됐으니 한 함수로 합칠 수 있다.

### 그 밖에 남긴 것

- flush-timeout: 질문이 떠 있는 동안 쓰기가 끝나도 질문은 남는다(손실 없음). 알린 개수는 쓰기를 시작할 때의 값이라 적게 보일 수 있다. 거둔 뒤 넘겨받는 탭을 기다리는 동안(3초를 넘기는 드문 경우) 친 글은 묻지 않고 사라진다(전부터). 가짜 백엔드의 `restartForUpdate` 는 라운드의 이유를 보지 않고, 아무 말 없는 창의 시간 제한을 본뜨지 않는다. `docs.ts` `MemoDoc.flush` 주석의 「Also when the text was undone back to the last save」 갈래가 실제로 도는지 보지 않았다.
- rust-robustness: 큰 파일·텍스트가 아닌 파일을 가져오면 감시기가 그 새 메모를 `Modified` 로 한 번 낸다(그 탭은 다시 읽지 않아 보이는 일이 없다 — 메모리 쪽에서는 낫다). 창이 하나도 없을 때 실패한 요청의 이유는 stderr 로만 간다. 감시기 기동 실패(`lib.rs`)와 요청 `handle` 자체는 시험이 없다.
- write-guard: 기준이 없는 외부 파일(「텍스트로 열기」 로 연 비텍스트 종류)은 ⌘S 검사를 하지 않는다. 「다시 저장」 은 강제 쓰기라 「삭제됨」 배너 뒤 다른 앱이 같은 이름을 다시 만들었으면 덮는다(전부터). 다른 앱의 rename 직후 이벤트 전의 저장은 옛 이름으로 파일을 다시 만든다(이벤트가 오면 메모가 둘). tote 가 rename 한 직후 `Modified` 가 한 번 더 날 수 있다(배너가 이미 떠 있는 메모만). 자기 쓰기의 스탯을 rename 전에 얻는 수정은 어떤 시험도 가르지 못한다(코드 읽기로만 보증). e2e 「내 버전 picked for a restored draft does not cover a change made after it」 는 `rebase` 를 빼도 통과한다(vitest 가 가른다).
- front-races: 휴지통 목록·검색 패널·워크스페이스 순서 목록은 여전히 통째로 다시 그린다. `refreshTrash` 는 읽기 번호만 있어 「창 자신의 변경에 추월당한 응답」 이 휴지통에도 있을 수 있다(재현해 보지 않음). 가져오기 뒤 `ext.discard()` 가 실패하면 탭이 외부 파일로 남아 다시 가져오면 메모가 둘. `placeChildren` 은 옮김이 가장 적은 방식이 아니다(지금 두 자리에서는 차이 없음). `Pane.activate` 가 조합 중일 때만 기다리게 하는 대안은 하지 않았다.
- modal-focus: 대화상자 중 ⌘Z 가 뒤의 입력칸(필터·검색칸)에 친 것을 되돌릴 수 있다(WebKit 의 되돌리기 기록이 창 하나에 하나, 메모 본문은 안전). `settingsOpen` 가드는 이제 `onMenu` 가드와 겹친다. 업데이트 창이 받는 동안 버튼이 다 꺼져 포커스가 대화상자 자신에 있다. 이전 버전 창은 첫 버전을 읽은 뒤에도 포커스가 대화상자에 남는다.
- id-validation: `BackupDir::new`·`ViewedTimes::file` 의 `#[cfg(test)]` 줄임꼴(병합 충돌을 피하려고 둔 것)은 이제 걷을 수 있다. `backup/versions.rs` 의 `is_one_segment` 와 `workspace::id::is_safe_segment` 는 비슷한 검사 둘이다. `backup_tick` 의 오류 갈래는 평소 닿지 않는다. 새 ID 를 받은 워크스페이스는 고르개의 순서·숨김을 잃는다(의도).
- ci-docs: `src-tauri/src/app/commands.rs` `workspace_items` 문서 주석의 「Recent order is what 「워크스페이스 열기…」 shows」 가 낡았다. `pnpm install` 이 `Ignored build scripts: lefthook` 경고를 낸다(훅은 `prepare` 로 깔려 동작에 문제없다). `pnpm build` 는 CI 에 없다(번들이 깨지는 것은 릴리스 워크플로에서야 걸린다).
- audit-followups: 확인 창을 키보드로 연 컨트롤이 **닫힌 뒤에** 문서에서 빠지면(닫는 순간에는 있다) 포커스는 그 컨트롤로 갔다가 body 로 떨어진다. 휴지통 행의 영구 삭제는 문맥 메뉴(마우스)로만 열리므로 지금 이 길은 없다.

## CI 첫 실행에서 볼 것

`.github/workflows/ci.yml` 은 로컬에서 YAML 파싱·actionlint·각 단계 명령만 확인했다. 워크플로 주석의 「로컬 통과가 근거가 아니다」 류 문장은 첫 실행 결과가 나오면 사실에 맞게 다듬는다(통과하면 「호스팅 러너에서 돈다」 로).

- **하네스 없는 시험 셋**(`menu_key_equivalents`·`menu_keypad`·`traffic_lights_resize` — 실제 AppKit 메뉴 막대와 창을 만든다)이 떨어지면 「cargo test」 단계 로그에서 어느 바이너리인지 본다(`Running tests/<이름>.rs` 다음 줄, 끝의 `error: test failed, to rerun pass '--test <이름>'`).
  - 패닉이 `a test without the harness runs on the main thread` 면 러너가 아니라 `harness = false` 설정 쪽이다.
  - `NSApplication::sharedApplication`·`NSWindow` 생성·`init_for_nsapp` 근처에서 패닉하거나 멈추면(60분 제한까지 간다) 러너 세션에 창 서버가 없는 것이다. 코드를 고치지 말고, 셋을 CI 에서 뺄지(`cargo test --lib --bins` 로 좁히고 셋은 로컬·릴리스 전 확인으로) 사람이 정한다.
  - 단언 실패(메뉴 키·신호등 좌표 값이 다름)면 러너의 macOS 판이 로컬(27)과 달라서일 수 있다. 앞의 둘은 「muda/AppKit 이 이렇게 동작한다」 를 못 박는 시험이다. 로그의 `runs-on` 이미지 판과 함께 본다.
- **시간.** 로컬은 7 workers 로 e2e 2~4분이었다. Playwright 기본 worker 는 논리 코어의 절반이라 코어가 적은 호스팅 러너에서는 1~2 worker 로 돈다. 리뷰가 잰 시험별 시간 합은 28분(부하 52~96 에서라 부풀었다. 2.2분 × 7 이면 약 15분)이고, 캐시 없는 첫 실행은 clippy·`cargo test` 빌드가 더해진다. 60분 제한에 걸리면 제한을 올리기 전에 단계별 시간과 실제 worker 수를 본다. `playwright.config.ts` 에는 CI 용 설정(재시도·worker 수)이 없다.
- **부하에 민감한 시험.** 위 「알려진 불안정 시험」 이 느린 러너에서 떨어질 수 있다. `test-results/` 는 산출물 `e2e-test-results` 로 올라온다. `docs/guides/development.md` 「부하에서만 실패하는 테스트는 …」 절의 순서로 본다.
- **`actions/upload-artifact@v7`.** 릴리스 워크플로에서 이 액션은 수동 실행 갈래에만 있고 최근 실행은 모두 태그 실행이었다 — 이 판 표기가 실제로 돈 적이 있는지 모른다. e2e 가 처음 떨어질 때 산출물이 올라오는지 본다.
- **단계는 차례로 돈다.** 포맷이 떨어지면 시험은 돌지 않는다(잡 하나로 둔 대가. 나누면 러너를 세 번 띄운다).
- **`dist/` 없이 cargo 가 돈다**는 판단(`custom-protocol` 없이 `devUrl` 이 있으면 `frontendDist` 를 싣지 않는다, `tauri-codegen` `context.rs`)은 로컬 새 워크트리로만 확인했다. 러너에서 `frontendDist` 를 찾는 오류가 나면 이 판단부터 다시 본다.
- 동시성: 같은 ref 의 새 커밋이 앞선 실행을 취소한다. 취소된 실행은 실패가 아니다.

## 지침에 반영한 것과 남은 것

### 반영한 것

- `docs/guides/development.md`
  - 「CI 는 로컬 훅이 돌지 않는 시험까지 돈다」 절(ci-docs).
  - 「디버그 앱은 언제나 …」 절의 대화상자를 닫은 뒤 포커스가 가는 자리(modal-focus 가 쓰고 audit-followups 가 연 자리가 없는 경우를 고쳐 씀).
  - 「부하에서만 실패하는 …」 절의 「다른 앱의 변경을 흉내 내는 시험」 둘째 문장 — 저장이 거절돼 배너를 띄운다(write-guard).
  - 같은 절: `FakeData.flushWriting` 과 가짜가 여는 전환 라운드의 3초, 「다시 그려도 클릭이 살아남는다」 시험의 앞 요소 경우와 `replaceChildren`, 가짜 백엔드 호출을 `(...args)` 로 감싸기, `reducedMotion` 양쪽(audit-followups, 출처 flush-timeout·front-races).
  - 새 절 「에이전트가 돌린 oxlint 는 몇 개를 봤는지 찍지 않는다」(출처 ci-docs), 「명령의 성패는 파이프에 넘기지 않고 본다」(출처 front-races).
  - 「E2E 전에 WebKit 을 설치한다」 절의 `page.goto` 30초 시간 초과 묶음(출처 front-races), 「파일을 되돌리면 post-checkout 훅이 돈다」 절의 「되돌리기 실증은 커밋한 뒤에」(출처 front-races), 손으로 만드는 `workspace.json` 의 UUID(출처 id-validation).
- 코어 설계(`docs/superpowers/specs/2026-10-07-tote-note-core-design.md`)
  - 「오류 처리」: 끝나지 않는 저장, 사라진 워크스페이스 폴더(flush-timeout). `conflict` 는 저장 실패가 아니다(write-guard). 저장 실패 문구의 원문 붙이기와 `io` 의 넓은 문장, 앱 데이터 파일이 깨졌을 때의 가리킴(audit-followups).
  - 「세션」: 빈 새 메모의 파일이 비어 있지 않으면 지우지 않는다(write-guard).
  - 「외부 변경」: 「편집기가 쥔 내용」 과 저장 검사 전부(write-guard), 워크스페이스를 감시하지 못할 때(audit-followups, 출처 rust-robustness).
  - 「워크스페이스와 데이터 모델」: 깨진 `machine.json`·`settings.json` 의 알림과 모르는 필드 보존(rust-robustness), `state.json` 과 기기 ID 검사, `extensions` 의 모르는 필드(audit-followups).
  - 「워크스페이스」·「메모 ID 와 색인」: 두 겹 ID 검사와 목록 읽기의 inode 짝짓기(id-validation), 바뀐 키가 잃는 것(탭 위치·버전 이력·본 시각), 목록이 먼저 알 때 다른 창이 보는 것, `index.json` 의 `pinned`(audit-followups, 출처 id-validation 리뷰).
  - 「워크스페이스 고르개」: 쓰기가 시간 제한까지 끝나지 않을 때의 질문(audit-followups, 출처 flush-timeout), 메뉴에 다른 워크스페이스를 새 창으로 여는 명령이 없다는 문장을 `tote -w` 와 맞게(ci-docs).
- 설정·단축키 설계 「3. 설정 화면」: 모달이 열린 동안의 포커스·메뉴 규칙(modal-focus).
- 휴지통 설계: `trash_memo` 의 쓰기 순서(ci-docs), `last_written` → `held`(write-guard).
