## 읽는 법

- 항목마다 「절차」·「기대」·「결과」 세 열이다. 「결과」는 비워 두었다. **합격이면 `합격`, 아니면 `불합격` 과 본 것**을 적는다. 불합격은 어디서(몇 번 단계) 무엇이 보였는지(문구·값)까지 적는다. 그래야 다음 계획이 그대로 받는다.
- 확인 못 한 것(앱이 안 뜸, 해당 화면 없음)은 `못 함` 과 이유를 적는다. 빈 칸으로 두지 않는다.
- 단축키 표기: ⌘ Command, ⌥ Option, ⌃ Control, ⇧ Shift.

## 공통 준비

모든 항목은 **디버그 번들과 임시 데이터 폴더**로 한다. 실제 메모 폴더 `~/Tote` 는 쓰지 않는다.

```bash
# 1) 디버그 번들 (--config 를 빼면 tote.app 이 나온다)
pnpm tauri build --debug --config src-tauri/tauri.dev.conf.json
# 결과: src-tauri/target/debug/bundle/macos/tote-dev.app

# 2) 시험 폴더. 항목을 새로 시작할 때마다 새로 만들어도 되고, 이어서 써도 된다
S=$(mktemp -d); echo "$S"

# 3) 띄우기 (TOTE_BACKGROUND 는 주지 않는다 — 창이 화면에 올라와야 한다)
open --env TOTE_DATA_DIR="$S" --env TOTE_BACKUP_INTERVAL_SECS=600 src-tauri/target/debug/bundle/macos/tote-dev.app
```

- 워크스페이스 폴더는 `$S/workspaces/<이름>` 이다. 처음 켜면 기본 워크스페이스 하나가 있다. 띠의 `+` 로 더 만든다.
- 앱 안에서 쓸 외부 파일은 `$S` 밖의 새 폴더(예: `mktemp -d` 한 번 더)에 만든다.
- `chmod` 는 **시험 폴더 안에서만** 쓴다: `chmod a-w "$S/workspaces/<이름>"` 로 저장 실패를 만들고, `chmod u+w` 로 되돌린다.
- 편집기에 글을 넣을 때 `orca computer` 의 `type-text`·`paste-text` 는 글이 두 번 들어가거나 클립보드를 한 번 더 붙인다. 자동으로 넣는다면 `set-value` 를 쓰고 들어간 글을 확인한다. 손으로 치는 항목은 해당 없다.
- 끝나면 앱을 끄고(`osascript -e 'tell application "tote-dev" to quit'`) 아래를 확인한다. 새로 생겼으면 `불합격` 으로 적는다.

```bash
ls -d ~/Tote-dev "$HOME/Library/Application Support/tote-dev" 2>&1   # 둘 다 "No such file" 이어야 한다
pgrep -f tote-dev.app                                                  # 아무것도 없어야 한다
rm -rf "$S"
```

## B. 한글 조합

macOS 한글 입력기로 **손으로** 친다. 칸 둘(`가`·`나`)에서 시작한다. 실제 입력기가 `blur` 로 조합을 확정하는지는 자동 시험이 못 본다.

| #   | 절차                                                                                              | 기대                                                                                                                                                                    | 결과 |
| --- | ------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| B-1 | 왼쪽 칸 메모에서 「한글」을 치다가 **마지막 글자 조합 도중**(예: `ㅎㅏㄴㄱㅡ` 까지 친 상태)에 ⌥⌘→ | 조합이 확정된 뒤 포커스가 오른쪽 칸으로 간다. 왼쪽 메모에는 `한그` 또는 `한글`(칸을 옮기기 직전 상태)이 **자모가 깨지지 않고** 들어 있다.                               |      |
| B-2 | **P20.** `ㄱ` 만 친 상태(조합 중)에서 ⌥⌘→ 한 뒤 새 칸에서 `ㅏ` 를 친다                            | 새 칸에 `ㅏ` 가 **새로 들어간다**(앞 칸의 `ㄱ` 과 합쳐진 `가` 가 아니다). 새 칸의 캐럿 앞 글자는 바뀌지 않는다. 앞 칸에는 `ㄱ` 이 남아 있다. 불합격이면 다음 계획 후보. |      |
| B-3 | 왼쪽 칸에서 「한글」 조합 도중 **오른쪽 칸의 탭 바(또는 띠가 아닌 다른 칸 영역)를 클릭**한다      | 조합이 확정되고 왼쪽 메모에 글이 그대로 들어간다. 오른쪽 칸이 포커스 칸이 된다.                                                                                         |      |
| B-4 | 칸 하나(메모 하나 이상)에서 「한글」 조합 도중 탭 오른쪽 클릭 → `탭을 새 창으로 옮기기`           | 조합이 확정되고, **떼어 낸 새 창의 그 메모**에 글이 들어 있다(원래 메모 그대로. 옮겨지지 않은 자모가 엉뚱한 메모에 들어가지 않는다). 원래 창에는 그 탭이 없다.          |      |
| B-5 | 조합 도중 띠의 다른 워크스페이스 클릭(전환)                                                       | 조합이 확정되고 떠난 워크스페이스의 그 메모에 글이 저장된다. 대상 워크스페이스에 새 `untitled` 메모가 생기지 않는다.                                                    |      |

## D. 탭 떼어 내기

끌어서 떼어 내기는 하지 않는다 — 스파이크 (a2) 는 `확인 못 함` 이었고 코어 스펙에 「끌기로는 떼어 내지 않는다」로 적었다. 아래 O-1 의 측정 결과에 따라 끌기를 다음 계획에 넣을지 정한다.

| D-7  | **외부 파일**(`x.sh`)에 글을 고쳐 저장하지 않은 채 D-2 로 떼어 낸다                                                                            | 새 창에 **저장 전 수정분 포함** 글이 열린다(저장 안 된 표시도 그대로).                                                                                                |      |
| D-8  | **저장 실패.** 워크스페이스 폴더를 `chmod a-w` 한 뒤 메모에 글을 쳐 저장이 실패하게 하고(상태 표시줄 `저장 실패`) D-2 로 떼어 낸다             | **옮기지 않는다.** 탭이 원래 창에 남고 `저장 실패` 가 그대로 남는다(상태 표시줄에 알림). 확인 뒤 `chmod u+w`.                                                         |      |
| D-9  | 충돌 배너가 떠 있는 탭(바깥에서 파일을 바꿔 띄운다)을 떼어 낸다                                                                                | 옮기지 않고 상태 표시줄에 알린다.                                                                                                                                     |      |
| D-10 | **미디어 탭**(이미지·동영상·오디오)을 떼어 낸다                                                                                                | 새 창에서 **다시 재생·표시**된다.                                                                                                                                     |      |
| D-11 | 떼어 낸 **직후, 새 창이 뜨는 동안** ⌘Q → 다시 켠다                                                                                             | 두 창 모두 돌아온다. 한 탭이 두 창에 열려 있지 않다.                                                                                                                  |      |
| D-12 | 새 창을 열고 닫는 동안 종료가 겹치는 경우(Task 1): 창 둘에서 한 창을 ⇧⌘W 로 닫는 **도중에** ⌘Q                                                 | 멈추지 않고 끝난다. 다시 켜면 닫으려던 창은 열리지 않고 남은 창만 돌아온다.                                                                                           |      |

## E. 워크스페이스 띠

워크스페이스를 셋 이상 만든다: 이름을 `가나다`, `Alpha`, `Beta` 처럼 한글·영문을 섞어 둔다.

| #     | 절차                                                                                                                                           | 기대                                                                                                                                                                                                                                      | 결과 |
| ----- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| E-1   | 띠(맨 왼쪽 48px)를 본다                                                                                                                        | 워크스페이스 전부가 **이름 순**으로 있다. 항목은 이름의 **앞 두 글자**가 둥근 칸에 보인다. 만들거나 지워도 나머지 순서는 바뀌지 않는다.                                                                                                   |      |
| E-2   | 항목에 마우스를 올린다                                                                                                                         | **이름 전체**가 보인다.                                                                                                                                                                                                                   |      |
| E-3   | 지금 창의 워크스페이스                                                                                                                         | 띠에서 **강조**돼 있다.                                                                                                                                                                                                                   |      |
| E-4   | 다른 워크스페이스의 항목을 누른다(그 워크스페이스는 어느 창에도 안 열려 있다)                                                                  | **지금 창이** 그 워크스페이스로 바뀐다. 창 제목·띠 강조·탭·사이드바가 모두 대상 것이고 **창의 자리·크기는 그대로**다. 대상의 활성 탭이 보인다.                                                                                            |      |
| E-4a  | **새로 고침 뒤 이벤트 한 번.** 띠로 **두 번 왕복 전환한 뒤** ⌘N 한 번, ⌘W 한 번. 이어서 다른 창에서 메모를 만든다                              | 메모가 **하나만** 생기고 탭이 **하나만** 닫힌다(새로 고침 뒤 메뉴 이벤트가 두 번 오지 않는다). 다른 창에서 만든 메모는 이 창 목록에 **한 번만** 나타난다.                                                                                 |      |

| E-6   | 같은 워크스페이스를 연 창이 둘 이상일 때 한쪽 창의 띠                                                                                          | 그 워크스페이스에 **작은 점**(다른 창에도 열려 있다는 표시)이 찍혀 있다. 그 창을 닫으면 점이 사라진다.                                                                                                                                    |      |

| E-8   | 띠 맨 아래 `+` 로 새 워크스페이스를 만든다                                                                                                     | 이름을 받아 만든 뒤 **지금 창이** 그 워크스페이스로 바뀐다.                                                                                                                                                                               |      |

| E-9   | 저장 실패가 남은 채 띠의 다른 워크스페이스를 누른다(폴더 `chmod a-w` + 글 입력)                                                                | 시트 `저장하지 못한 메모가 있습니다` 와 버튼 `그래도 바꾸기` / `취소`. `취소` 는 그대로 남고, `그래도 바꾸기` 는 바뀐다(저장 못 한 글은 버려진다는 점을 문구로 알 수 있는가).                                                             |      |

| E-10a | **⌃숫자로 전환하며 단어를 마저 친다.** 메모에 글을 치다가 ⌃2 를 누르고 손을 떼지 않고 몇 글자 더 친다(편집기 포커스가 빠지지 않는다)           | 전환이 끝난 뒤 떠난 워크스페이스로 돌아가 그 메모를 열면 **⌃2 뒤에 친 글까지** 남아 있다. 새로 고치기 직전 수 ms 안에 친 글자는 빠질 수 있다 — 빠진 글자가 있으면 몇 글자인지 적는다.                                                     |      |
| E-11  | 전환 대상 폴더를 **그사이 Finder 에서 지운다**(전환 시작 직후가 어려우면 지운 뒤 누른다)                                                       | 상태 표시줄에 `워크스페이스를 열지 못했습니다: …` (시작 전에 지웠으면 `not-found` 류 오류 문구). 탭은 그대로다.                                                                                                                           |      |
| E-12  | 전환 후 **창을 닫았다 다시 켜면** 그 창이 어느 워크스페이스로 열리나                                                                           | 전환한 **대상** 워크스페이스로 열린다.                                                                                                                                                                                                    |      |

## F. 종료

창 셋: 같은 워크스페이스 A 두 창 + 다른 워크스페이스 B 한 창. 각 창에 탭을 몇 개 두고 칸도 하나는 둘로 나눈다.

| #   | 절차                                                                                                                                                             | 기대                                                                                                                                      | 결과 |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| F-1 | ⌘Q                                                                                                                                                               | 멈추지 않고 끝난다. 다시 켜면 **창 셋 모두 제자리**(워크스페이스·자리·크기·칸·탭).                                                        |      |
| F-2 | 다시 켠 뒤 Dock 아이콘 우클릭 → 종료                                                                                                                             | F-1 과 같다.                                                                                                                              |      |
| F-3 | 다시 켠 뒤 시스템 메뉴 › 로그아웃(또는 `osascript -e 'tell app "System Events" to log out'`). 로그아웃 확인 창이 뜨면 취소해도 되고, 실제로 해도 된다(저장 확인) | 앱이 로그아웃을 막지 않는다. 실제로 로그아웃한 경우 다시 로그인해 켜면 창 셋이 제자리.                                                    |      |

| F-6 | 사라진 워크스페이스: 창 둘이 열린 채 앱을 끄고, 한 창의 워크스페이스 폴더를 지우고 켠다                                                                          | 그 창은 열리지 않고 나머지가 돌아온다. 사라진 워크스페이스를 알리는 문구가 있다면 문구를 적는다. 앱이 멈추거나 빈 창이 남지 않는다.       |      |

## O. 측정

load 가 높으면 값이 틀어진다. 모든 측정 앞에 `uptime` 으로 load 가 **3 아래**인지 본다(`perf:measure` 가 기다린다). 측정 중에는 다른 무거운 작업을 하지 않는다. 측정 번들은 사람 화면에 창을 띄우므로 측정 동안 건드리지 않는다.

### O-1. 창 밖 끌기 (스파이크 a1·a2, 코디네이터 판정용)

끌어서 떼어 내기를 다음 계획에 넣을지 정하는 근거다. 절차와 읽는 법은 `spikes/lab/README.md` 「사람이 하는 측정」의 `drag` 항목, 판정 기준은 스파이크 보고서 「(a1)·(a2) — 사람이 나중에 재는 절차」.

```bash
cd spikes/lab && pnpm install && pnpm tauri build --debug --no-bundle
rm -f results/drag.json
TOTE_LAB_MANUAL=drag ./src-tauri/target/debug/lab
```

`drag` 모드는 **빌드·타입 검사만 했고 한 번도 실행되지 않았다.** 첫 실행에서 페이지 오류가 날 수 있으니 `results/drag.json` 의 `screenX/Y`·`clientX/Y` 원본을 같이 본다. 창을 다른 창으로 가리지 않은 채 잰다.

세 가지를 **각각 세 번**: ① 탭을 다른 탭 바에 놓기 ② 탭을 창 밖(바탕 화면)에 놓기 ③ 끌다가 창 안에서 Esc. 포인터 변형 바도 같은 세 가지.

| #    | 절차                              | 기대                                                                                             | 결과 |
| ---- | --------------------------------- | ------------------------------------------------------------------------------------------------ | ---- |
| O-1a | ① 탭 바 사이 놓기 ×3 (HTML5 끌기) | **(a1) 됨:** `dragstart`·`dragover`·`drop`·`dragend` 가 모두 오고 `drop` 의 `target` 이 다른 바. |      |
| O-1b | ② 창 밖 놓기 ×3                   | **(a2) 구별함:** 마지막 `dragend` 가 `dropEffect === "none"` 이고 `insideWindow === false`.      |      |
| O-1c | ③ 창 안 Esc ×3                    | `drop` 없이 `dragend`, `insideWindow === true` — ② 와 **갈린다**.                                |      |
| O-1d | 포인터 변형 ①②③ 각각 ×3           | 창 밖 `pointerup` 이 `setPointerCapture` 뒤에 오는가(`insideWindow === false`).                  |      |

판정: O-1b·O-1c 가 모두 갈리면 (a2) **구별함** → 끌어서 떼어 내기를 다음 계획에 넣는다. 한쪽이라도 같으면 **끌기로는 떼어 내지 않는다**를 유지한다(코어 스펙 그대로). `results/drag.json` 에서 각 세 번의 값을 옮겨 적는다.
