# tote-notes 칸·창·전환 — 사람 확인 목록

HEAD `e18fe3f` 위에서 쓴 목록이다. 에이전트가 화면 없이 할 수 있는 것은 이미 했다(`2026-10-17-tote-notes-panes-and-windows-smoke.md`). 여기에는 **화면이나 사람 손이 있어야 하는 것**만 모았다. 한 번에 위에서 아래로 한다.

## 읽는 법

- 항목마다 「절차」·「기대」·「결과」 세 열이다. 「결과」는 비워 두었다. **합격이면 `합격`, 아니면 `불합격` 과 본 것**을 적는다. 불합격은 어디서(몇 번 단계) 무엇이 보였는지(문구·값)까지 적는다. 그래야 다음 계획이 그대로 받는다.
- 확인 못 한 것(앱이 안 뜸, 해당 화면 없음)은 `못 함` 과 이유를 적는다. 빈 칸으로 두지 않는다.
- 단축키 표기: ⌘ Command, ⌥ Option, ⌃ Control, ⇧ Shift.

## 공통 준비

모든 항목은 **디버그 번들과 임시 데이터 폴더**로 한다. 실제 메모 폴더 `~/Tote` 는 쓰지 않는다.

```bash
# 1) 디버그 번들 (--config 를 빼면 tote.app 이 나온다)
pnpm tauri build --debug --config src-tauri/tauri.dev.conf.json
# 결과: src-tauri/target/debug/bundle/macos/tote-dev.app

# 2) 시험 폴더. 항목을 새로 시작할 때마다 새로 만들어도 되고, 이어서 써도 된다
S=$(mktemp -d); echo "$S"

# 3) 띄우기 (TOTE_BACKGROUND 는 주지 않는다 — 창이 화면에 올라와야 한다)
open --env TOTE_DATA_DIR="$S" --env TOTE_BACKUP_INTERVAL_SECS=600 src-tauri/target/debug/bundle/macos/tote-dev.app
```

- 워크스페이스 폴더는 `$S/workspaces/<이름>` 이다. 처음 켜면 기본 워크스페이스 하나가 있다. 띠의 `+` 로 더 만든다.
- 앱 안에서 쓸 외부 파일은 `$S` 밖의 새 폴더(예: `mktemp -d` 한 번 더)에 만든다.
- `chmod` 는 **시험 폴더 안에서만** 쓴다: `chmod a-w "$S/workspaces/<이름>"` 로 저장 실패를 만들고, `chmod u+w` 로 되돌린다.
- 편집기에 글을 넣을 때 `orca computer` 의 `type-text`·`paste-text` 는 글이 두 번 들어가거나 클립보드를 한 번 더 붙인다. 자동으로 넣는다면 `set-value` 를 쓰고 들어간 글을 확인한다. 손으로 치는 항목은 해당 없다.
- 끝나면 앱을 끄고(`osascript -e 'tell application "tote-dev" to quit'`) 아래를 확인한다. 새로 생겼으면 `불합격` 으로 적는다.

```bash
ls -d ~/Tote-dev "$HOME/Library/Application Support/tote-dev" 2>&1   # 둘 다 "No such file" 이어야 한다
pgrep -f tote-dev.app                                                  # 아무것도 없어야 한다
rm -rf "$S"
```

## A. 칸

워크스페이스 하나, 창 하나로 시작한다. 메모 `가`·`나`·`다` 를 만들어 탭을 셋 연다.

| #    | 절차                                                                                                                                                        | 기대                                                                                                                                        | 결과 |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| A-1  | 탭 `가`·`나`·`다` 가 열린 채 `가` 를 활성으로 두고 ⌘\                                                                                                       | 활성 탭 `가` 가 **오른쪽 새 칸으로 옮겨 가고**(복제가 아니다) 그 칸이 포커스 칸이다. 왼쪽 칸에는 `나`·`다` 가 남는다.                       |      |
| A-2  | 탭이 하나뿐인 칸(오른쪽 칸)에서 ⌘\                                                                                                                          | 오른쪽에 **빈 칸**이 생기고 포커스가 그리로 간다. 빈 칸에는 안내만 보인다.                                                                  |      |
| A-3  | 창을 가로로 줄여 칸 하나가 320px 아래가 될 만큼 좁게 한 뒤 ⌘\                                                                                               | 아무것도 하지 않고 상태 표시줄에 `창이 좁아 나눌 수 없습니다`.                                                                              |      |
| A-4  | 칸 둘일 때 경계를 끌어 왼쪽 칸을 아주 좁게 줄이고, 다음에 아주 넓게 늘린다                                                                                  | 어느 칸도 **320px 에서 멈춘다**(더 안 줄어든다). 놓으면 그 비율이 유지된다.                                                                 |      |
| A-5  | ⌥⌘← / ⌥⌘→ 를 번갈아                                                                                                                                         | 포커스 칸이 왼쪽·오른쪽으로 옮겨 간다. 끝 칸에서 더 누르면 그대로. 상태 표시줄이 포커스 칸의 활성 탭 것(줄·열, 언어)을 보인다.              |      |
| A-6  | 사이드바에서 메모 `라` 를 새로 눌러 연다. 그 뒤 포커스 칸을 바꿔 다시 한 번                                                                                 | `라` 가 **포커스 칸**에 열린다. 이미 다른 칸에 열린 메모를 사이드바에서 누르면 새 탭을 만들지 않고 **열린 자리로** 간다.                    |      |
| A-7  | 오른쪽 칸의 마지막 탭을 ⌘W 로 닫는다                                                                                                                        | 칸도 같이 닫히고 칸이 하나가 된다. 빈 칸에서 ⌘W 는 그 칸을 닫는다. 칸이 하나뿐이면 ⌘W 는 창을 닫는다.                                       |      |
| A-8  | 칸 둘일 때 왼쪽 칸의 탭을 **끌어서 오른쪽 칸의 탭 바**에 놓는다                                                                                             | 탭이 오른쪽 칸으로 **옮겨 간다**(저장 동작 없이 글·커서·스크롤 그대로). 4px 넘게 움직여야 끌기가 시작된다. 놓기 전 놓일 자리 표시가 보인다. |      |
| A-9  | 칸 하나일 때 탭을 **편집 영역의 오른쪽 가장자리(48px 안)**로 끌어 놓는다                                                                                    | 새 칸이 생기고 탭이 거기 열린다. 좁은 창(A-3 같은)에서는 아무 일 없이 `창이 좁아 나눌 수 없습니다`.                                         |      |
| A-10 | 끌기 도중 Esc                                                                                                                                               | 끌기가 취소되고 탭이 제자리에 있다.                                                                                                         |      |
| A-11 | 칸 둘 중 **오른쪽 칸에 `.html` 같은 미리보기가 켜진 메모**를 두고, 왼쪽 칸의 탭을 그 미리보기 칸 위를 지나 그 칸의 탭 바에 끌어 놓는다(실제 WKWebView 확인) | 미리보기 위를 지나도 끌기가 끊기지 않고 탭 바에 놓으면 옮겨 간다.                                                                           |      |
| A-12 | **iframe 클릭 포커스.** 오른쪽 칸을 미리보기로 두고 왼쪽 칸이 포커스인 상태에서 미리보기 안쪽을 한 번 누른다. 이어서 ⌘W                                     | 누른 칸이 **포커스 칸**이 된다(칸 강조가 옮겨 감). ⌘W 는 **그 칸의 활성 탭**을 닫는다. 왼쪽 칸 탭이 닫히면 불합격.                          |      |
| A-13 | 칸 둘·너비를 바꿔 둔 채 포커스를 오른쪽 칸에 두고 앱을 껐다 켠다(⌘Q)                                                                                        | 칸 둘, **너비 비율**, **포커스 칸**, 각 칸의 탭·활성 탭이 그대로 돌아온다.                                                                  |      |
| A-14 | 같은 메모를 두 자리에서 열 수 없는지 본다: 칸 둘에서 왼쪽 칸에 열린 메모를 `tote` 로(또는 사이드바에서) 다시 연다                                           | 새 탭이 생기지 않고 **이미 열린 칸·탭이 활성**이 된다.                                                                                      |      |

## B. 한글 조합

macOS 한글 입력기로 **손으로** 친다. 칸 둘(`가`·`나`)에서 시작한다. 실제 입력기가 `blur` 로 조합을 확정하는지는 자동 시험이 못 본다.

| #   | 절차                                                                                              | 기대                                                                                                                                                                    | 결과 |
| --- | ------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| B-1 | 왼쪽 칸 메모에서 「한글」을 치다가 **마지막 글자 조합 도중**(예: `ㅎㅏㄴㄱㅡ` 까지 친 상태)에 ⌥⌘→ | 조합이 확정된 뒤 포커스가 오른쪽 칸으로 간다. 왼쪽 메모에는 `한그` 또는 `한글`(칸을 옮기기 직전 상태)이 **자모가 깨지지 않고** 들어 있다.                               |      |
| B-2 | **P20.** `ㄱ` 만 친 상태(조합 중)에서 ⌥⌘→ 한 뒤 새 칸에서 `ㅏ` 를 친다                            | 새 칸에 `ㅏ` 가 **새로 들어간다**(앞 칸의 `ㄱ` 과 합쳐진 `가` 가 아니다). 새 칸의 캐럿 앞 글자는 바뀌지 않는다. 앞 칸에는 `ㄱ` 이 남아 있다. 불합격이면 다음 계획 후보. |      |
| B-3 | 왼쪽 칸에서 「한글」 조합 도중 **오른쪽 칸의 탭 바(또는 띠가 아닌 다른 칸 영역)를 클릭**한다      | 조합이 확정되고 왼쪽 메모에 글이 그대로 들어간다. 오른쪽 칸이 포커스 칸이 된다.                                                                                         |      |
| B-4 | 칸 하나(메모 하나 이상)에서 「한글」 조합 도중 탭 오른쪽 클릭 → `탭을 새 창으로 옮기기`           | 조합이 확정되고, **떼어 낸 새 창의 그 메모**에 글이 들어 있다(원래 메모 그대로. 옮겨지지 않은 자모가 엉뚱한 메모에 들어가지 않는다). 원래 창에는 그 탭이 없다.          |      |
| B-5 | 조합 도중 띠의 다른 워크스페이스 클릭(전환)                                                       | 조합이 확정되고 떠난 워크스페이스의 그 메모에 글이 저장된다. 대상 워크스페이스에 새 `untitled` 메모가 생기지 않는다.                                                    |      |

## C. 새 창

| #   | 절차                                                                                                                                                                                                                       | 기대                                                                                                                                                                                                           | 결과 |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| C-1 | 창을 **화면 가운데쯤** 두고 ⌥⌘N. 메뉴 `파일 › 새 창` 으로도 한 번                                                                                                                                                          | 같은 워크스페이스의 **빈 칸 하나짜리 창**이 원래 창에서 **오른쪽·아래 24px**, 같은 크기로 뜬다. 창 제목 ` — 2`(원래 창 제목은 그대로 또는 ` — 1` 이 아닌 이름). 한 번 더 하면 ` — 3`.                          |      |
| C-2 | 창을 **화면 오른쪽 아래 끝**에 붙이고 ⌥⌘N                                                                                                                                                                                  | 24px 옮기면 화면 밖이라 **기본 크기·가운데**로 뜬다. 화면 밖으로 나가지 않는다.                                                                                                                                |      |
| C-3 | 창 둘에서 한 창은 메모 `가` 만, 다른 창은 빈 칸. **한 창에서 새 메모를 만든다**                                                                                                                                            | 다른 창의 메모 목록에 그 메모가 **바로**(몇 초 기다리지 않고) 보인다. 삭제·이름 바꿈도 같다.                                                                                                                   |      |
| C-4 | 창 둘에서 창1 에 열린 메모 `가` 를 **창2 의 사이드바에서** 눌러 연다                                                                                                                                                       | 창2 에 새 탭이 생기지 않고, **창1 이 앞으로 와서** 그 칸·탭이 활성이 된다.                                                                                                                                     |      |
| C-5 | 외부 파일 `x.sh` 를 창1 에 열어 둔 채, 번들 실행 파일에 같은 `TOTE_DATA_DIR` 로 `--tote-request='{"files":["<x.sh 절대 경로>"]}'` 를 보내 다시 연다. 이어서 같은 요청에 `"workspace":"<다른 워크스페이스>"` 를 더해 보낸다 | 창1 이 앞으로 오고 그 탭이 활성이 된다. 새 탭이 생기지 않는다. 두 번째 요청도 열린 파일을 다른 워크스페이스로 **옮기지 않는다**.                                                                               |      |
| C-6 | 창 둘(같은 워크스페이스)에서 한 창만 닫고 앱을 껐다 켠다(⌘Q)                                                                                                                                                               | 남은 창의 배치 **하나만** 돌아온다. 이어서 마지막 창까지 닫고(앱은 살아 있다면 그대로) 껐다 켜면 마지막 창의 배치가 남아 있다.                                                                                 |      |
| C-7 | **창 자리·크기 복원.** 창 둘을 서로 다른 자리·크기로 두고(예: 왼쪽 위 작게 / 오른쪽 아래 크게) ⌘Q 후 다시 켠다                                                                                                             | 두 창이 **각자 저장했던 자리·크기**로 돌아온다. 에이전트 스모크(백그라운드)에서는 두 창이 같은 값(236,128 1101×761)으로 다시 쓰여 원인을 못 가렸다. 같은 값으로 모이면 불합격이고, 두 창의 자리·크기를 적는다. |      |
| C-8 | **다른 모니터에서 복원**(모니터가 둘일 때만). 창을 두 번째 모니터에 두고 ⌘Q 후, 모니터를 뺀 채 켠다                                                                                                                        | 창이 보이는 모니터 안에 뜬다(화면 밖에 뜨지 않는다). 모니터가 하나뿐이면 `못 함`.                                                                                                                              |      |

## D. 탭 떼어 내기

끌어서 떼어 내기는 하지 않는다 — 스파이크 (a2) 는 `확인 못 함` 이었고 코어 스펙에 「끌기로는 떼어 내지 않는다」로 적었다. 아래 O-1 의 측정 결과에 따라 끌기를 다음 계획에 넣을지 정한다.

| #    | 절차                                                                                                                                           | 기대                                                                                                                                                                  | 결과 |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| D-1  | 탭 둘 이상에서 **활성이 아닌** 탭을 오른쪽 클릭                                                                                                | 포인터 자리에 **네이티브 팝업 메뉴** `탭을 새 창으로 옮기기` 가 뜬다.                                                                                                 |      |
| D-2  | D-1 의 메뉴에서 항목을 고른다                                                                                                                  | 그 탭(활성이 아니었어도)이 같은 워크스페이스의 **새 창**으로 가서 글·위치 그대로 열린다. 원래 창에서는 사라진다. 새 창은 C-1 규칙(오른쪽·아래 24px, ` — 2`)으로 뜬다. |      |
| D-3  | 메뉴를 띄운 뒤 Esc, 다시 띄워 메뉴 밖을 클릭                                                                                                   | 아무 일 없다(탭이 옮겨 가지 않는다).                                                                                                                                  |      |
| D-4  | **앞 선택이 새지 않는지.** 탭 `가` 에서 메뉴를 띄워 Esc, 곧바로 탭 `나` 에서 메뉴를 띄워 항목을 고른다. 또 메뉴를 연달아 여러 번 열었다 닫는다 | `나` 만 옮겨 간다. `가` 가 옮겨 가거나 아무 때나 창이 열리면 불합격.                                                                                                  |      |
| D-5  | 메뉴 `윈도우 › 탭을 새 창으로 옮기기`                                                                                                          | 활성 탭이 새 창으로 간다. 탭이 하나뿐일 때도 된다(원래 창은 빈 칸이 된다).                                                                                            |      |

| D-7  | **외부 파일**(`x.sh`)에 글을 고쳐 저장하지 않은 채 D-2 로 떼어 낸다                                                                            | 새 창에 **저장 전 수정분 포함** 글이 열린다(저장 안 된 표시도 그대로).                                                                                                |      |
| D-8  | **저장 실패.** 워크스페이스 폴더를 `chmod a-w` 한 뒤 메모에 글을 쳐 저장이 실패하게 하고(상태 표시줄 `저장 실패`) D-2 로 떼어 낸다             | **옮기지 않는다.** 탭이 원래 창에 남고 `저장 실패` 가 그대로 남는다(상태 표시줄에 알림). 확인 뒤 `chmod u+w`.                                                         |      |
| D-9  | 충돌 배너가 떠 있는 탭(바깥에서 파일을 바꿔 띄운다)을 떼어 낸다                                                                                | 옮기지 않고 상태 표시줄에 알린다.                                                                                                                                     |      |

## O. 측정

load 가 높으면 값이 틀어진다. 모든 측정 앞에 `uptime` 으로 load 가 **3 아래**인지 본다(`perf:measure` 가 기다린다). 측정 중에는 다른 무거운 작업을 하지 않는다. 측정 번들은 사람 화면에 창을 띄우므로 측정 동안 건드리지 않는다.

### O-1. 창 밖 끌기 (스파이크 a1·a2, 코디네이터 판정용)

끌어서 떼어 내기를 다음 계획에 넣을지 정하는 근거다. 절차와 읽는 법은 `spikes/lab/README.md` 「사람이 하는 측정」의 `drag` 항목, 판정 기준은 스파이크 보고서 「(a1)·(a2) — 사람이 나중에 재는 절차」.

```bash
cd spikes/lab && pnpm install && pnpm tauri build --debug --no-bundle
rm -f results/drag.json
TOTE_LAB_MANUAL=drag ./src-tauri/target/debug/lab
```

`drag` 모드는 **빌드·타입 검사만 했고 한 번도 실행되지 않았다.** 첫 실행에서 페이지 오류가 날 수 있으니 `results/drag.json` 의 `screenX/Y`·`clientX/Y` 원본을 같이 본다. 창을 다른 창으로 가리지 않은 채 잰다.

세 가지를 **각각 세 번**: ① 탭을 다른 탭 바에 놓기 ② 탭을 창 밖(바탕 화면)에 놓기 ③ 끌다가 창 안에서 Esc. 포인터 변형 바도 같은 세 가지.

| #    | 절차                              | 기대                                                                                             | 결과 |
| ---- | --------------------------------- | ------------------------------------------------------------------------------------------------ | ---- |
| O-1a | ① 탭 바 사이 놓기 ×3 (HTML5 끌기) | **(a1) 됨:** `dragstart`·`dragover`·`drop`·`dragend` 가 모두 오고 `drop` 의 `target` 이 다른 바. |      |
| O-1b | ② 창 밖 놓기 ×3                   | **(a2) 구별함:** 마지막 `dragend` 가 `dropEffect === "none"` 이고 `insideWindow === false`.      |      |
| O-1c | ③ 창 안 Esc ×3                    | `drop` 없이 `dragend`, `insideWindow === true` — ② 와 **갈린다**.                                |      |
| O-1d | 포인터 변형 ①②③ 각각 ×3           | 창 밖 `pointerup` 이 `setPointerCapture` 뒤에 오는가(`insideWindow === false`).                  |      |

판정: O-1b·O-1c 가 모두 갈리면 (a2) **구별함** → 끌어서 떼어 내기를 다음 계획에 넣는다. 한쪽이라도 같으면 **끌기로는 떼어 내지 않는다**를 유지한다(코어 스펙 그대로). `results/drag.json` 에서 각 세 번의 값을 옮겨 적는다.

### O-3. 워크스페이스 전환 시간

목표 1,000ms. **관문이 아니다** — 넘으면 다음 계획에서 컨트롤러 다시 세우기를 검토할 근거로 남긴다. O-2 의 명령이 만든 perf 번들을 쓴다.

```bash
S=$(mktemp -d)
mkdir -p "$S/workspaces" && cp /tmp/tote-perf-fixtures/machine.json "$S/" \
```
