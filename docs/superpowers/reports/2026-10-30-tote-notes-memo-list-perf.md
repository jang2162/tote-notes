# tote-notes 메모 목록 미리보기 — 목록 첫 수신 실측

메모 목록 기능 묶음 계획(`docs/superpowers/plans/2026-10-30-tote-notes-memo-list-features.md`) Task 5 의 측정 기록이다. 스펙(`docs/superpowers/specs/2026-10-30-tote-notes-memo-list-features-design.md` 「미리보기」 의 ⚠)이 「메모 10,000 개 워크스페이스에서 목록을 처음 받는 시간이 코어 설계 「성능」 절의 목표를 넘지 않아야 한다」 고 한 것을 미리보기를 넣기 전과 뒤에 쟀다. 규칙은 `tests/measure/perf.md` 그대로이고, 이 시나리오는 그 파일 「측정 전에 더한 것」 의 「메모 목록 첫 수신」 항목으로 데이터를 보기 전에 적었다.

## 한눈에

| 지표(`memos-10k`, 세션 없음)     | 목표    | 전(`2f6fddf`) 중앙값 | 후(`e1423f8`) 중앙값 | 판정 |
| -------------------------------- | ------- | -------------------- | -------------------- | ---- |
| `process-start` → `memos-listed` | 1,500ms | 481.8ms              | 816.2ms              | 된다 |
| `process-start` → `app-ready`    | 1,500ms | 492.0ms              | 832.2ms              | 된다 |

**미리보기를 목록과 함께 주는 방식(`MemoInfo.preview`)으로 둔다.** 목록 첫 수신이 334.4ms 늘었지만(1만 개 파일의 앞 4KB 를 읽는 몫) 목표 안쪽이다. 스펙이 말한 「목록 먼저, 미리보기는 뒤따라」 로는 바꾸지 않았다.

## 회별 값

값은 ms, 회 순서. p95 는 nearest-rank(5회면 최댓값). 무효·재실행은 둘 다 0.

| 지표           | 전                                | 전 p95 | 후                                | 후 p95 |
| -------------- | --------------------------------- | ------ | --------------------------------- | ------ |
| `memos-listed` | 499.3, 510.9, 469.9, 481.8, 426.4 | 510.9  | 826.1, 839.4, 790.9, 789.7, 816.2 | 839.4  |
| `app-ready`    | 513.6, 529.3, 480.1, 492.0, 438.5 | 529.3  | 842.5, 856.2, 807.1, 806.2, 832.2 | 856.2  |

## 환경

- Mac17,9 · Apple M5 Pro · 48GB, macOS 27.0.1 (26A434), 전원 연결(AC). 켜진 디스플레이는 2560×1440 외장(주 디스플레이). 창은 배경(`TOTE_BACKGROUND=1`)이라 rAF 를 쓰지 않는 이 두 마크에는 디스플레이가 끼지 않는다.
- 빌드: `perf` 프로필, `tauri.dev.conf.json`. 전은 이 워크트리를 `2f6fddf`(측정 시나리오만 더하고 미리보기는 없는 커밋)로 옮겨 빌드했고, 후는 `e1423f8`(여섯 기능 전부)로 돌아와 같은 `target/` 에서 다시 빌드했다.
- 부하: 시작 때 1분 load average 전 2.36(17:38), 후 2.88(17:43). 같은 기기에서 다른 에이전트 세션이 돌고 있었다.
- 픽스처: `pnpm perf:fixtures` 의 `memos-10k`(메모 1만 개, 각 2KB 안팎). 메모가 4KB 보다 작아 미리보기가 파일을 통째로 읽는다 — 큰 메모가 많은 워크스페이스에서도 읽는 양은 메모마다 4KB 로 묶인다.
- 측정 뒤 `~/.tote-dev`·`~/Library/Application Support/tote-dev` 는 새로 생기지 않았다(스크립트의 `WARNING: the measurement made …` 없음).

## 다시 재는 법

```bash
pnpm perf:fixtures <빈 폴더>/fixtures
TOTE_DATA_DIR=$(mktemp -d) PERF_ONLY="list-10k" pnpm perf:measure <빈 폴더>/fixtures
grep -E '메모 1만 개 \|' tests/measure/results/summary.md
```

`com.develma.totenotes.dev` 식별자의 앱(디버그 번들, `pnpm app:dev`)이 떠 있으면 스크립트가 시작하지 않는다. 미리보기 전 값을 다시 보려면 워크트리를 `2f6fddf` 로 옮겨 같은 명령을 돌린다.

## 재지 않은 것

- 미리보기 캐시가 찬 뒤의 목록 다시 읽기(창 포커스·다른 창의 변경마다 도는 `listMemos`). 같은 파일은 다시 읽지 않으므로(이름·수정 시각·크기가 같으면 캐시) 첫 수신보다 작아야 하지만 재지 않았다.
- 내용 필터(`find_in_memos`)의 시간. 워크스페이스 검색과 같은 엔진·같은 대상이고 파일마다 첫 일치에서 멈추므로 「검색 메모 1만 개」(168.8ms, `docs/superpowers/reports/2026-10-12-tote-notes-perf.md`) 이하로 본다 — 파일마다 둘째 일치를 만나면 그 파일을 그만 읽는다. 추론이다.
