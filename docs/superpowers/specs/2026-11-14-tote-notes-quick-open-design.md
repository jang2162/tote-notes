# tote-notes 빠른 열기(⌘P)·명령 팔레트 설계

2026-11-14. 2026-11-13 점검 끝에 추천받은 기능 묶음의 하나다. 사용자는 설계 확인 없이 바로 진행하라고 했다. 그래서 결정마다 출처를 붙인다 — **코디네이터의 판단**(작업 지시서가 정한 것)과 **구현자의 판단**(지시서가 비워 둬서 만드는 사람이 정한 것). 바꾸고 싶으면 그 줄만 고친다.

## 왜

메모를 열려면 사이드바 메모 목록에서 찾아 누르거나 필터 칸에 쳐야 한다. 손이 키보드에 있는 채로 메모 하나를 이름 몇 글자로 여는 길이 없다. 코어 설계(`docs/superpowers/specs/2026-10-07-tote-note-core-design.md`) 「범위」 의 「1차에 넣지 않는 것」 첫 항목이 「⌘P 빠른 열기, 명령 팔레트」 였다. 이 문서로 그 둘이 들어온다.

## 하지 않는 것

코디네이터의 판단:

- 메모 **내용** 검색. 워크스페이스 검색(⇧⌘F)과 메모 목록 필터의 몫이다.
- 다른 워크스페이스의 메모, 파일 시스템의 아무 파일.
- 한글 초성 검색(「ㅎㄱ」 으로 「회의」 찾기).
- 편집기 안의 줄·기호로 가기(`:`·`@` 접두).
- 명령 팔레트의 별도 단축키(⇧⌘P 는 미리보기 전환이 쓴다).

구현자의 판단:

- 휴지통의 메모(읽기 전용 탭으로 열린 것 포함). 휴지통은 사이드바의 휴지통 화면에서 연다.
- 고른 결과를 기억해 순위를 올리는 학습. 순위는 이름 일치와 조회 시각만으로 정한다.

## 여는 법

- 메뉴 **「파일 › 빠른 열기…」**, 기본 키 **⌘P**(`CmdOrCtrl+P`). 명령 id 는 `quick-open` 이다(코디네이터의 판단: 메뉴와 기본 키. 구현자의 판단: id 와 「파일 열기…」 바로 아래라는 자리 — 여는 명령끼리 모은다).
- 설정 › 단축키에서 바꾸고 지우고 되돌릴 수 있는 앱 명령이다(코디네이터의 판단).
- **⌘P 는 다른 명령에 저장된 키에 양보한다**(`shortcuts::Command::yields`, 구현자의 판단). 이 판 전에 사람이 ⌘P 를 다른 명령에 걸어 두었으면 그 키가 이기고 「빠른 열기…」 는 키 없이 시작한다. 그 키가 풀리면 ⌘P 로 돌아온다. ⌘B 의 사이드바 접기, ⇧⌘P 의 미리보기 전환과 같은 규칙이다(코어 설계 「전체 구조」). 양보하지 않으면 업데이트만으로 사람이 저장한 단축키가 지워진다(`sanitize` 는 기본값과 겹치는 저장 키를 버린다).
- 겹침 확인(구현자의 판단으로 확인한 것): ⌘P 는 다른 기본 단축키(`shortcuts::COMMANDS`)·고정 단축키(`shortcuts::FIXED`)와 겹치지 않는다 — Rust 시험 `every_built_in_shortcut_parses_is_recordable_and_none_is_taken_twice` 가 본다. 편집기 키맵에도 ⌘P 가 없다 — vitest `src/ui/quick-open-match.test.ts` 「⌘P is no editor key」 가 `conflict()` 로 본다. macOS 의 ⌘P 는 앱 메뉴의 「프린트」 관례이고 시스템 전역 키가 아니다. 이 앱에는 프린트 메뉴가 없다.
- 대화상자가 떠 있거나 창이 떠나는 중이면 메뉴 명령이 버려지는 기존 규칙(`AppController.onMenu`)을 그대로 따른다. 빠른 열기가 떠 있는 동안 ⌘P 를 다시 눌러도 아무것도 하지 않는다.

## 모양

- 창 위쪽 가운데에 뜨는 띄움 상자. 입력칸 하나와 그 아래 결과 목록(코디네이터의 판단).
- 기존 모달(`modal()`, `src/ui/dialogs.ts`)로 띄운다 — 배경 `inert`, Tab 이 상자 안에서 돌기, Esc 로 닫기, 닫으면 포커스를 연 자리로 되돌리기, 메뉴 가드가 그대로 따라온다(코디네이터의 판단).
- 상자는 창 맨 위에서 72px 아래에 놓이고 너비 520px(창이 좁으면 창 너비 − 32px)다. 배경은 다른 모달과 달리 어둡게 덮지 않는다 — 치는 동안 아래 편집기가 그대로 보인다(구현자의 판단. 버린 대안: 다른 모달과 같은 25% 어둡게 — 띄움 상자가 「창 전체를 막는 질문」 처럼 보인다).
- 결과 목록은 한 번에 **10행**까지 보이고 넘치면 목록 안에서 스크롤된다. 결과는 **최대 50개**다(구현자의 판단: 이름 몇 글자로 고르는 상자라 50개 아래에서 고르지 못하면 더 쳐야 한다. 1만 메모를 모두 그리지 않는다).
- 입력칸의 안내 글: 「메모 이름 — 명령은 >」(구현자의 판단).

## 메모 찾기

- **대상:** 지금 창의 워크스페이스의 메모 전부 — 메모 목록이 보이는 것과 같은 것(휴지통 제외, 고정 여부 무관, 필터 칸과 무관). 그리고 **열려 있는 외부 파일 탭 전부, 어느 창이든**(코디네이터의 판단).
  - 다른 창의 외부 파일 탭은 새 백엔드 명령 `list_open_externals`(`Backend.listOpenExternals`)로 받는다. 「한 메모는 한 자리에」 의 자리 기록(`Places`)에서 외부 파일 자리를 모두 꺼내 경로순으로 돌려준다(구현자의 판단: 자리 기록이 모든 창의 탭을 이미 한 곳에 갖고 있다).
- **일치:** 이름(메모는 파일 이름, 외부 파일은 경로의 마지막 부분)에 대한 퍼지 일치. 친 글자가 이름 안에 **순서대로** 들어 있으면 맞는다. 대소문자 무시, 양쪽을 NFC 로 맞춘다 — Finder 가 주는 NFD 이름도 맞는다(코디네이터의 판단).
  - 친 글의 공백은 무시한다(구현자의 판단: 「회의 메모」 가 「회의메모.md」 와 「회의 메모.md」 를 모두 찾는다).
- **점수**(구현자의 판단, `src/ui/quick-open-match.ts` 의 `fuzzyMatch`): 맞은 글자마다 1점, 바로 앞 글자도 맞았으면(연속) 7점 더(단어 머리보다 크게 — 친 글자가 한 덩어리로 있는 것이 단어마다 흩어진 머리보다 앞선다), 맞은 글자가 단어 머리면 6점 더(이름의 맨 앞이면 8점), 맞은 글자 사이에 건너뛴 글자마다 0.1점 뺀다. 단어 머리는 이름의 맨 앞, 공백·`-`·`_`·`.`·`/`·괄호 뒤, 소문자 뒤의 대문자, 한글과 한글 아닌 글자의 경계다. 같은 글자가 여러 자리에 있으면 점수가 가장 높은 자리를 고른다(동적 계획).
- **순위:** 점수 높은 순. 같으면 최근에 본 순(아래 「조회 시각」), 그것도 같으면 메모 목록의 이름순(`byName`)이다(구현자의 판단). 외부 파일은 조회 시각이 없어 같은 점수의 메모 뒤에 온다.
- **빈 입력:** 메모를 **최근에 본 순서**로 보인다 — 메모 목록의 「최근 조회순」 이 쓰는 값과 규칙 그대로(`sortMemos(…, "viewed-desc")`: 한 번도 본 적 없는 메모는 수정 시각, 동점은 이름순)(코디네이터의 판단). 최근 50개 메모 뒤에 열려 있는 외부 파일을 경로순으로 모두 붙인다(구현자의 판단: 외부 파일은 조회 시각이 없고 대개 몇 개뿐이다. 앞에 두면 「⌘P, Enter 로 방금 본 메모로」 가 외부 파일에 막힌다).
- **보이기:** 행마다 이름을 보이고 맞은 글자를 굵게 한다(코디네이터의 판단). 외부 파일 행은 이름 뒤에 그 폴더 경로를 흐리게 보인다(구현자의 판단: 같은 이름의 두 파일을 가른다). 이름은 NFC 로 보인다.
- 맞는 것이 없으면 목록 자리에 **「일치하는 메모가 없습니다」** 한 줄(코디네이터의 판단).

## 키와 누르기

- ↑↓ 로 고른다. 맨 위·맨 아래에서는 멈춘다(돌아가지 않는다, 구현자의 판단). 고른 행은 목록 안에서 보이게 스크롤된다. 글을 칠 때마다 고른 행은 첫 행으로 돌아간다.
- **Enter 로 연다**(코디네이터의 판단). 상자를 닫은 뒤 메모는 `AppController.openMemo`, 외부 파일은 `openExternal` 로 연다. 그래서 「한 메모는 한 자리에」 가 그대로 선다 — 지금 창에 없으면 **포커스 칸**에 새 탭으로 열리고, 이미 지금 창의 다른 칸에 열려 있으면 **그 칸으로** 가서 그 탭을 활성화하고, 다른 창에 열려 있으면 **그 창이 앞으로 와서** 그 탭을 보인다.
- 행을 **마우스로 눌러도** 연다(코디네이터의 판단). 누르는 동안 입력칸이 포커스를 잃지 않는다.
- **한글 조합 중 Enter 는 조합을 확정할 뿐 열지 않는다**(코디네이터의 판단). 기존 입력칸과 같은 판정(`isSubmitEnter`·`isCompositionKey`, `src/ui/dialogs.ts`)을 쓴다 — `isComposing` 이거나 `keyCode` 229 인 Enter 는 열기가 아니다. 조합 중 ↑↓ 도 고르기에 쓰지 않는다(구현자의 판단: 후보 창이 있는 입력기에서 ↑↓ 는 입력기의 몫이다).
- **Esc 로 닫는다**(코디네이터의 판단). 포커스는 연 자리(대개 편집기)로 돌아간다(`modal()`). 조합 중 Esc 는 조합을 취소할 뿐 닫지 않는다(`modal()` 의 기존 규칙).
- 결과가 없을 때 Enter 는 아무것도 하지 않는다.

## 명령 팔레트

- 입력이 `>` 로 시작하면 **명령 팔레트**다. `>` 뒤의 글(앞뒤 공백 무시)로 메뉴의 앱 명령을 같은 퍼지 일치로 찾는다(코디네이터의 판단).
- 대상은 설정 › 단축키 목록과 같은 앱 명령(`Backend.shortcutTable()` 의 `commands`)이고, 행에는 **명령 이름과 지금 키**를 보인다(코디네이터의 판단). 이름 뒤에 그 명령이 있는 메뉴 이름을 흐리게 보인다(구현자의 판단).
  - 「빠른 열기…」 자신은 목록에서 뺀다(구현자의 판단: 고르면 상자를 닫고 같은 상자를 다시 연다).
  - 고정 단축키 항목(설정…, 종료, 편집 메뉴)은 앱 명령이 아니라 목록에 없다(구현자의 판단: 단축키 목록이 「앱 명령」 으로 보이는 것과 같게).
- `>` 만 쳤으면 명령 전부를 메뉴 순서로 보인다(구현자의 판단).
- **Enter(또는 누르기)로 실행한다.** 상자를 닫은 뒤 `Backend.runMenuCommand(id)` 로 보낸다 — 메뉴 항목을 고른 것과 같은 길(`menu::run_command`)이다(구현자의 판단: 「새 창」·「창 닫기」·「업데이트 확인…」·「셸 명령 설치…」 는 Rust 가 실행해서 페이지의 `onMenu` 만 불러서는 되지 않는다. 편집기가 메뉴 키를 넘길 때 쓰는 길과 같다). 실행할 수 없는 상황은 `onMenu` 가 막는 그대로다(코디네이터의 판단).
- 맞는 명령이 없으면 「일치하는 명령이 없습니다」.

## 조회 시각

빈 입력의 순서와 동점 순서는 메모 목록의 「최근 조회순」 과 같은 값(`MemoInfo.viewedMs`, 없으면 `modifiedMs`)을 쓴다(`docs/superpowers/specs/2026-10-30-tote-notes-memo-list-features-design.md` 「정렬」). 빠른 열기로 연 메모도 칸에 보이는 순간 조회 시각이 바뀐다 — 사이드바에서 연 것과 같다. 새로 저장하는 것은 없다.

## 데이터·저장

- 설정을 더하지 않는다. `settings.json` 에 바뀌는 것은 없다(단축키를 바꾸면 기존 `shortcuts` 맵에 `quick-open` 항목이 생길 뿐이다).
- 새 백엔드 명령 `list_open_externals` — 인자 없음, 모든 창의 외부 파일 탭 경로(`Vec<PathBuf>`, 경로순). 쓰지 않는다.

## 시험

- Rust(`src-tauri/src/shortcuts.rs`·`src-tauri/src/app/menu.rs`·`src-tauri/src/app/places.rs`): 「파일 › 빠른 열기…」 가 「파일 열기…」 바로 아래에 있고 기본 키가 ⌘P 이며 양보한다, 저장된 ⌘P 가 그 명령에 남고 빠른 열기는 키 없이 시작한다, 기본 단축키끼리 겹치지 않는다, 자리 기록이 외부 파일 자리만 경로순으로 내놓는다.
- vitest(`src/ui/quick-open-match.test.ts`): 퍼지 일치(순서, 대소문자, NFC·NFD, 공백 무시), 점수와 순위(연속·단어 머리 가산, 동점의 조회 시각·이름순), 빈 입력의 최근 순서와 외부 파일 자리, 결과 수 제한, 명령 팔레트의 대상과 자신 빼기, ⌘P 가 편집기 키가 아님.
- e2e(`tests/e2e/quick-open.spec.ts`, 가짜 백엔드): 메뉴 id 로 열기 → 치기 → Enter 로 그 메모가 포커스 칸에 열림, 이미 다른 칸에 열린 메모는 그 칸으로, 다른 창에 열린 외부 파일이 목록에 있음, 마우스로 열기, Esc 로 닫으면 포커스가 편집기로, `>` 로 명령 실행, 조합 중 Enter 가 열지 않음, 맞는 것이 없을 때의 한 줄, 빈 입력의 최근 순서.
- e2e 는 메뉴 단축키를 누르지 못한다(`docs/guides/development.md` 「e2e 는 메뉴 단축키를 누르지 못한다」). ⌘P 가 실제 메뉴에서 이 명령을 부르는지는 Rust 시험과 사람 확인으로 본다.
