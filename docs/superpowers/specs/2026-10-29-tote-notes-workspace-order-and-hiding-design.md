# tote-notes 워크스페이스 순서·숨김과 고르개 단축키 안내 — 설계

2026-10-29. 사용자 요청: 「워크스페이스 순서 설정 가능하도록. 좌측에 워크스페이스 선택 펼치면 오른쪽 끝에 워크스페이스 전환 단축키 안내」, 이어서 「설정에 워크스페이스 관리 추가하고 드래그로 순서 조정. 관리 페이지 추가하는 김에 숨김 여부 추가해줘. 숨긴 워크스페이스는 워크스페이스 선택에서 표시 안 함」, 「워크스페이스 설정은 워크스페이스 루트에 저장」. 사용자는 시안(설정 구역 목록 + 펼친 고르개, 저장소 밖)을 보고, 「지금 창의 워크스페이스를 숨기면 고르개 목록에서도 사라진다」에 「맞아」로 답했다. 그 밖에 이 문서에서 정한 것은 **설계자 판단**으로 표시한다.

## 왜

- 고르개(사이드바 맨 위 콤보박스, `src/ui/workspace-switcher.ts`)는 워크스페이스를 **이름순으로만** 늘어놓고, ⌃1~⌃9 가 그 순서의 1~9번째를 고른다. 자주 쓰는 워크스페이스를 ⌃1·⌃2 에 두려면 이름을 바꾸는 수밖에 없다.
- ⌃1~⌃9 가 어느 워크스페이스로 가는지 화면 어디에도 보이지 않는다.
- 쓰지 않는 워크스페이스도 고르개에 늘 보이고 ⌃ 번호를 차지한다.

## 목표

1. 설정 화면에 **「워크스페이스」 구역**이 생기고, 거기서 워크스페이스를 **끌어서 순서를 바꾼다.**
2. 같은 구역에서 워크스페이스마다 **숨김**을 켜고 끈다. 숨긴 워크스페이스는 고르개에 보이지 않는다.
3. 고르개와 ⌃1~⌃9 가 **그 순서·숨김을 따른다.**
4. 고르개를 펼치면 각 워크스페이스 행 **맨 오른쪽에 그 행의 전환 단축키**(⌃1~⌃9)가 보인다.
5. 순서와 숨김은 **워크스페이스 루트에** 저장된다. 루트 폴더를 다른 기기와 동기화하면 순서·숨김도 따라간다.

## 하지 않는 것

- 관리 구역에서 워크스페이스 이름 바꾸기·지우기·만들기.
- ⌃1~⌃9 를 다른 키로 바꾸기(고정 단축키로 남는다).
- 10번째 이후 워크스페이스의 단축키.
- 「워크스페이스 열기…」 대화상자(`workspacePicker`)의 순서·숨김. 이 대화상자는 지금처럼 최근 사용순으로 **숨긴 것까지 모두** 보인다. 숨긴 워크스페이스를 여는 길이 여기 남는다.
- 루트 바깥의 워크스페이스(최근 목록에만 있는 것, 사라진 것)의 순서·숨김.
- 키보드만으로 순서 바꾸기 **(설계자 판단: 사용자가 「드래그로」 를 골랐다. 구현이 싸면 넣어도 된다 — 아래 「빌더에게 남긴 것」)**.

## 하면 실패인 것

- 설정에서 순서를 바꿨는데 이미 열린 다른 창의 고르개·⌃ 번호가 옛 순서로 남는다.
- 숨긴 워크스페이스가 ⌃ 번호를 차지한다(아래의 것이 한 칸 당겨지지 않는다).
- 고르개의 단축키 표시와 실제로 ⌃n 이 가는 곳이 다르다.
- 워크스페이스 폴더 이름을 바꿨더니(Finder·`relocate`) 순서나 숨김이 풀린다.
- 순서 파일이 깨졌거나 모르는 내용이면 고르개가 비거나 앱이 실패한다. (이름순으로 돌아가야 한다.)
- 루트 폴더를 쓸 수 없을 때 끌기가 조용히 되돌아간다(까닭이 보이지 않는다).
- 순서 파일이 루트에 있어 **워크스페이스로 잘못 읽히거나** 메모 감시·백업에 섞인다.

## 저장

- **자리:** 워크스페이스 루트 바로 아래 숨김 파일 하나. 이름은 설계자 판단으로 `<루트>/.tote-workspaces.json`. `Workspace::list` 는 `.` 으로 시작하는 이름을 건너뛰므로 워크스페이스로 읽히지 않는다.
- **열쇠는 워크스페이스 id** (`.tote/workspace.json` 의 `id`)에 **폴더 이름을 곁들인 쌍**이다. 그래서 이름을 바꾸거나 옮겨도 순서·숨김이 남는다 **(설계자 판단)**.
  - 폴더 이름을 곁들이는 까닭: Finder 에서 복제한 폴더는 원본과 **같은 id** 를 갖는다(`AppCore::workspace_key` 주석이 이미 이 경우를 전제한다). id 만 열쇠로 쓰면 한쪽을 숨길 때 둘 다 숨겨진다.
  - **맞추는 순서 (설계자 판단):** ① id 와 이름이 둘 다 같은 항목 ② 그 id 를 가진 폴더가 루트에 **하나뿐이면** id 만 같은 항목(이름을 바꾼 경우) ③ 어느 것에도 안 맞으면 파일에 없는 워크스페이스로 친다(맨 끝). 같은 id 의 폴더가 여럿인데 이름이 안 맞는 것은 ③ 이다. 저장할 때는 지금 이름으로 고쳐 쓴다.
  - `.tote/workspace.json` 을 읽을 수 없는 워크스페이스는 id 가 없다. 그런 것은 맨 끝(파일에 없는 워크스페이스보다도 뒤, 그들끼리 이름순)에 두고 숨김 체크박스를 끈 채(`disabled`) 보인다 **(설계자 판단)**. 열면 `Workspace::open` 이 새 id 를 주므로 그다음부터는 보통 항목이다.
- **모양 (설계자 판단):**
  ```json
  { "version": 1, "order": [{ "id": "<id>", "name": "<폴더 이름>" }, ...], "hidden": [{ "id": "<id>", "name": "<폴더 이름>" }, ...] }
  ```
  - `order` 에 없는 워크스페이스(새로 만든 것, 다른 기기에서 생긴 것)는 **목록 맨 끝에, 그들끼리 이름순으로** 붙는다.
  - `order`·`hidden` 에 있는데 루트에 없는 id 는 무시한다. 다음 저장 때 지워도 되고 남겨도 된다(빌더 판단). 남기면 그 워크스페이스가 돌아왔을 때 자리를 되찾는다.
- **읽기:** 파일이 없으면 모두 이름순·숨김 없음. 깨졌거나 `version` 을 모르면 이름순·숨김 없음으로 보이고, 파일은 **덮어쓰기 전까지 건드리지 않는다** **(설계자 판단: 다른 기기의 새 빌드가 쓴 파일을 이 빌드가 지우지 않게)**. 필드 하나만 모양이 틀리면 그 필드만 기본값이다(`settings.json` 의 `lenient` 와 같은 방식).
  - ⚠ 기존 `persist::read_json` 은 깨진 파일을 `.corrupt-<ms>` 로 이름을 바꿔 치워 둔다. 위 규칙과 다르므로 이 파일에는 쓰지 않는다. 쓰기 쪽 `persist::write_json` 은 그대로 쓴다.
- **쓰기:** 끌기를 놓을 때, 숨김을 바꿀 때 바로 쓴다. 기존 JSON 쓰기와 같은 원자적 쓰기(임시 파일 → 이름 바꾸기)를 쓴다. 쓰기가 실패하면 설정 화면의 상태 줄(`modal-error`)에 까닭을 보이고 목록을 파일 내용대로 되돌린다.
- **루트가 바뀌면** 새 루트의 파일을 읽는다. 루트마다 순서가 따로다. 지금 루트를 바꾸는 `patch_settings` 는 `tote://config` 만 보내고 고르개는 그 신호를 듣지 않는다. 그래서 루트가 바뀔 때 **`tote://workspaces` 도 보내** 열린 창의 고르개와 설정 구역이 새 루트의 목록으로 바뀌게 한다.
- **앱을 처음 띄울 때**(최근 목록이 비었을 때) 고르는 워크스페이스(`AppCore::fallback_workspace`)는 이름순 첫 번째가 아니라 **순서 파일 순서로 숨기지 않은 첫 번째**다. 모두 숨겼으면 순서상 첫 번째다 **(설계자 판단)**.
- 다른 기기의 동기화로 파일이 바뀐 것을 **감시하지는 않는다** **(설계자 판단)**. 다음에 목록을 다시 읽을 때(아래 「다른 창에 알리기」) 반영된다.

## 백엔드

- `list_workspaces` 는 지금처럼 **최근 사용순**으로 돌려주고(「워크스페이스 열기…」 가 그대로 쓴다), 각 항목에 **`order`**(순서 파일 순서로 매긴 자리, 0부터, 숨긴 것도 센다), **`hidden`**, **`orderable`**(id 를 읽을 수 있음)을 싣는다. 사라진 것(`missing`)은 지금처럼 뒤에 붙고 `order: null`·`hidden: false`·`orderable: false` 다. 프론트는 경로만 다루고 id 를 모른다.
  - 고르개(`switcherItems`)와 설정 구역은 `order` 로 정렬한다. **결과:** 고르개·설정 구역은 순서 파일 순서, 「워크스페이스 열기…」 는 최근 사용순.
  - ⚠ `order` 는 ⌃ 번호가 아니다. ⌃ 번호는 숨긴 것을 뺀 고르개 목록에서 다시 센다(`shortcutHint`).
- 순서·숨김을 바꾸는 명령 하나(예: `set_workspace_order({ order, hidden })`, 이름은 빌더 판단). 저장한 뒤 **`tote://workspaces` 를 모든 창에 보낸다.**
- 프론트 `Backend`(`src/backend/types.ts`)·`TauriBackend`·`FakeBackend`(e2e 용)에 같이 넣는다.

## 다른 창에 알리기

- 순서·숨김이 바뀌면 `tote://workspaces` 로 모든 창이 `refreshSwitcher` 를 돈다(기존 경로). 다른 창의 설정 화면 「워크스페이스」 구역도 이 신호를 듣고 다시 그린다. 끄는 중인 구역은 놓을 때까지 다시 그리지 않는다 **(설계자 판단)**.
- 고르개를 **펼칠 때마다** 목록을 다시 읽을지는 빌더 판단이다(동기화로 들어온 변경을 빨리 보이게 하려면). 펼친 목록이 깜빡이면 안 된다.

## 설정 화면 「워크스페이스」 구역

- **자리:** 구역 목록에서 「일반」 바로 아래. 순서: 일반 · 워크스페이스 · 편집기 · 모양 · 단축키 · 확장 **(설계자 판단)**. `SettingsSection` 에 `"workspaces"` 를 더한다.
- **맨 위 설명:** 「끌어서 순서를 바꿉니다. 고르개와 ⌃1~⌃9 가 이 순서를 따릅니다. 숨긴 워크스페이스는 고르개에 보이지 않습니다.」
- **행 하나:** 왼쪽부터 끄는 손잡이(⋮⋮) · 이름 · 단축키(⌃1~⌃9, 흐린 글씨, 숨겼거나 10번째 이후면 비움) · 「숨김」 체크박스.
  - 숨긴 행은 이름을 흐리게(`--muted`) 그린다.
  - 단축키는 **숨기지 않은 것만 세어** 매긴다. 끌거나 숨김을 바꾸면 곧바로 다시 매긴다 **(설계자 판단: 결과가 바로 보인다)**.
  - 지금 창의 워크스페이스, 다른 창이 보고 있는 워크스페이스를 따로 표시하지 않는다 **(설계자 판단)**.
- **끌기:** 행 어디를 잡아도 끌린다(손잡이는 표시일 뿐). 끄는 동안 놓일 자리에 가로줄을 보이고, 놓으면 저장한다. 목록 밖에서 놓거나 Esc 를 누르면 원래대로 돌아간다. 체크박스를 누르는 것은 끌기로 치지 않는다.
- 루트 아래 워크스페이스가 없으면 「워크스페이스 루트에 워크스페이스가 없습니다.」 를 보인다.
- 사라진 워크스페이스(`missing`)는 보이지 않는다.

## 고르개

- 목록 순서는 순서 파일 순서, 숨긴 것은 빠진다. **지금 창의 워크스페이스도 숨겼으면 빠진다**(사용자 확인). 이때 닫힌 고르개 버튼은 여전히 지금 워크스페이스 이름을 보인다. 지금 `WorkspaceSwitcher.render` 는 버튼 이름을 목록의 `current` 항목에서 가져오므로, 지금 이름을 목록과 따로 넘겨야 한다. 펼쳤을 때 처음 강조되는 행은 첫 행이다 **(설계자 판단)**.
- ⌃1~⌃9 는 **펼친 목록(숨김이 빠진 목록)** 의 1~9번째를 고른다. 고르개가 닫혀 있어도 같다.
- **단축키 안내:** 워크스페이스 행마다 맨 오른쪽에 「⌃1」~「⌃9」 를 흐린 글씨(`--muted`, 12px, `tabular-nums`)로 보인다. 다른 창 점(●)이 있으면 점 **다음**(더 오른쪽)이다. 10번째부터는 비운다. 「새 워크스페이스…」·「워크스페이스 열기…」 에는 붙이지 않는다.
  - 표기는 macOS 기호(⌃)와 숫자다. 고정 단축키라 표에서 읽지 않고 그대로 쓴다.
  - 화면 읽기용으로 행의 이름을 「회사, Control 1」 처럼 읽히게 할지(예: `aria-keyshortcuts="Control+1"`)는 빌더 판단.
- 「새 워크스페이스…」 로 만든 워크스페이스는 순서 파일에 없으므로 목록 맨 끝에 나타난다.

## 빌더에게 남긴 것

- 순서 파일 이름과 JSON 필드 이름(위 값은 제안).
- 끌기 구현(HTML5 drag and drop 또는 포인터 이벤트). WKWebView 에서 안정적인 쪽을 고른다. 탭 끌기(`free-splits-and-tab-drag` 설계)가 포인터 이벤트를 쓴다면 그 방식을 따른다.
- 키보드로 순서 바꾸기(⌥↑·⌥↓ 등) — 넣는다면 설정 화면의 다른 키 처리와 겹치지 않게.
- `list_workspaces` 를 나눌지, 정렬을 어디서 할지.
- 이미 없는 id 를 저장할 때 걸러낼지.

## 확인

- Rust 단위 테스트: 순서 파일 없음·깨짐·모르는 version·필드 하나 틀림, `order` 에 없는 워크스페이스는 끝에 이름순, 이름을 바꾼 워크스페이스가 자리를 지킴, 숨김 플래그.
- 프론트 단위 테스트(`workspace-switcher.test.ts`): 숨김이 빠지고 ⌃ 번호가 당겨짐, 10번째부터 단축키 없음, 단축키 표시가 `switcherShortcut` 이 고르는 행과 같음.
- e2e(`tests/e2e/`): 설정에서 끌어 순서를 바꾸면 고르개 순서와 ⌃1 이 가는 곳이 바뀜, 숨기면 고르개에서 빠짐, 다른 창의 고르개도 따라감.
- 실기기 스모크(WKWebView): 설정 구역에서 끌기, 체크박스 클릭이 끌기로 새지 않음.
