# tote-note 코어 설계

## 목적과 성공 기준

tote-note 는 아무 때나 막 적고, 앱을 닫아도 그대로 남는 가벼운 메모 앱이다. Zed 의 편집 감각(멀티커서, 신택스 하이라이트)은 가져오고, 코드 도구(터미널, git, 폴더 열기와 파일 트리, LSP 수준 편집)는 뺀다.

성공 기준:

- **언제 꺼도 다시 켜면 그대로다.** 강제 종료를 포함한다. 최악의 입력 손실은 「성능」 절의 저장 간격을 넘지 않는다.
- **가볍고 빠르다.** 목표치는 「성능」 절.
- **테마, 문법, 다른 형식 뷰어를 확장으로 바꿔 끼울 수 있다.**

## 범위

tote-note 는 서브프로젝트 셋으로 나뉜다. 이 문서는 **코어**만 다룬다. 나머지 둘은 각자의 스펙을 갖는다.

| 서브프로젝트   | 내용                                                                                                                             |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 코어 (이 문서) | 워크스페이스, 세션 유지, 편집기, 노트 기능, 백업, `tote` CLI, 확장 로더, 번들 확장(기본 테마·언어·마크다운 미리보기·미디어 뷰어) |
| 마켓플레이스   | 확장 검색·설치·업데이트·무결성 검증                                                                                              |
| 동기화         | 선택 기능. docker 로 띄우는 원격 워크스페이스에 연결한다                                                                         |

코어는 동기화 없이 완전히 동작해야 한다. 코어가 동기화와 마켓플레이스를 위해 미리 지키는 것은 「동기화 대비」·「확장 구조」 절에 있다.

**1차에 넣지 않는 것:** ⌘P 빠른 열기, 명령 팔레트, 위아래 분할, 나란히 미리보기, 같은 메모를 두 칸·두 창에 여는 것, 이미 열린 다른 창으로 탭 옮기기, 실행 취소 기록 영구 보존, `tote --wait`, UTF-8 외 인코딩 편집, 마크다운 미리보기의 원격 이미지 표시, 확장의 코드 실행, 사용자 설치 확장의 뷰어(「뷰어」 절).

## 플랫폼과 스택

- **플랫폼:** macOS 먼저. Windows·Linux 로 넓힐 수 있게 OS 의존 코드(경로, 하드링크, CLI 설치, 앱 데이터 위치)는 백엔드 모듈 경계 안에 가둔다.
- **앱 셸:** Tauri 2. 프론트엔드는 TypeScript, 백엔드는 Rust.
- **편집기:** CodeMirror 6.
- **하이라이트:** TextMate 문법 엔진(Shiki 계열). 정규식 엔진은 Oniguruma(WASM)를 쓴다 — 10MB 코드 전체 토큰화가 JavaScript 정규식 엔진보다 1.9–2.9배 빨랐다(두 실행, 스파이크 보고서 「편집 성능」 절). 테마는 VS Code 테마 형식.
- **툴체인:** 저장소에 이미 있는 Node·pnpm·oxc·lefthook 위에 Rust 툴체인을 더한다.

## 전체 구조

창은 워크스페이스 하나를 보인다. 같은 워크스페이스로 창을 여럿 열 수 있고, 그 창들은 메모 목록·색인·감시·백업을 함께 쓴다 — 한 창에서 메모를 만들거나 이름을 바꾸면 다른 창의 목록도 바로 바뀌고, 백업은 창 수와 관계없이 워크스페이스마다 한 번 찍는다. 여러 워크스페이스는 각각 창으로 동시에 열 수 있다.

창 배치: 사이드바(맨 위에 워크스페이스 고르개, 그 아래 메모 목록 ↔ 검색 패널 전환), 칸들(가로·세로로 나눈 나눔 나무, 칸마다 탭 바와 편집 영역), 상태 표시줄(창에 하나. 포커스 칸의 활성 탭의 언어, 줄·열, 저장 상태).

메뉴와 단축키는 포커스된 창에 간다.

### 칸

- **배치:** 칸은 **나눔 나무**다. 잎은 칸이고 가지는 방향(가로로 늘어놓기 `row` / 세로로 쌓기 `column`)과 자식들의 몫(합이 1)을 갖는다. 같은 방향으로 거듭 나누면 새 가지를 만들지 않고 그 가지에 자식을 더한다.
- **만들기:** 나누는 방향은 왼쪽·오른쪽·위·아래 넷이다. ⌘\ 는 지금 탭을 오른쪽에 새로 만든 칸으로, ⇧⌘\ 는 아래에 새로 만든 칸으로 옮긴다(같은 파일을 복제하지 않는다 — 아래 「한 메모는 한 자리에」). 탭 오른쪽 클릭 메뉴에는 네 방향이 모두 있다. 칸에 탭이 하나뿐이면 그쪽에 빈 칸을 만들고 포커스를 옮긴다. 탭을 칸의 가장자리(변에서 너비·높이의 1/4 안)로 끌어 놓아도 그쪽에 새 칸이 생긴다. 끄는 동안 놓을 자리를 반투명 마스크로 보인다.
- **옮기기:** 탭을 포인터로 끌어 다른 칸의 탭 바나 가운데에 놓으면 그 칸으로 옮긴다. 옮기기만으로는 저장하지 않는다 — 같은 탭 상태가 그대로 옮겨 간다. 탭을 모두 끌어 낸 칸은 닫힌다(창에 칸이 하나뿐이면 남는다).
- **닫기:** ⌘W 로 칸의 마지막 탭을 닫으면 칸은 빈 칸으로 남고, 빈 칸에는 「새 메모를 만드세요」 안내와 「새 메모」 버튼, 「메모 목록에서 메모를 열거나 ⌘N 을 누르세요」 한 줄이 보인다. 빈 칸에서 ⌘W 를 누르면 칸이 닫히고(칸이 하나뿐이면 창을 닫는다) 그 몫은 같은 가지의 이웃(앞쪽, 맨 앞이면 뒤쪽)에게 간다. 자식이 하나만 남은 가지는 없어지고 그 자식이 부모 자리에 들어간다. 창에는 칸이 항상 하나 이상 있다. 탭 바의 마지막 탭 오른쪽 빈자리를 더블클릭하면 그 칸에 새 메모가 마지막 탭으로 열린다.
- **크기:** 칸 사이 경계(가로·세로)를 끌어 비율을 바꾼다. 한 칸의 최소 크기는 너비 **320px**, 높이 **160px**. 새 칸이 이 크기를 지킬 수 없으면 나누기와 끌어 놓기는 그쪽으로 나누지 않고(끌어 놓기는 가운데 놓기로 친다), 메뉴·단축키는 아무것도 하지 않고 상태 표시줄에 「창이 좁아 나눌 수 없습니다」를 띄운다.
- **포커스:** 클릭한 칸이 포커스 칸이다. ⌥⌘← / ⌥⌘→ / ⌥⌘↑ / ⌥⌘↓ 로 그쪽에 있는 칸으로 옮긴다(그쪽에 칸이 없으면 아무 일도 없다). 사이드바에서 메모를 열면 포커스 칸에 열린다. 칸 포커스를 옮기기 전에 한글 조합을 확정한다. 제목 자동 생성의 「탭이 포커스를 잃을 때」는 칸 포커스가 옮겨 갈 때도 해당한다.
- **칸마다 따로인 것:** 탭 목록, 활성 탭, 편집 ↔ 미리보기 모드, 충돌·삭제 배너. 탭 순환(⇧⌘] / ⇧⌘[)은 포커스 칸 안에서만 돈다. 칸이 여럿이어도 보이는 칸의 문서만 하이라이트한다.

### 한 메모는 한 자리에

메모와 외부 파일은 **모든 창을 통틀어 한 자리(한 창의 한 칸)에만** 탭으로 열린다. 이미 열린 것을 다른 칸이나 다른 창에서 열려고 하면 열린 자리로 간다(그 창을 앞으로 가져오고 그 칸·탭을 활성화한다). 외부 파일·`tote -w`·세션 되살리기도 같다.

- 외부 파일은 워크스페이스가 달라도 한 자리다. 저장 전 수정분 보관(`buffers/`)이 경로마다 하나라서, 두 창에 같은 파일이 열리면 보관분이 서로 덮인다.
- 세션을 되살리다가 이미 다른 자리에 열린 탭을 만나면 되살리는 쪽에서 그 탭을 뺀다. 먼저 열린 자리가 이긴다.
- **이유:** 같은 메모를 두 자리에서 고치려면 편집기 상태 둘을 실시간으로 맞춰야 한다. 이 앱은 여러 커서에 한글을 넣는 입력 처리를 직접 하고 있어(`src/editor/ime.ts`) 두 상태를 맞추는 층이 그 처리와 부딪힐 위험이 크고, 두 창이 같은 파일을 따로 쓰면 한쪽 글이 조용히 덮인다. 긴 메모의 두 곳을 나란히 보는 쓰임은 이 규칙으로는 못 한다.

### 새 창

- **같은 워크스페이스로 새 창:** 파일 › 「새 창」(⌥⌘N). 포커스된 창과 같은 워크스페이스로 빈 칸 하나짜리 창을 원래 창에서 오른쪽·아래 24px 로 열되, 그쪽으로 모니터의 작업 영역(메뉴 막대·Dock 을 뺀 영역)을 넘치는 축은 왼쪽·위로 24px 옮긴다. 창은 작업 영역 안에 다 들어가게 놓고, 작업 영역보다 크면 줄인다. 되살리는 창도 같다. 저장된 자리의 모니터가 없으면 기본 크기로 가운데에 연다.
- **탭 떼어 내기:** 창 › 「탭을 새 창으로 옮기기」, 탭 오른쪽 클릭 메뉴, 탭을 창 밖으로 끌어 놓기 셋으로 한다. 끌어 놓은 자리가 tote 창이 아닌 곳이면 그 자리에 새 창이 열린다(왼쪽 위 모서리가 놓은 자리, 크기는 원래 창과 같고, 자리는 위 「새 창」 규칙으로 작업 영역 안에 들인다). 그 자리의 맨 앞 창이 같은 워크스페이스를 보이고 있으면 탭은 그 창의 포인터 아래 칸의 마지막 탭으로 옮겨지고 그 창이 앞으로 온다. 맨 앞 창이 다른 워크스페이스를 보이고 있거나 떠나는 중(닫기·전환)이면 새 창으로 떼어진다. 다른 창 위에서는 놓을 자리 마스크를 보이지 않는다. 창 밖에서 Esc 를 누르거나 포인터를 원래 탭 바로 되가져와 놓으면 취소된다.
- **옮길 때 글을 잃지 않는다.** 메모는 옮기기 전에 즉시 저장한다. 외부 파일의 저장 전 수정분은 즉시 보관한 뒤 새 창이 그 보관분으로 연다. 조합 중인 글자는 옮기기 전에 확정되고 실행 취소 기록은 옮겨지지 않는다. 떼어 내는 동안 그 탭의 내용은 보이지 않고 입력을 받지 않는다. **저장되지 않은 글이 남았거나(저장 실패), 충돌·삭제 배너가 떠 있는 탭은 떼어 내지 않고** 상태 표시줄에 알린다.
- **창 제목**은 워크스페이스 이름이다. 같은 워크스페이스의 창이 둘 이상이면 뒤에 ` — 2`, ` — 3` 을 붙인다.

### 워크스페이스 고르개

- **자리:** 모든 창의 사이드바 맨 위, 메모 목록의 제목 필터 바로 위에 콤보박스(직접 그린 목록) 하나. 사이드바가 검색 패널일 때도 맨 위에 남는다. 닫혀 있을 때는 지금 창의 워크스페이스 이름과 펼침 표시(▾)를 보인다.
- **항목:** 워크스페이스 루트의 워크스페이스 전부(「워크스페이스 열기…」 목록과 같은 것), **이름 순**. 순서가 바뀌지 않아야 단축키가 고정된다. 지금 창의 워크스페이스에는 체크를 붙이고, 다른 창에도 열려 있는 워크스페이스에는 작은 점을 찍는다. 찾을 수 없는 워크스페이스는 보이지 않는다.
- **구분선 아래 명령:** 「새 워크스페이스…」(이름을 받아 만든 뒤 **지금 창**이 그 워크스페이스로 바뀐다)와 「워크스페이스 열기…」(메뉴의 같은 이름과 같다).
- **키보드:** 펼친 동안 ↑↓ 로 고르고 Enter 로 정하고 Esc 로 닫는다. 고르개가 포커스를 잃으면 닫힌다. 창이 비활성화될 때(다른 앱이 앞으로 올 때)도 닫히고, 키는 목록을 열기 전 자리로 돌아가 창이 돌아오면 그리로 간다. WKWebView 는 이때 목록에 포커스를 둔 채 `focusout` 없이 창 `blur` 만 내므로 창 `blur` 로도 닫는다. **단축키** ⌃1 – ⌃9 는 목록의 1–9번째로 바로 전환한다. 대화상자가 열려 있거나 창이 떠나는 중이면 ⌃1–⌃9 는 아무것도 하지 않는다.
- **고르면:**
  - 고르거나 ⌃1–⌃9 를 누르면 조합 중인 글자는 그 메모에 먼저 확정된다. 고르개를 눌러도 편집기의 포커스는 옮겨 가지 않는다.
  - 떠나는 중에는 항목이든 명령이든, 메뉴 「새 워크스페이스…」 를 골라도 아무것도 하지 않는다.
  - 그 워크스페이스가 다른 창에 열려 있으면 그 창을 앞으로 가져온다. 지금 창은 그대로다.
  - 아니면 **지금 창이 그 워크스페이스로 바뀐다.** 모든 탭을 저장하고(창을 닫을 때와 같은 쓰고 닫기) 배치를 세션에 남긴 뒤 대상 워크스페이스의 세션을 이 창에 되살린다. 창의 위치·크기는 그대로다. 구현은 웹뷰를 언제나 새로 고친다. 창이 탭을 다 쓰면 답하기 전에 칸이 비워져 입력을 받지 않고, 대상 워크스페이스로 넘어간 때부터 새 페이지가 뜰 때까지 그 창의 쓰기는 거절된다. 전환이 거둬지면(취소, 대상을 열지 못함, 다른 창이 이미 보임) 칸이 돌아온다. 쓰기가 시간 제한을 넘겨 늦게 끝난 경우에도 창이 떠나지 않으면 칸이 돌아온다. 칸이 돌아올 때 포커스는 떠나기 전 자리(편집기, 검색 입력, 제목 필터 칸 등)가 아직 보이면 그리로, 아니면 포커스된 칸으로 돌아간다.
  - 저장 실패가 남아 있으면 창 닫기와 같은 질문(「저장하지 못한 메모가 있습니다」 / 그래도 바꾸기 / 취소)을 한다.
- **메뉴 「워크스페이스 열기…」** 와의 차이: 고르개는 지금 창을 바꾸고, 메뉴는 고른 워크스페이스를 새 창으로 연다(이미 열려 있으면 그 창을 앞으로).

### 프론트엔드 (TS, WebView)

화면 전부와 **편집 중인 텍스트의 원본**을 갖는다. 탭, 메모 목록, 검색 패널, CodeMirror 6 편집기, 뷰어 호스트(「확장 구조」 절), 설정 화면.

설정 화면은 모달 하나에 구역 다섯으로 나눈다. 왼쪽 탭에서 한 번에 한 구역만 본다(설계: `docs/superpowers/specs/2026-10-20-tote-notes-settings-and-shortcuts-design.md`).

- **일반**: 워크스페이스 루트.
- **편집기**: 줄번호, 글꼴 크기, 글꼴.
- **모양**: 라이트·다크 테마 선택.
- **단축키**: 앱 명령의 단축키 바꾸기·지우기·되돌리기(편집기 안 키는 바꾸지 않고, 겹치면 경고만 한다).
- **확장**: 목록(설치·활성·제거).

### 백엔드 (Rust)

디스크와 OS 를 다루는 일 전부.

| 모듈         | 하는 일                                                          |
| ------------ | ---------------------------------------------------------------- |
| `workspace`  | 워크스페이스 생성·열기, 메모 ID ↔ 파일 이름 색인, 외부 변경 감시 |
| `persist`    | 메모 자동 저장, 외부 파일 ⌘S 저장, 원자적 쓰기                   |
| `session`    | 창·칸·탭·커서·스크롤, 외부 파일의 저장 전 수정분                 |
| `backup`     | 주기 스냅샷, 보존 정책, 이전 버전 조회                           |
| `search`     | 워크스페이스 전체 텍스트 검색                                    |
| `extensions` | 확장 설치·검증·레지스트리                                        |
| `files`      | 파일 토큰 URL 발급·회수와 Range 응답(뷰어·대용량 텍스트 뷰어)    |
| `cli`        | `tote` 인자 수신(single-instance)과 라우팅                       |

**원자적 쓰기:** 항상 같은 폴더의 임시 파일에 쓴 뒤 rename 한다. 쓰는 도중 앱이 죽어도 파일이 반쯤 깨지지 않는다. 파일을 제자리 수정하지 않는다(「백업」 절의 하드링크가 이 성질에 기댄다).

**IPC:** 파일 내용은 JSON 문자열이 아니라 Tauri 2 바이너리 IPC 로 주고받는다.

## 워크스페이스와 데이터 모델

```
~/Tote/                          워크스페이스 루트 (설정에서 변경 가능)
  업무 메모/                     워크스페이스 하나 = 폴더 하나, 이름 = 폴더 이름
    회의 준비.md                 메모는 루트에 평평하게
    deploy.sh                    가져온 외부 파일도 여기로 복사
    .tote/
      workspace.json             워크스페이스 ID·설정 (이름은 폴더 이름이라 두지 않는다)
      index.json                 메모 ID → 파일 이름, 자동 제목 여부, 언어 지정
      sessions/<기기 ID>.json    그 기기의 창들·칸·탭·커서·스크롤

~/Library/Application Support/tote/   이 기기 전용, 워크스페이스 밖
  machine.json                   기기 ID(최초 실행 때 UUID 생성)·기기 이름(호스트명)
  settings.json                  워크스페이스 루트, 테마, 확장 활성 상태, 편집기 설정(`editor`: 줄번호·글꼴 크기·글꼴), 기본값과 다른 단축키(`shortcuts`)
  state.json                     마지막에 열려 있던 창 목록
  buffers/                       외부 파일의 저장 전 수정분
  backups/<워크스페이스 ID>/     스냅샷
  extensions/<id>@<버전>/        사용자가 설치한 확장
```

### 워크스페이스

- **tote 가 만든 폴더만 연다.** `.tote/workspace.json` 이 있는 폴더가 워크스페이스다. 아무 폴더나 열면 파일 트리가 다시 생기기 때문이다.
- 새 워크스페이스는 이름을 받아 루트 아래에 폴더와 `.tote/` 를 만든다.
- **평평하다.** 메모 목록과 검색은 워크스페이스 루트의 파일만 본다. 하위 폴더와 점(`.`)으로 시작하는 파일은 무시한다.

### 메모 ID 와 색인

- 메모는 경로가 아니라 **ID(UUID)** 로 식별한다. 제목 자동 생성이 파일 이름을 바꾸고, 동기화는 이름이 바뀐 파일을 같은 메모로 알아봐야 하기 때문이다.
- ID 는 `index.json` 에 둔다. 파일 안(frontmatter)에 넣으면 `.sh` 같은 파일을 더럽힌다.
- `index.json` 항목: `file`(파일 이름), `autoTitle`(제목 자동 생성 대상인가), `language`(사용자가 지정한 언어, 없으면 생략).
- 감시기가 rename 을 잡으면 대응표를 고친다. **rename 을 놓치면 새 메모로 취급**되고, 그 메모의 탭 위치 정보만 사라진다.
- 다른 앱이 워크스페이스 루트에 넣은 파일은 새 ID 를 받고 `autoTitle: false` 다.

### 제목 자동 생성

- 대상은 `autoTitle: true` 인 메모다. tote 안에서 새로 만든 메모가 여기에 해당한다. 사용자가 이름을 직접 바꾸면 `false` 가 된다. 가져온 파일은 처음부터 `false` 다.
- 첫 번째 비어 있지 않은 줄에서 앞쪽 `#` 와 공백을 걷고(**문서의 첫 줄이 `#!` 로 시작하면 그 줄은 건너뛰고 다음 줄부터 찾는다** — 스크립트 메모가 `! bin sh` 같은 제목을 받지 않게 한다), 파일 이름에 쓸 수 없는 문자(`/ \ : * ? " < > |`, 제어 문자)를 공백으로 바꿔 연속 공백을 하나로 줄인다. 앞쪽 `.` 은 걷는다(숨김 파일 방지). **60자**에서 자른다.
- 결과가 비면 `untitled` 다. 확장자는 그대로 둔다.
- 이름이 겹치면 ` 2`, ` 3` … 을 붙인다.
- **타이핑할 때마다 바꾸지 않는다.** 커서가 첫 줄을 벗어날 때, 탭이 포커스를 잃을 때, 탭을 닫거나 앱을 끌 때 바꾼다.

### 탭 종류

| 종류                  | 가리키는 것                   | 저장              |
| --------------------- | ----------------------------- | ----------------- |
| 메모                  | 메모 ID                       | 자동 저장         |
| 외부 파일             | 이 기기의 절대 경로 + 기기 ID | ⌘S 로만           |
| 다른 기기의 외부 파일 | 그 기기의 경로 + 기기 ID      | 내용 없음, 경로만 |

세 번째 종류는 동기화가 붙어야 실제로 생긴다. 코어는 세션 형식에서 외부 파일 항목에 기기 ID 를 항상 기록하고, 표시 UI 는 동기화 스펙이 정한다.

### 가져오기

외부 파일 탭에서 「워크스페이스로 가져오기」를 하면 파일을 워크스페이스 루트로 **복사**한다(이름이 겹치면 ` 2`). 탭은 메모 탭으로 바뀌고, 원본 파일은 건드리지 않는다. 그 탭에 저장 전 수정분이 있으면 수정분을 포함한 내용을 복사한다.

## 세션 유지·저장·백업

### 세션

- **세션 파일은 워크스페이스·기기마다 하나이고 창 여럿을 담는다.** 창마다: 위치·크기, 칸 배치(나눔 나무: 잎은 칸의 탭 순서·활성 탭, 가지는 방향과 자식들의 몫), 포커스 칸(잎의 깊이 우선 순서 번호). 탭마다: 커서(멀티커서의 모든 선택), 스크롤, 편집·미리보기 모드. 옛 형식(창 하나·탭 목록 하나)은 칸 하나짜리 창 하나로, 옛 좌우 칸 배열(`panes`)은 `row` 가지 하나로 읽는다. 몫이 깨진 배치는 바로잡고, 읽을 수 없는 가지의 탭은 한 칸에 모은다 — 탭을 버리지 않는다.
- **앱을 끌 때** 열려 있던 창 전부(창마다 워크스페이스와 배치)를 다음 실행 때 다시 연다(`state.json`). 같은 워크스페이스가 여러 번 나올 수 있다.
- **워크스페이스를 열 때** 세션에 남은 창 배치 중 첫 번째를 그 창에 되살린다. 고르개로 바꿔 들어올 때도 같다.
- 같은 워크스페이스의 창들이 한 파일을 쓰므로 창마다 따로 쓰면 서로 덮는다. 백엔드가 창들의 배치를 모아 한 파일로 쓴다.
- 세션 파일은 변화가 멈추고 **1초** 뒤에 쓴다. 창을 닫거나 앱을 끌 때는 즉시 쓴다(이유는 「저장」 절의 즉시 저장과 같다).
- **지연 로딩:** 복원할 때 활성 탭의 내용만 읽는다. 나머지 탭은 처음 활성화될 때 읽는다.
- **창을 닫을 때:** 그 워크스페이스의 창이 아직 남아 있으면 닫은 창의 배치는 버린다(탭을 닫은 것과 같다). 마지막 창이면 세션에 남겨 다음에 그 워크스페이스를 열 때 복원한다. 고르개로 워크스페이스를 떠날 때도 같다. 그래서 세션에 남는 배치는 언제나 「지금 열린 창들의 배치」이거나, 열린 창이 없을 때 「마지막으로 닫힌 창 하나의 배치」다. 늘어나기만 하는 목록은 생기지 않는다.
- **비어 있는 새 메모의 탭을 닫으면 파일도 지운다.**
- **저장 전 수정분이 있는 외부 파일의 탭을 닫을 때만 묻는다** — 저장 / 버리기 / 취소. 앱을 끌 때는 묻지 않고 수정분을 보관한다.

### 저장

- **메모:** 타이핑이 멈추면 자동 저장한다. 간격은 「성능」 절의 크기별 값을 따른다. 탭이 포커스를 잃거나 앱을 끌 때는 즉시 저장한다. 가려진 창에서는 macOS 가 WebView 프로세스를 거의 멈춰 프론트엔드의 저장 타이머(0.5초·1초·3초)도 멈추거나 크게 늦어진다. 즉시 쓰기가 손실 상한을 지키는 장치이므로 빼지 않는다.
- **외부 파일:** ⌘S 로만 쓴다. 저장 전 수정분은 변화가 멈추고 **1초** 뒤에 `buffers/` 에 보관한다. 보관 항목은 경로, 편집을 시작할 때의 디스크 내용 해시, 수정된 내용이다. 저장하거나 버리면 지운다.
- **인코딩과 줄바꿈:** UTF-8 만 편집한다(BOM 은 유지). UTF-8 로 읽을 수 없는 파일은 「텍스트로 열 수 없음」을 표시한다. 줄바꿈 형식(LF/CRLF)은 파일의 것을 유지한다. CR 만 쓰는 옛 Mac 형식은 LF 로 저장한다.

### 외부 변경

- **자기 쓰기 걸러내기:** 백엔드는 경로마다 마지막으로 쓴 내용의 해시를 기억하고, 그 해시와 같은 변경 이벤트는 무시한다.
- **다른 앱이 열린 메모를 고쳤을 때:** 아직 쓰지 않은 내용이 없으면 커서를 유지한 채 조용히 다시 읽는다. 있으면 충돌 배너로 「디스크 버전 / 내 버전」을 고르게 한다.
  - **충돌을 고르지 않은 채 창을 닫거나 앱을 끄면** 다른 앱의 버전은 원래 메모에 두고 내 버전을 새 메모로 저장한다. 새 메모의 탭에 그 사실과 원래 메모 이름을 담은 배너를 띄우고, 사람이 닫을 때까지 다시 켜도 세션에 실어 남긴다. 탭을 닫으면 배너도 끝난다. 그 탭에 다른 배너가 오르면, 그 배너가 끝난 뒤 다시 보인다.
- **외부 파일의 수정분을 복원할 때 디스크 내용 해시가 보관 당시와 다르면** 같은 충돌 배너를 띄운다.
- **열린 파일이 지워졌을 때:** 「삭제됨」 배너를 띄우고 내용은 편집기에 남긴다. 다시 저장하거나 닫을 수 있다.

### 백업

- **바뀐 것이 있을 때만 10분마다** 스냅샷을 만든다. **워크스페이스를 열 때(앱 시작의 복원 포함) 한 번 찍는다** — 닫기 전 마지막 10분 안의 변경이 어느 스냅샷에도 없을 수 있어, 열 때 그 상태를 남긴다. **직전 스냅샷과 파일 목록·내용이 모두 같으면(`.tote/index.json` 포함) 만들지 않는다.** 위치는 `backups/<워크스페이스 ID>/<YYYYMMDD-HHMMSS>/`.
- 스냅샷은 Finder 로 그대로 열어 볼 수 있는 완전한 폴더다. 워크스페이스 루트의 텍스트 파일과 `.tote/index.json` 을 담는다. **바이너리 파일(앞 8KB 에 NUL 바이트가 있는 파일)은 제외한다** — 미디어와 문서가 여기에 해당한다. 세션 파일도 제외한다.
- **하드링크:** 직전 스냅샷과 내용이 같은 파일은 **직전 스냅샷의 사본에** 하드링크한다. ⚠ 워크스페이스 파일 자체에는 하드링크하지 않는다. 다른 앱이 워크스페이스 파일을 제자리 수정하면 링크된 백업까지 함께 바뀌기 때문이다. 첫 사본은 항상 복사(가능하면 APFS clone)로 만든다.
- **보존:** 24시간 안의 스냅샷은 전부 남긴다. 그보다 오래된 것은 하루에 마지막 하나만 30일까지 남긴다. 30일이 지난 것은 지운다. 정리는 스냅샷을 만들 때마다 돈다.
- **복원:** 「백업 폴더 열기」, 그리고 메모 하나의 「이전 버전」 목록. 이전 버전은 메모 ID 로 스냅샷을 거슬러 찾고(이름이 바뀌어도 `index.json` 으로 추적), 인접 스냅샷과 내용이 다른 시점만 보이고, **같은 내용이 이어진 구간은 처음과 끝 시각으로 보인다**(같은 날이면 `2026-10-12 07:50:00 – 08:30:00`). 미리 보고 「이 버전으로 되돌리기」를 하면 편집기 내용을 바꾼다. 이 동작은 ⌘Z 로 되돌릴 수 있다.

## 편집기와 노트 기능

### 편집기

- **멀티커서:** ⌥클릭 커서 추가, ⌘D 다음 같은 단어 선택, ⌥드래그 사각 선택. 키맵은 Zed 와 비슷하게 맞춘다. 세부 단축키는 구현 계획에서 확정한다.
  - **커서 여럿·선택 여럿에서 한글을 치면 모든 커서·선택에 같은 글자가 들어간다** — 영문 입력·Zed 와 같다. 조합 중의 미리보기(밑줄 글자)는 주 선택 한 자리에만 보이고, 조합이 확정되면 모든 자리에 같은 글자가 들어가며 다른 자리에 자모가 남지 않는다. 조합 중 Esc·포커스 이동은 macOS 입력기가 확정으로 처리하므로 그때까지의 글자가 모든 자리에 같게 들어간다. 입력기가 조합 글자를 지우는 취소면 아무 자리에도 남기지 않는다.
  - 조합으로 친 글을 ⌘Z 하면 조합 전의 커서·선택이 모두 돌아오고 음절 단위로 되돌린다.
  - 커서가 여럿일 때 스크롤·Esc·상태 표시줄의 기준은 맨 앞 커서다(아래 규칙의 결과).
  - ⚠ WKWebView 의 입력기는 주 선택 한 곳에만 글자를 넣고(스파이크 보고서 「한글 입력」 절), 캐럿을 편집 영역 시작으로부터의 오프셋으로 추적하는 것으로 보인다(관찰 둘에서 추론 — 캐럿 앞 줄에 글자가 들어가면 음절을 새로 시작했고, 뒤 줄에만 들어가면 이어 썼다). 그래서 **범위가 여럿이면 주 선택은 항상 맨 앞 범위다** — 나머지 자리에 넣은 글자가 캐럿 앞에 들어가면 입력기가 음절을 새로 시작해 `가` 대신 `ㄱㅏ` 가 된다. 입력기가 글자를 넣는 두 경로(조합 이벤트 없이 바로 넣는 경로와 조합 경로)와 각 경로에서 나머지 자리에 넣는 방식은 `src/editor/ime.ts` 머리 주석.
- **언어는 확장자로 정한다.** 새 메모는 `.md` 로 시작한다.
- **언어 바꾸기:** 상태 표시줄에서 고른다. 메모면 확장자를 바꾸고(파일 rename) `index.json` 에 `language` 를 기록한다. 외부 파일이면 표시만 바뀌고 세션에 기록한다.
- **자동 인식은 확실한 경우만 한다.** 대상은 `.md` 이면서 `language` 가 없고, 사람이 이름을 바꾸지 않은(`autoTitle: true`) 메모다 — 사람이 정한 이름을 인식이 되돌리지 않게 한다. 첫 줄이 언어 기여의 `firstLine` 패턴(shebang 등, 대소문자를 무시한다)에 맞거나, 내용 전체가 `{` 나 `[` 로 시작하는 유효한 JSON 이면 그 언어로 바꾼다. **`.md` 에서 다른 언어로 올라가기만 하고 저절로 되돌아가지 않는다.** 그 밖의 추측은 하지 않는다.
- **마크다운 편집 보조:** 목록 이어 쓰기 같은 편집 보조는 앱에 번들된 `@codemirror/lang-markdown` 의 파서와 키맵이 맡는다. 색은 TextMate 하이라이트가 칠한다(이 팩의 하이라이트 스타일은 쓰지 않는다).
- **주석 토글(⌘/), 괄호 자동 닫기, 단어 경계**는 언어 기여의 `language-configuration.json` 을 따른다.

### 메모 목록

사이드바에 워크스페이스 루트의 파일을 **최근 수정순으로 평평하게** 보인다. 미디어 등 텍스트가 아닌 파일은 아이콘으로 구분한다. 위에 제목 필터 칸(대소문자 무시, 부분 일치)을 둔다. 누르면 탭으로 연다.

### 워크스페이스 검색

- 별도 패널. 대소문자 구분·정규식 토글.
- Rust 백엔드가 ripgrep 라이브러리로 **병렬 검색**하고 결과를 나오는 대로 보낸다. 새 검색어가 들어오면 이전 검색을 취소한다.
- 대상은 워크스페이스 루트의 **텍스트 메모**(확장자로 미디어·문서가 아닌 것). 그중 바이너리와 **5MB 를 넘는 파일**은 건너뛴다. 색인은 만들지 않는다.
- 결과는 메모별로 묶어 줄과 앞뒤 문맥을 보이고, 누르면 그 위치로 연다.

### 마크다운 미리보기

탭마다 편집 ↔ 미리보기를 전환한다(⇧⌘V 예정). 미리보기는 번들 미리보기 뷰어 확장이 그린다(「확장 구조」 절의 샌드박스). 전환하는 순간의 텍스트를 넘긴다. 상대 경로 이미지는 뷰어 API 로 토큰 URL 을 받아 표시한다. 원격 이미지는 네트워크 차단 때문에 표시하지 않는다.

## 확장 구조

### 허용 범위

확장은 **선언형 기여와 샌드박스 뷰어만** 담는다. 확장은 파일 시스템과 네트워크에 접근할 수 없고, 앱 명령(IPC)을 실행할 수 없다(격리 방식과 그 한계는 「뷰어」 절). 마켓에서 아무 확장이나 설치해도 메모가 밖으로 새지 않는 것이 이 범위의 목적이다.

### 패키지 형식

- 매니페스트는 VS Code `package.json` 형식을 따른다. ID 는 `publisher.name`.
- `contributes.languages`(id, extensions, filenames, firstLine, configuration), `contributes.grammars`(language, scopeName, path, embeddedLanguages), `contributes.themes`(label, uiTheme, path)를 읽는다.
- 뷰어는 최상위 `tote.viewers` 에 적는다: `id`, `kind`(`primary` | `preview`), `extensions`, `entry`(HTML 경로).
- **VS Code 확장(.vsix)을 그대로 설치할 수 있다.** `main`·`browser`·`activationEvents` 같은 코드 항목은 무시하고 선언형 부분만 쓴다.

### 설치와 로딩

- 위치는 둘: 앱 번들 안의 번들 확장(읽기 전용), `Application Support/tote/extensions/<id>@<버전>/`.
- 1차 설치 경로: 파일(.vsix, .zip)이나 폴더에서 수동 설치. 같은 ID 가 이미 있으면 확인 후 교체한다. 마켓플레이스는 이 설치기를 그대로 다시 쓴다(내려받기 → 검증 → 같은 설치기).
- 백엔드가 확장을 훑어 매니페스트를 검증하고 레지스트리(언어, 문법, 테마, 뷰어)를 만든다. 프론트엔드는 레지스트리를 받아 쓴다. 1차에는 사용자 설치 확장의 뷰어를 레지스트리에 넣지 않는다(「뷰어」 절의 격리).
- **문법은 그 언어의 파일을 처음 열 때만 불러온다.**
- 두 확장이 같은 파일 확장자를 주장하면 **사용자 설치가 번들보다 우선**이다. 설정에서 바꿀 수 있다.

### 테마

라이트 테마와 다크 테마를 따로 지정하고 OS 모양을 따른다. VS Code 테마의 `colors` 중 tote UI 에 대응하는 키만 CSS 변수로 옮기고, `tokenColors` 는 하이라이트에 쓴다. 뷰어에도 같은 CSS 변수를 넘긴다.

어느 슬롯에 어느 종류의 테마든 고를 수 있다(다크 슬롯에 Light+ 도 된다). 테마가 주지 않은 CSS 변수는 **슬롯(OS 모양)이 아니라 테마 종류**의 기본값에서 채운다. 종류는 매니페스트의 `uiTheme`(`vs`·`hc-light` 는 라이트, `vs-dark`·`hc-black` 은 다크), 없거나 모르는 값이면 테마 파일의 `type`(`light`·`hcLight`·`dark`·`hc`), 그것도 없으면 슬롯이다(`themeKind`, `src/theme/vscode-theme.ts`). 페이지의 `color-scheme`(스크롤 막대·폼 컨트롤)도 테마 종류를 따른다. 슬롯에서 시작하던 때는 번들 Light+(`editor.background`·`editor.foreground` 만 tote 변수에 닿는다)를 다크 슬롯에 두면 `--fg` 만 검게 바뀌어 띠 입력칸·사이드바 글자가 어두운 바탕 위에서 1.2:1 로 읽히지 않았다(검색 띠 스모크 A-4). 번들 테마 전부를 두 슬롯에 넣어 글자 대비가 4.5:1 이상인지 단위 시험(`src/theme/manager.test.ts`)이 본다. 뷰어 프레임의 `color-scheme` 은 아직 `light dark`(OS 모양)이다 — 뷰어는 변수만 받는다.

### 뷰어

- **주 뷰어**(`primary`)는 텍스트가 아닌 파일(이미지, PDF 등)을 연다. **미리보기 뷰어**(`preview`)는 텍스트 파일을 다르게 보여 준다(마크다운 등).
- **격리:** `sandbox="allow-scripts"` iframe(동일 출처 없음)에서 돈다. CSP 로 네트워크를 막는다. 뷰어 iframe 에는 `__TAURI_INTERNALS__` 가 없어 앱 명령을 부르는 API 가 없다. 단 WKWebView 의 네이티브 IPC 핸들러(`window.webkit.messageHandlers.ipc`)는 iframe 에도 열려 있어 메시지가 Tauri 까지 가고, 명령 실행을 막는 것은 Tauri 의 invoke key 검사 하나다.
  - **1차는 이 한 겹에 기댄다. 그래서 1차에는 번들 확장의 뷰어만 돈다** — 사용자가 설치한 확장은 테마·언어·문법 기여만 싣고 `tote.viewers` 는 싣지 않는다. 남이 만든 뷰어를 받기 전에(마켓플레이스보다 먼저) 뷰어를 IPC 핸들러가 없는 별도 webview 로 옮긴다. 유효한 키를 가진 프레임이 명령에 닿는지는 재지 않았다(스파이크 보고서 「검증하지 않은 것」 절).
- **파일 전달:** 백엔드 `files` 모듈이 **그 파일 하나만 가리키는 토큰 URL**(커스텀 URL 스킴)을 발급한다. 토큰은 파일 경로를 드러내지 않고, 받은 화면(뷰어·대용량 텍스트 뷰어)이 열려 있는 동안 몇 번이든 쓸 수 있으며, 그 화면을 닫을 때 회수한다. `resolveRelative` 로 받은 토큰도 같다. Range 요청을 지원한다(영상 탐색). 영상 탐색은 같은 URL 로 Range 요청을 수십 번 보내므로 첫 사용에 소모되는 토큰으로는 안 된다. 미리보기 뷰어는 텍스트를 메시지로 받는다.
- **뷰어 API (postMessage):** 호스트 → 뷰어 `init`(파일 이름·확장자·크기·토큰 URL 또는 텍스트·테마 변수). 뷰어 → 호스트 `ready`, `error`, `resolveRelative(경로)`. `resolveRelative` 는 **열린 파일과 같은 폴더 안의 파일만** 토큰 URL 로 돌려준다.
- 뷰어가 오류를 내거나 응답하지 않으면 「열 수 없음」과 함께 「텍스트로 열기」를 제공한다.

### 번들 확장 (1차)

1. 기본 테마 — 라이트, 다크.
2. 기본 언어 묶음 — VS Code 내장 문법에서 고른다: markdown, plaintext, shellscript, json/jsonc, yaml, toml, ini/dotenv, javascript, typescript, python, html, css, xml, sql, go, rust, java, c/cpp, diff, dockerfile, makefile. **문법마다 라이선스를 확인한다**(VS Code 저장소는 MIT 지만 문법 일부는 다른 출처의 라이선스를 따른다).
3. 마크다운 미리보기 뷰어.
4. 미디어 뷰어 — 이미지는 창 맞춤 ↔ 실제 크기 전환만, 영상·오디오는 WebView 기본 플레이어 컨트롤. 포맷은 macOS WebView 가 재생하는 것만(mp4, mov, mp3, m4a, wav 등). 재생할 수 없으면 「지원하지 않는 포맷」.

## 성능

Zed 의 속도 원리 중 로프 구조 문서와 뷰포트 렌더링은 CodeMirror 6 가 이미 갖는다. 코어가 직접 넣는 것은 아래다.

- **하이라이트를 입력 경로에서 뗀다.** TextMate 토큰화는 **Web Worker** 에서 돈다. 보이는 영역부터 처리하고, 줄마다 문법 상태를 캐시해 편집한 줄부터만 다시 계산한다. 타이핑은 토큰화를 기다리지 않는다. 줄 상태 캐시에 들어가는 토큰화에는 벽시계 기준의 줄당 시간 제한을 쓰지 않는다. Shiki 의 줄당 시간 제한은 벽시계라, 창이 가려져 WebView 가 스로틀되면 줄이 중간에서 잘리고, 그 줄의 문법 상태가 캐시에 남아 이후 줄 색이 틀릴 수 있다.
- **바이너리 IPC**(「전체 구조」 절), **세션 지연 로딩**(「세션」 절), **검색 스트리밍·취소**(「워크스페이스 검색」 절).

### 크기별 단계

| 조건                   | 동작                                                                               |
| ---------------------- | ---------------------------------------------------------------------------------- |
| 메모 1MB 이하          | 자동 저장 간격 **0.5초**                                                           |
| 메모 1MB 초과          | 자동 저장 간격 **3초**                                                             |
| 한 줄이 20,000자 초과  | 그 줄은 하이라이트하지 않는다                                                      |
| 한 줄이 경계 길이 초과 | 읽기 전용 **대용량 텍스트 뷰어**로 연다(경계 길이는 구현 계획에서 실측으로 정한다) |
| 20MB 초과              | 하이라이트·접기를 끈다. 편집은 된다                                                |
| 100MB 초과             | 읽기 전용 **대용량 텍스트 뷰어**로 연다                                            |

20,000자와 20MB 는 VS Code 의 기본 기준값을 출발점으로 삼은 것이다. 줄 수 기준은 두지 않는다. 실측(스파이크 보고서 「편집 성능」 절):

- 10MB·385,701줄 코드는 하이라이트를 켜도 키 입력 지연이 작은 파일 기준선과 구별되지 않았다. 10MB 에서는 입력 지연이 아니라 전체 토큰화 시간(Oniguruma 35–40초)이 문제였다. 20MB 이하에서는 앞에서부터 차례로 배경 토큰화하므로, 멀리 점프하면 그 자리 색이 늦게 칠해진다.
- 아주 긴 줄은 하이라이트하지 않아도 편집이 무겁다. 10MB 한 줄 JSON 은 하이라이트 없이도 키 입력 지연이 작은 파일 기준선보다 한 프레임 넘게 늘었다. 그래서 한 줄이 경계 길이를 넘는 파일은 편집기 대신 읽기 전용으로 연다. 잰 것은 10MB 한 줄 하나라서 경계 길이는 아직 없다.
- 20,000자 가드는 유지한다. 가드 없이 10MB 한 줄을 토큰화하면 첫 화면까지 2–4초가 걸린다.
- 100MB 경계와 저장 간격은 제안값이다. 스파이크가 재지 않았고, 구현 계획에서 실측으로 조정한다.

**대용량 텍스트 뷰어**는 확장이 아니라 코어의 읽기 전용 화면이다. 뷰어와 같은 토큰 URL·Range 요청으로 페이지 단위로 읽고, 파일 안 검색은 Rust 가 맡는다.

최악의 입력 손실(강제 종료 때): 1MB 이하 메모 0.5초, 1MB 초과 메모 3초, 외부 파일의 저장 전 수정분 1초.

### 목표와 측정

- **목표: 10MB 파일의 키 입력 지연(keydown → 다음 프레임) p95 가 같은 측정의 작은 파일 기준선보다 한 프레임 넘게 늘지 않는다. 한 프레임은 같은 측정에서 잰 rAF 간격 중앙값이다.** 이 측정 방식은 프레임 대기가 바닥으로 들어가 작은 파일도 p95 가 한 프레임 근처라서, 16ms 같은 절댓값으로는 판정할 수 없다(스파이크 보고서 「편집 성능」 절).
- 나머지 목표치(콜드 스타트, 파일 열기, 세션 복원, 검색)는 구현 계획에서 정한다. 파일 열기 → 첫 화면의 출발점 값은 스파이크 보고서 「스펙에 반영할 것」 절에 있다.
- **파일 세트:** 1MB·10MB·100MB 코드 파일, 한 줄짜리 10MB minified JSON, 10만 줄 로그, 메모 1만 개 워크스페이스.
- **지표:** 콜드 스타트, 파일 열기 → 첫 화면, 키 입력 지연, 스크롤 프레임, 메모리, 탭 50개 세션 복원, 검색 시간.
- **측정 방법:** 개발 빌드에 계측 지점(keydown → 다음 프레임 등)을 심어 앱 안에서 잰다. Zed·Sublime 과는 같은 파일로 수동 비교한다. 한글 조합 키의 지연은 keydown → 다음 프레임 방식으로 잡히지 않는다(WKWebView 에서 조합 갱신이 그 프레임 뒤에 들어온다). 따로 재는 방법이 필요하다.
- **한계:** 수백 MB 편집에서는 WebView·JS 구조상 Zed·Sublime 수준에 못 미친다. 목표는 일반 크기(메모, 스크립트, 로그)에서 체감 차이가 없는 것이고, 거대 파일은 대용량 텍스트 뷰어로 우회한다.

## `tote` CLI

- **설치:** 앱 메뉴 「셸 명령 설치」가 `/usr/local/bin/tote` 심볼릭 링크를 만든다(대상은 앱 번들 안의 셸 스크립트). 권한이 없으면 `~/.local/bin` 에 만들고 PATH 설정 방법을 알린다.
- **전달:** 스크립트는 앱 실행 파일을 인자와 현재 디렉터리와 함께 부른다. 실행 중인 앱이 있으면 single-instance 로 그 앱에 넘긴다. 넘긴 뒤 곧바로 끝난다.

```
tote                  앱을 앞으로 (꺼져 있으면 마지막 워크스페이스로 실행)
tote a.sh b.md        가장 최근에 포커스된 워크스페이스 창에 외부 탭으로 열기
tote -w 업무 a.sh     지정한 워크스페이스(루트 아래 폴더 이름)에 열기. 이미 열려 있는 파일이면 그 자리로 간다
tote --import a.sh    워크스페이스로 바로 가져오기(복사)해서 메모 탭으로 열기
echo 내용 | tote -    stdin 내용으로 새 메모 만들기
```

- 열린 창이 없으면 가장 최근에 쓴 워크스페이스를 연다.
- 상대 경로는 호출한 디렉터리 기준으로 푼다. `*.sh` 는 셸이 펼친다.
- **폴더 인자는 거절한다.** 나머지 인자는 열고, 거절한 것을 stderr 에 적고 종료 코드 1 로 끝난다.
- 없는 경로는 빈 외부 탭으로 열고 ⌘S 때 파일을 만든다.
- `-w` 는 새로 열 자리를 고르는 것이다. 파일이 이미 다른 창(다른 워크스페이스의 창 포함)에 열려 있으면 옮기지 않고 그 탭으로 간다(「한 메모는 한 자리에」).
- `-w` 의 워크스페이스가 없으면 stderr 에 적고 종료 코드 1.

## 오류 처리

**원칙: 메모 파일이 원본이다.** `.tote/` 안의 데이터가 깨져도 메모 내용은 잃지 않는다.

- **저장 실패**(권한, 디스크 가득 참): 탭에 「저장 실패」 표시를 띄우고 내용은 메모리에 둔 채 **5초마다 재시도**한다. **앱 종료를 막는 경우는 이것 하나뿐이다** — 저장 실패가 남아 있으면 끄기 전에 경고한다.
- **백업 실패:** 상태 표시줄에 오류로 알린다. 창마다 처음 한 번, 실패가 이어지면 하루마다 다시 알리고, 창을 닫았다 다시 열면 다시 알린다. 백업 실패는 종료를 막지 않는다.
- **`index.json` 이나 세션 파일이 깨졌을 때:** 깨진 파일을 `.corrupt-<시각>` 으로 옮기고, 폴더를 다시 훑어 색인을 새로 만든다(새 ID, `autoTitle: false`). 세션은 빈 상태로 시작한다.
- **확장 오류:** 매니페스트가 잘못된 확장은 건너뛰고 확장 목록에 오류로 표시한다. 앱 시작은 막지 않는다. 문법을 불러오지 못하면 일반 텍스트로 연다. 뷰어 오류는 「뷰어」 절.
- **워크스페이스 폴더가 사라졌을 때:** 최근 목록에 「찾을 수 없음」으로 표시하고 위치를 다시 지정할 수 있게 한다.

## 동기화 대비

동기화는 선택 기능이다. docker 로 띄운 원격 워크스페이스에 연결하는 형태이고, 서버·연결·충돌 병합·공유 범위·인증은 동기화 스펙이 정한다. 코어가 지금 지키는 것:

- 메모는 경로와 무관한 ID 로 식별한다(`index.json`).
- 세션은 기기별 파일(`sessions/<기기 ID>.json`)이고, 외부 파일 항목에 기기 ID 를 기록한다.
- 외부 파일의 저장 전 수정분과 기기 설정은 워크스페이스 밖(`Application Support/tote/`)에 둔다. 동기화되면 안 되는 것이기 때문이다.
- 편집기는 CRDT 바인딩이 있는 CodeMirror 6 다. 변경분 단위 저장은 동기화와 함께 도입한다.

## 테스트

- **Rust 백엔드:** `cargo test` 로 모듈별 단위 테스트. 대상 — 색인과 rename 대응, 원자적 쓰기, 자기 쓰기 걸러내기, 세션 직렬화, 백업 하드링크와 보존 정책, 검색, 매니페스트 파싱(실제 .vsix 를 픽스처로). 모두 임시 폴더에서 돈다.
- **프론트엔드 순수 로직:** Vitest. 대상 — 제목 추출 규칙, 언어 자동 인식, 테마 색상 대응, 세션 상태.
- **UI 흐름:** Playwright 로 Vite 개발 서버에 Tauri IPC 목을 붙여 검사한다. tauri-driver 가 macOS WebView(WKWebView)를 지원하지 않아 macOS 에서 앱 자체 E2E 자동화는 쓰지 않는다.
- **경계를 넘는 흐름**(강제 종료 후 복원 등): Rust 통합 테스트와 수동 스모크 체크리스트.
- **성능:** 「목표와 측정」 절의 파일 세트와 계측.

## 구현 계획 맨 앞의 검증 스파이크

설계가 기대는 가정 중 문서로 확인되지 않은 셋을 실측했다. 판정·수치·재측정 방법은 `docs/superpowers/reports/2026-10-07-tote-note-spikes.md` 에 있고, 결과는 이 문서의 해당 절에 반영돼 있다. 실험 앱은 `spikes/lab` 이다.

1. **뷰어 파일 전달 — 된다.** 동일 출처 없는 샌드박스 iframe 이 커스텀 URL 스킴의 토큰 URL 에서 영상을 Range 요청으로 받아 탐색까지 된다. 격리가 invoke key 한 겹에 기대는 것과 그 대응은 「뷰어」 절에 있다.
2. **편집 성능 — 된다.** 10MB 코드에서 키 입력 지연이 작은 파일 기준선과 같았다. 한 줄짜리 10MB 파일은 무겁다(「크기별 단계」 절).
3. **한글 입력 — 조건부.** 커서 하나에서는 깨지지 않는다. 멀티커서·다중 선택에서 깨진다(대응은 「편집기」 절).
