# tote-notes 편의 기능 — Finder 에서 보기, 경로 복사, 메모 복제, 다른 워크스페이스로 옮기기, 워크스페이스 이름 바꾸기·지우기

2026-11-14. 사용자가 2026-11-13 점검 끝에 추천받은 기능 묶음을 설계 확인 없이 진행하라고 했다. 동작·문구 가운데 코디네이터가 브리프로 정한 것은 **(코디네이터의 판단)**, 브리프가 비워 둬서 만드는 사람이 정한 것은 **(구현자의 판단)** 으로 표시한다. 사용자가 읽고 바꿀 수 있게 각 결정에 버린 대안을 함께 적는다.

## 왜

- 메모 파일을 Finder 에서 보는 길은 「백업 폴더 열기」 뿐이다. 메모는 숨겨진 워크스페이스 폴더(`~/.tote/<워크스페이스>`)에 있어 Finder 로 찾아가기 번거롭고, 다른 앱에 파일 경로를 넘기려면 그 경로를 손으로 맞춰 써야 한다.
- 메모를 본떠 새 메모를 시작하려면 새 메모에 글을 복사해 붙이고 이름을 다시 지어야 한다.
- 메모를 다른 워크스페이스로 보내는 길이 없다. 새로 만들고 붙여 넣은 뒤 원본을 휴지통으로 옮겨야 하고, 고정·언어 지정은 따라가지 않는다.
- 워크스페이스는 만들기·순서·숨김만 되고 이름 바꾸기·지우기는 Finder 로만 된다.

## 목표

1. 메모 행과 탭의 문맥 메뉴에서 **파일을 Finder 에서 보고**(그 파일이 선택된 채), **절대 경로를 클립보드에 복사한다.**
2. 메모 행과 메모 탭의 문맥 메뉴에서 **메모를 복제한다** — 같은 워크스페이스에 `<이름> 2.<확장자>` 로.
3. 메모 행의 문맥 메뉴에서 **메모를 다른 워크스페이스로 옮긴다.** 옮기는 도중 무엇이 실패해도 글을 잃지 않는다.
4. 설정 「워크스페이스」 구역에서 **어느 창에도 열려 있지 않은 워크스페이스의 이름을 바꾸고, macOS 휴지통으로 옮긴다.**

## 하지 않는 것

- 여러 메모를 한꺼번에 복제·옮기기·Finder 에서 보기 **(코디네이터의 판단)**. 2차의 메모 목록 다중 선택이 복제·옮기기를 선택 전체에 적용하도록 넓혔다(`docs/superpowers/specs/2026-11-14-tote-notes-list-keyboard-design.md` 「문맥 메뉴」. Finder 에서 보기·경로 복사는 하나일 때만). 그 자리를 위해 메모 행·탭의 문맥 메뉴 항목은 `src/app/context-menus.ts` 의 함수 하나씩이 정한다.
- 열린 워크스페이스의 이름 바꾸기·지우기, 워크스페이스 폴더를 루트 밖으로 옮기기 **(코디네이터의 판단)**.
- 메뉴 막대(앱 메뉴)·단축키로 이 동작들을 하는 것 **(코디네이터의 판단: 문맥 메뉴만)**. 그래서 새 단축키가 없고, 기존 단축키·편집기 키맵·macOS 시스템 키와 겹칠 것도 없다.
- 워크스페이스를 지울 때 그 백업 폴더(`backups/<워크스페이스 ID>/`)를 지우는 것 **(코디네이터의 판단)**. 백업은 앱 데이터 폴더에 그대로 남고, 휴지통에서 되살린 워크스페이스는 같은 ID 라 그 백업을 다시 이어 쓴다.
- 복제본을 여는 것 **(코디네이터의 판단)**, 목록이 복제본으로 스크롤해 강조하는 것 **(구현자의 판단: 상태 표시줄의 한 줄로 알린다. 목록이 이미 그 행을 보여 주는 정렬이 많고, 스크롤·강조는 2차의 목록 선택이 생기면 그 선택으로 하는 편이 맞다)**.
- 휴지통 메모를 복제·다른 워크스페이스로 옮기기 **(구현자의 판단: 복구한 뒤에 한다)**.

## 하면 실패인 것

- 옮기기·복제가 **저장 안 된 글을 조용히 잃는다.** 옮기기가 중간에(파일을 옮긴 뒤 색인을 쓰기 전, 다른 볼륨으로 복사하다가) 실패하거나 앱이 죽어도 글은 원래 워크스페이스나 대상 워크스페이스 가운데 적어도 한쪽에 남는다.
- 옮기거나 복제한 메모가 **같은 이름의 다른 메모를 덮어쓴다.**
- 열려 있는 워크스페이스의 폴더 이름이 바뀌거나 휴지통으로 간다(그 창의 저장이 사라진 폴더로 간다).
- 워크스페이스를 지우는 것이 **되살릴 수 없는 삭제**가 된다.
- 이름을 바꾼 워크스페이스가 고르개 순서·숨김·백업을 잃는다.

## 메뉴

메모 행의 문맥 메뉴 **(구현자의 판단: 항목 순서와 구분선. 이름과 자리에 관한 것 · 다른 자리로 보내는 것 · 파일 시스템 · 지우기로 묶었다)**:

```
이름 바꾸기…
맨 위에 고정            (고정된 메모는 「고정 해제」)
복제
다른 워크스페이스로 옮기기  ▸  고르개 순서의 워크스페이스들
─────────
Finder 에서 보기
경로 복사
─────────
휴지통으로 이동
```

- 「다른 워크스페이스로 옮기기」 는 **네이티브 하위 메뉴**다 **(구현자의 판단: 문맥 메뉴가 하위 메뉴를 그리도록 `showPopupMenu` 의 항목에 `items` 를 더했다. 버린 대안 — 고르기 대화상자: 한 번 더 누르고 다른 모양의 목록을 하나 더 배워야 한다)**. 하위 항목은 고르개에 보이는 것과 같다 — 순서 파일의 순서, 숨긴 것 제외, 지금 창의 워크스페이스 제외, 사라진 것(`missing`) 제외 **(코디네이터의 판단)**. 이름 뒤에 ⌃ 번호는 붙이지 않는다.
- 옮길 곳이 하나도 없으면(워크스페이스가 이것뿐이거나 나머지를 모두 숨겼으면) 「다른 워크스페이스로 옮기기」 항목을 **빼고** 메뉴를 그린다 **(구현자의 판단: 비활성 항목을 그리려면 팝업 항목에 `enabled` 를 더해야 하는데, 쓰는 곳이 이것 하나뿐이다)**.
- 메뉴를 그리기 직전에 워크스페이스 목록을 다시 읽는다 **(구현자의 판단: 다른 창이 만든·숨긴 것을 놓치지 않는다. 목록 읽기는 루트를 한 번 훑는 값이라 문맥 메뉴가 늦게 뜨지 않는다)**. 읽기가 실패하면 그 항목만 빼고 메뉴를 그린다.

탭의 문맥 메뉴:

```
왼쪽으로 나누기 · 오른쪽으로 나누기 · 위로 나누기 · 아래로 나누기
탭을 새 창으로 옮기기     (휴지통 탭에는 없다 — 휴지통 스펙)
─────────
복제                    (메모 탭만)
Finder 에서 보기
경로 복사
```

- 「Finder 에서 보기」·「경로 복사」 는 메모·외부 파일·휴지통 메모 탭 모두에 있다 **(구현자의 판단: 휴지통 탭도 파일이 있는 자리 `.trash/<id>/` 가 있다)**.
- 휴지통 목록 행의 문맥 메뉴에도 「Finder 에서 보기」 를 넣는다: 「복구」, 「Finder 에서 보기」, 구분선, 「영구 삭제」 **(구현자의 판단: 브리프가 할지 말지를 맡겼다. 휴지통 메모를 다른 앱으로 꺼내 볼 길이 된다. 「경로 복사」 는 행에 두지 않는다 — 탭에서 된다)**.

## Finder 에서 보기

- Finder 창을 열어 그 파일을 **선택한 채로** 보인다(macOS `open -R <경로>`) **(코디네이터의 판단)**.
- 메모는 워크스페이스 안의 지금 파일, 외부 파일은 그 경로, 휴지통 메모는 `.trash/<id>/<파일>` 이다.
- 파일이 없으면(다른 앱이 지웠거나 옮겼다) Finder 를 열지 않고 상태 표시줄에 **「파일이 없어 Finder 에서 보지 못했습니다」** 를 띄운다 **(구현자의 판단: 문구)**. 저장하지 않은 새 외부 탭(파일이 아직 없음)도 같다.
- 열린 메모 탭의 저장 전 글은 먼저 저장하지 않는다 **(구현자의 판단: Finder 는 파일 자리만 보인다. 500ms 안에 저장 타이머가 쓴다)**.

## 경로 복사

- 그 파일의 **절대 경로**를 클립보드에 넣고 상태 표시줄에 **「경로를 복사했습니다」** 를 띄운다 **(코디네이터의 판단)**. 경로는 디스크에 쓰인 그대로다(NFC 로 고치지 않는다).
- 클립보드에는 **네이티브 쪽이 쓴다**(`NSPasteboard`) **(구현자의 판단. 버린 대안 — 웹뷰의 `navigator.clipboard.writeText`: 문맥 메뉴는 네이티브 팝업이라 고른 항목이 페이지에 도착할 때는 이미 사용자 동작(클릭)의 처리 밖이다. WKWebView 는 사용자 동작 밖의 클립보드 쓰기를 거절할 수 있고, 그러면 화면 확인에서야 드러난다)**. 백엔드 명령 하나가 경로를 정하고 그 자리에서 쓴다. 가짜 백엔드는 쓴 경로를 차례로 기록한다(`FakeData.copiedPaths`) — e2e 는 이 기록과 상태 문구로 본다.
- 파일이 없어도 경로는 복사한다 **(구현자의 판단: 경로는 그 파일이 어디 있어야 하는지를 말할 뿐이다)**.

## 메모 복제

- 같은 워크스페이스에 **`<이름> 2.<확장자>`** 로 만든다. 그 이름도 있으면 ` 3`, ` 4` … (메모 만들기·복구와 같은 이름 충돌 규칙 `Workspace::free_name`) **(코디네이터의 판단)**. 원본 이름이 `회의록 2.md` 면 복제본은 `회의록 2 2.md` 다(구현자의 판단: 번호를 이어 세지 않는다 — 규칙 하나로 충분하다).
- 복제본은 **새 ID, `autoTitle: false`, 원본의 언어 지정을 따르고, 고정은 따르지 않는다** **(코디네이터의 판단)**.
- 내용: 이 창에 그 메모의 탭이 열려 있고 글이 읽혀 있으면 **편집기의 지금 글**(저장 전 글 포함, 원본의 줄 끝·BOM 그대로)을 넘겨 쓴다. 아니면 네이티브 쪽이 파일을 그대로 복사한다 — 이진 파일·100MB 넘는 파일도 그대로다 **(구현자의 판단. 버린 대안 — 먼저 저장하고 파일을 복사: 저장이 충돌 배너로 거절되면 저장 전 글이 복제본에 들어가지 않는다)**. 다른 창에만 열려 있으면 그 창의 저장 전 글은 담지 않는다(그 창이 500ms 안에 저장한 것까지다).
- 복제본은 **열지 않는다** **(코디네이터의 판단)**. 메모 목록에 나타나고, 상태 표시줄에 「복제했습니다: <새 파일 이름>」 을 띄운다 **(구현자의 판단: 열지 않으니 무엇이 생겼는지 알린다. 파일 이름은 대개 확장자로 끝나 「(으)로」 를 고를 수 없어 이름을 뒤에 둔다)**. 같은 워크스페이스의 다른 창의 목록도 따라온다.

## 다른 워크스페이스로 옮기기

### 사람이 보는 것

- 하위 메뉴에서 워크스페이스를 고르면, 그 메모가 이 창이나 같은 워크스페이스의 다른 창에 열려 있을 때 **그 탭을 먼저 저장하고 닫는다.** 저장이 실패하거나 충돌·삭제 배너가 떠 있으면 **옮기지 않고** 상태 표시줄에 **「저장하지 못해 다른 워크스페이스로 옮기지 않았습니다」** 를 띄운다 — 휴지통으로 옮기기·탭 떼어 내기의 규칙과 같다 **(코디네이터의 판단)**.
- 옮긴 뒤 이 창과 같은 워크스페이스의 다른 창의 목록에서 그 행이 빠지고, **대상 워크스페이스를 보이고 있는 창의 목록에는 바로 나타난다** **(코디네이터의 판단)**. 이 창의 상태 표시줄에 **「<대상>(으)로 옮겼습니다」** 를 띄운다(받침에 따라 「으로」·「로」).
- 대상에 같은 이름이 있으면 복제와 같은 규칙으로 ` 2`, ` 3` 을 붙인다. 덮어쓰지 않는다.
- 옮긴 메모는 대상에서 **열지 않는다**(구현자의 판단: 다른 창·다른 워크스페이스라 이 창이 열 수 없다).
- 빈 새 메모(자동 제목이고 비었다)는 탭을 닫을 때 지워지므로(코어 설계 「세션」) 옮길 것이 남지 않는다. 그 행은 목록에서 빠지고 아무것도 옮기지 않는다 — 휴지통으로 옮기기와 같다 **(구현자의 판단)**.

### 색인과 ID

- 대상 색인에 **새 ID** 로 넣는다. `autoTitle`·언어·고정은 따라간다 **(구현자의 판단. 버린 대안 — ID 유지: Finder 로 복제한 워크스페이스는 원본과 같은 메모 ID 를 가져서, 대상 색인이나 대상 휴지통(`.trash/<id>/`)에 이미 같은 ID 가 있을 수 있다. 그때만 새 ID 를 주는 갈래는 드물게만 도는 코드라 시험만 늘린다. ID 를 지켜도 얻는 것이 없다 — 백업의 「이전 버전」 은 워크스페이스 ID 별 스냅숏이라 어느 쪽이든 끊기고, 보았던 시각(`viewed`)은 워크스페이스별 파일이다)**.
- **「이전 버전」 은 끊긴다.** 옮긴 메모의 버전 창은 대상 워크스페이스에서 처음부터 시작한다. 옛 버전은 원래 워크스페이스의 백업 폴더에 그대로 있다(「백업 폴더 열기」).
- 원래 워크스페이스에서는 색인 항목과 그 메모의 보았던 시각을 지운다.

### 쓰기 순서와 실패 (구현자의 판단)

옮기기는 원래 워크스페이스의 잠금을 처음부터 끝까지 쥐고 한다. 그래서 파일 감시가 원래 이름의 사라짐을 다룰 때는 색인에 그 메모가 없어 「삭제됨」 을 알리지 않는다(휴지통으로 옮기기와 같은 방식). 대상이 열려 있으면 두 워크스페이스의 잠금을 **폴더 경로 순서로** 잡는다 — 두 창이 서로의 워크스페이스로 동시에 옮겨도 서로 기다리다 멈추지 않는다. 대상이 어느 창에도 열려 있지 않으면 앱의 창 장부 잠금을 쥔 채 대상을 잠깐 열어 쓰고 닫는다 — 그 사이에 다른 창이 그 워크스페이스를 열어 같은 폴더를 두 벌로 들고 쓰는 일이 없다.

1. 대상 폴더에서 빈 이름을 정한다(`free_name`).
2. **파일을 옮긴다.**
   - 같은 볼륨: `rename` 한 번. 실패하면 아무것도 바뀌지 않은 채 끝난다.
   - 다른 볼륨(`rename` 이 `CrossesDevices` 로 거절): 대상 폴더의 임시 파일(점으로 시작해 목록·감시에 안 잡히고, 다음에 열 때 치워지는 이름)로 **복사**하고 디스크에 내린 뒤 빈 이름으로 바꾸고, 복사본을 원본과 **바이트로 견줘 확인한다.** 복사·확인이 실패하면 복사본을 지우고 끝난다 — 원본은 손대지 않았다.
3. 대상 색인에 항목을 넣고 쓴다. 대상이 열려 있으면 tote 가 스스로 들여온 파일로 기록한다(감시가 남의 변경으로 보지 않는다).
4. 다른 볼륨이면 **원본 파일을 지운다.** 지우지 못하면 원래 색인을 그대로 두고 실패로 끝난다 — 메모는 **두 워크스페이스에 모두** 있고(대상에는 새 ID 로), 상태 표시줄에 까닭이 뜬다.
5. 원래 색인에서 항목을 빼고 쓴다.

어느 사이에 앱이 죽어도: ① 전이면 원래 자리에 그대로, ② 뒤 ③ 전이면 대상 폴더에 파일이 있고 대상을 다음에 열 때 색인이 맞춰지며 새 메모로 들어오고(`autoTitle: false`, 언어·고정 없음), 원래 색인의 항목은 파일이 없으니 맞출 때 빠진다. ④ 전이면(다른 볼륨) 두 곳에 모두 남는다. 어느 경우에도 글은 남는다. 색인 쓰기(③·⑤)가 실패하면 나머지 단계를 마저 하고 실패로 알린다 — 파일은 이미 대상에 있고, 앱이 켜 있는 동안은 메모리의 색인이, 다시 열면 색인 맞추기가 그것을 메모로 본다.

### 다른 창이 그 메모를 쥐고 있을 때

휴지통으로 옮기기와 같은 계약이다(휴지통 스펙 「만드는 사람에게 맡기는 것」 첫 항목). 백엔드는 다른 창이 그 메모를 열고 있으면 아무것도 옮기지 않고 그 창에 `tote://move-memo`(메모 ID·대상 경로)를 보낸다. 받은 창은 이 창에서 옮길 때와 같은 길(저장·닫기 뒤 옮기기)로 옮긴다. 그 창의 저장이 실패하면 **그 창의 상태 표시줄에만** 알린다 — 요청한 창은 「다른 창에 넘겼다」 만 안다 **(구현자의 판단: 휴지통과 같은 꼴)**.

## 워크스페이스 이름 바꾸기·지우기

설정 「워크스페이스」 구역(워크스페이스 순서·숨김 스펙 「설정 화면 『워크스페이스』 구역」)의 행마다 오른쪽 끝에 버튼 둘: **「이름 바꾸기…」**, **「휴지통으로 이동…」** **(구현자의 판단: 문구. 메모의 「휴지통으로 이동」 과 같은 이름이고, 확인 창이 있어 「…」 를 붙인다)**. 행을 누르면 끌기가 시작되지만 버튼을 누르는 것은 끌기로 치지 않는다(숨김 체크박스와 같다).

- **열려 있는 워크스페이스**(어느 창이 보이고 있거나 열리는 중)의 두 버튼은 꺼져 있다 **(코디네이터의 판단)**. 그런 행이 하나라도 있으면 목록 아래에 **「열린 워크스페이스는 그 창을 닫거나 다른 워크스페이스로 바꾼 뒤 이름을 바꾸거나 지울 수 있습니다.」** 를 보이고, 꺼진 버튼의 `title` 에도 같은 까닭을 둔다 **(구현자의 판단: 꺼진 버튼은 마우스를 올려도 툴팁이 뜨지 않을 수 있어 까닭을 화면에 적는다)**. 열린 행의 이름 옆에는 흐린 「열림」 을 붙인다.
- 버튼을 누른 사이에 다른 창이 그 워크스페이스를 열었으면 백엔드가 거절하고(`workspace-open`) 설정 화면의 상태 줄에 같은 까닭을 보인다. 판정은 백엔드가 창 장부 잠금 안에서 하고, 이름 바꾸기·휴지통 옮기기도 그 잠금 안에서 한다 — 판정과 동작 사이에 창이 열릴 틈이 없다.

### 이름 바꾸기

- 「새 워크스페이스 이름」 입력 창(지금 이름이 들어 있다)을 띄우고, **폴더 이름을 바꾼다**(워크스페이스 이름 = 폴더 이름) **(코디네이터의 판단)**. 이름 규칙은 새 워크스페이스와 같다(`is_valid_file_name`: 빈 이름·`/` `:` 등·점으로 시작·앞뒤 공백·255바이트 초과 거절). 같은 이름이 있으면 「같은 이름이 이미 있습니다」. 대소문자만 바꾸는 것은 된다 **(구현자의 판단: APFS 에서는 같은 폴더로 보여 「이미 있다」 로 거절될 일이지만, 사람에게는 다른 이름이다)**.
- 워크스페이스 ID 는 그대로라 **백업·보았던 시각이 이어진다.** 순서 파일(`.tote-workspaces.json`)에 그 워크스페이스의 항목(ID 와 옛 이름)이 있으면 새 이름으로 고쳐 써서 **순서·숨김이 이어진다** **(구현자의 판단: 순서 파일의 맞추기 규칙은 ID 가 하나뿐이면 이름이 달라도 찾아 주지만, Finder 로 복제해 같은 ID 가 둘이면 놓친다)**. 순서 파일을 읽을 수 없으면 건드리지 않는다(순서·숨김 스펙 「저장」 의 「덮어쓰기 전까지 건드리지 않는다」).
- `state.json` 의 최근 목록이 그 경로를 기억하면 새 경로로 고친다 — 「워크스페이스 열기…」 가 사라진 항목을 보이지 않는다.
- 바꾼 뒤 모든 창의 고르개와 설정 구역이 새 이름을 보인다(`tote://workspaces`).

### 지우기

- 확인 창: **「「<이름>」 워크스페이스를 휴지통으로 옮길까요? 메모 N개가 함께 옮겨집니다.」**, 버튼 「취소」·위험 스타일 「휴지통으로 이동」 **(코디네이터의 판단: 문구 꼴. 구현자의 판단: 버튼 이름)**. N 은 워크스페이스 바로 아래의 메모 파일 수다(앱 안 휴지통의 메모는 세지 않는다). 메모가 없으면 「…옮길까요?」 까지만.
- **폴더를 macOS 휴지통으로 옮긴다** — Finder 의 「휴지통에 넣기」 와 같아, Finder 에서 「되돌려 놓기」 로 되살린다. 영구 삭제하지 않는다 **(코디네이터의 판단)**. 방법은 `NSFileManager trashItemAtURL` 이다 **(구현자의 판단: `objc2-foundation` 이 이미 의존성이라 기능 플래그(`NSFileManager`·`NSURL`·`NSError`)만 더했다. 버린 대안 — `trash` 크레이트: 새 의존성. Finder AppleScript: 자동화 권한을 묻는다)**.
- **백업 폴더는 지우지 않는다** (「하지 않는 것」).
- 순서 파일의 그 항목(순서·숨김)과 `state.json` 최근 목록의 그 경로를 뺀다. 모든 창의 고르개·설정 구역이 따라온다.

## 백엔드 (구현자의 판단)

| 명령                           | 하는 것                                                                                          |
| ------------------------------ | ------------------------------------------------------------------------------------------------ |
| `reveal_in_finder(target)`     | `open -R`. 파일이 없으면 `not-found`                                                             |
| `copy_file_path(target)`       | 절대 경로를 `NSPasteboard` 에 쓰고 돌려준다                                                      |
| `duplicate_memo(id, 본문?)`    | 본문이 있으면 그것을, 없으면 파일을 복사해 새 메모. 같은 워크스페이스의 다른 창에 `tote://memos` |
| `move_memo_to(id, workspace)`  | 위 「다른 워크스페이스로 옮기기」. `{kind:"moved", info, workspace}` 또는 `{kind:"elsewhere"}`   |
| `rename_workspace(path, name)` | 새 경로를 돌려준다. 열려 있으면 `workspace-open`                                                 |
| `workspace_memo_count(path)`   | 확인 창의 N                                                                                      |
| `trash_workspace(path)`        | macOS 휴지통으로. 열려 있으면 `workspace-open`                                                   |

- `target` 은 `{kind:"memo", id}`·`{kind:"external", path}`·`{kind:"trashed", id}` 다(`FileTarget`). 프런트가 경로를 넘기지 않고 백엔드가 그 창의 워크스페이스에서 정한다 — 메모 경로를 프런트가 만들지 않는다.
- 워크스페이스를 가리키는 `path` 는 워크스페이스 루트 바로 아래의 워크스페이스여야 한다. 아니면 `not-a-workspace`. 메모를 지금 워크스페이스로 옮기라는 요청은 `bad-request`.
- 새 오류 코드 `workspace-open`: 「열린 창을 닫거나 다른 워크스페이스로 바꾼 뒤 바꿀 수 있습니다」.
- 팝업 메뉴 항목(`PopupMenuItem`)에 `items`(하위 메뉴)를 더한다. 하위 항목을 고르면 그 항목의 `id` 가 돌아온다.

## 코어 설계·다른 스펙과의 관계

- 코어 설계 「메모 목록」 절과 메모 목록 스펙 「이름 바꾸기」 절이 문맥 메뉴 항목을 「셋」 으로 세던 문장을 이 문서를 가리키게 고친다.
- 워크스페이스 순서·숨김 스펙 「하지 않는 것」 의 「관리 구역에서 워크스페이스 이름 바꾸기·지우기·만들기」 에서 이름 바꾸기·지우기를 빼고 이 문서를 가리킨다.

## 시험

- Rust: 복제(이름 ` 2`·` 3`, 새 ID·`autoTitle: false`·언어 따라감·고정 안 따라감, 넘긴 본문, 파일 복사), 옮기기(같은 볼륨, 다른 볼륨 흉내 — `rename` 이 `CrossesDevices` 를 내는 함수를 주입, 복사 실패·확인 불일치·원본 지우기 실패에서 글이 남음, 이름 충돌, 색인 항목과 감시 기록, 열려 있지 않은 대상), 워크스페이스 이름 바꾸기·지우기(열린 워크스페이스 거절, 이름 규칙, 대소문자만, ID 유지, 순서 파일·최근 목록 갱신, 휴지통 옮기기는 주입한 함수로), 팝업 하위 메뉴 항목 읽기.
- 프런트 단위(vitest): 문맥 메뉴 항목 함수(옮길 곳의 순서·숨김·지금 것·사라진 것 제외, 탭 종류별 항목), 「(으)로」.
- e2e(가짜 백엔드): 문맥 메뉴 항목이 보이고, 각 동작이 가짜 백엔드의 호출 기록·목록·탭 상태로 드러난다. 열린 메모를 옮기면 탭이 닫히고 대상 워크스페이스에 들어가며, 저장이 실패하면 옮기지 않는다. 설정의 이름 바꾸기·휴지통 이동과 열린 워크스페이스의 꺼진 버튼.
- 실기기(WKWebView) 확인 — 보고서의 「사람 확인」 표: 하위 메뉴가 네이티브로 그려지고 고르면 옮겨지는지, `open -R` 가 Finder 에서 파일을 선택하는지, 클립보드에 한글 경로가 깨지지 않고 들어가는지, 지운 워크스페이스가 macOS 휴지통에 있고 「되돌려 놓기」 가 되는지.
