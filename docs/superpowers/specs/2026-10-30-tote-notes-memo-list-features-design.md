# tote-notes 메모 목록 기능 묶음 설계 — 이름 바꾸기·내용 검색·미리보기·정렬·고정·「저장하지 않음」

2026-10-30. 사용자가 한 번에 요청한 여섯 가지다. 사용자는 질문 없이 바로 시작하기를 골랐으므로, 요청 문장은 그대로 인용하고 그 밖의 결정은 모두 **설계자 판단**으로 표시한다.

이 문서는 코어 설계(`docs/superpowers/specs/2026-10-07-tote-note-core-design.md`)의 「메모 목록」 절 전체와, 「세션」 절의 「저장 / 버리기 / 취소」 를 대신한다.

## 요청 (사용자 원문)

- 노트 이름 수정 기능
- 제목 필터 => 내용 검색도 가능하도록
- 파일 저장하지 않고 닫는 경우 버리기 => 저장하지 않음
- 옵션으로 사이드바 파일항목에 내용 일부도 표시 가능하도록(기본 활성화)
- 사이드바 정렬 기능 조회 순, 수정 순 역순, 정순 으로 선택 가능
- 사이드바 고정 기능 스크롤 해도 고정

⚠ 마지막 줄은 **「메모를 목록 맨 위에 고정(핀)하고, 고정된 메모는 목록을 스크롤해도 그 자리에 남는다」** 로 읽었다(설계자 판단). 다른 뜻이면 「고정」 절만 바꾼다.

## 지금 있는 것

- 이름 바꾸기는 메뉴 「파일 → 이름 바꾸기…」 로만 된다. 활성 탭의 메모에만 닿고 기본 단축키가 없다(`renameActive` in `src/app/controller.ts`, `MemoDoc.rename` in `src/app/docs.ts`).
- 사이드바 메모 목록(`MemoList` in `src/ui/memo-list.ts`)은 최근 수정순 고정, 파일 이름 부분 일치 필터, 28px 한 줄 행, 가상 스크롤이다.
- 내용 검색은 사이드바의 별도 패널(「워크스페이스 검색」, `src/ui/search-panel.ts`, 백엔드 `src-tauri/src/search/`)에 있다.
- 외부 파일 탭을 닫을 때 묻는 창(`askUnsaved` in `src/ui/dialogs.ts`)의 버튼은 「버리기 / 취소 / 저장」 이다.

## 하지 않는 것

- 태그·폴더·고정 메모끼리의 순서 끌어 바꾸기.
- 목록 행 안에서 바로 이름 고치기(인라인 편집). 이름은 지금과 같은 이름 입력 창으로 받는다.
- 필터의 정규식·대소문자 구분. 그것은 워크스페이스 검색 패널의 몫이다.
- 전문 색인(full-text index). 내용 일치는 워크스페이스 검색과 같은 방식으로 그때그때 찾는다.
- 여러 메모를 골라 한꺼번에 고정·이름 바꾸기.

## 「저장하지 않음」

- `askUnsaved` 의 「버리기」 버튼 이름을 **「저장하지 않음」** 으로 바꾼다(사용자 요청). 동작(수정분을 버리고 닫는다)·자리·강조(위험 스타일)·안내 문장 「저장하지 않으면 바뀐 내용이 사라집니다.」 는 그대로다.
- 코드 식별자(`"discard"`, `ExternalDoc.discard`)는 바꾸지 않는다. 그 주석 속 「버리기」 는 「저장하지 않음」 으로 맞춘다.
- 「버리기」 로 버튼을 찾는 테스트(`tests/e2e/external.spec.ts`)를 함께 고친다.

## 이름 바꾸기

- **사이드바 행에서 바꾼다.** 행을 오른쪽 클릭(⌃클릭)하면 문맥 메뉴가 뜨고, 첫 항목이 **「이름 바꾸기…」** 다(설계자 판단: 요청이 사이드바 항목에 관한 것들이라 같은 자리에 둔다).
- 문맥 메뉴는 macOS 기본 모양의 **네이티브 팝업**이다(설계자 판단: 앱의 다른 메뉴와 같은 모양·키보드 동작). 항목은 이 문서의 「이름 바꾸기…」 와 「고정」 절의 항목 하나, 둘이다.
- 이름 입력 창은 「파일 → 이름 바꾸기…」 와 같은 창(`promptText("새 파일 이름", …)`)이고 규칙도 같다 — 확장자를 뺀 부분이 선택된 채 열리고, 바꾸면 자동 제목이 멈추고(`autoTitle: false`), 쓸 수 없는 이름·겹치는 이름은 지금과 같은 오류로 알린다.
- **열려 있지 않은 메모도 바꿀 수 있다.** 그 메모가 어느 창·칸에 열려 있으면 그 탭들의 이름이 함께 바뀌고, 열린 탭의 바뀐 내용은 이름을 바꾸기 전에 저장된다(`MemoDoc.rename` 의 `saveNow` 와 같은 보장).
- 메뉴 「파일 → 이름 바꾸기…」 는 지금처럼 활성 탭에 닿는다.

## 필터가 내용도 찾는다

- 필터 칸의 안내 글을 **「제목·내용 검색」** 으로 바꾼다.
- **제목(파일 이름) 일치는 지금처럼 치는 즉시 보인다.** 대소문자 무시, 부분 일치, 한글 NFC 정규화(`filterMemos` 의 `fold`).
- **내용 일치는 입력이 `SEARCH_DEBOUNCE_MS`(150ms) 멈춘 뒤 백엔드에 물어 더한다.** 새 입력이 오면 앞의 물음은 취소한다.
  - 일치 규칙은 제목과 같다 — 대소문자 무시, 정규식이 아닌 글자 그대로, NFC 로 맞춘 글자끼리.
  - 대상은 워크스페이스 검색과 같다(코어 설계 「워크스페이스 검색」 절) — 텍스트 메모만, 바이너리와 5MB 를 넘는 파일은 건너뛴다.
  - 엔진은 워크스페이스 검색의 백엔드를 쓴다. 기존 스트리밍 명령을 그대로 부를지, 메모마다 첫 일치 하나만 돌려주는 명령을 새로 둘지는 만드는 사람이 정한다.
- 목록은 **제목 일치와 내용 일치의 합집합**을 지금의 정렬 순서로 보인다. 고정 구역에도 같은 필터가 걸린다.
- **내용으로 맞은 행은 미리보기 줄 자리에 맞은 줄의 앞뒤 일부를 보이고 맞은 글자를 강조한다**(설계자 판단). 미리보기 설정이 꺼져 있으면 행은 한 줄 그대로이고 맞은 줄도 보이지 않는다(설계자 판단: 필터 중에 행 높이가 바뀌지 않게).
- **내용으로 맞은 행을 누르면 그 메모를 첫 일치 자리에 커서를 두고 연다**(설계자 판단: 검색 패널의 결과를 누를 때와 같다). 제목으로만 맞은 행은 지금처럼 연다.
- 맞는 메모가 하나도 없으면 목록 자리에 「맞는 메모가 없습니다」 를 보인다.
- 필터를 비우면 내용 물음도 멈추고 목록이 원래대로 돌아온다.

## 미리보기

- 사이드바 메모 행에 **내용 일부를 둘째 줄로 보인다.** 설정으로 끌 수 있고 **기본은 켜짐**이다(사용자 요청).
- 설정: 설정 화면에 「사이드바」 구역을 두고 그 안에 **「메모 목록에 내용 미리보기」** 켜기/끄기를 둔다. `settings.json` 의 `sidebar.preview`(기본 `true`), 패치는 `sidebarPreview`. 바꾸면 열린 창 전부에 바로 적용된다(설계자 판단: 편집기 설정과 같은 전파 방식).
- **미리보기 글:** 제목 줄(`titleLine` 이 고르는 줄 — 첫 비어 있지 않은 줄, `#!` 로 시작하는 첫 줄은 건너뜀) 다음부터 비어 있지 않은 줄들을 이어 붙인다. 각 줄 앞의 마크다운 표지(`#`, `-`, `*`, `+`, `>`, `1.` 꼴)와 공백을 걷고, 연속 공백을 하나로 줄이고, **100자**에서 자른다. 행에서는 한 줄을 넘으면 말줄임으로 끝난다(설계자 판단).
  - 제목 줄 뒤에 아무것도 없으면 둘째 줄은 비어 있다. 행 높이는 그대로다.
  - 텍스트가 아닌 메모(이미지·영상·소리·문서)는 미리보기가 없다. 둘째 줄은 비어 있다.
- **미리보기는 백엔드가 만든다**(설계자 판단: 목록은 열려 있지 않은 메모도 보이므로 프론트가 파일을 읽을 수 없다). 메모 목록 정보(`MemoInfo`)에 `preview` 를 더한다. 파일 앞쪽 **4KB**만 읽고(UTF-8 경계에서 자름), 메모의 수정 시간·크기가 그대로면 다시 읽지 않는다. 미리보기 규칙은 한 곳(Rust)에만 둔다.
  - ⚠ 메모 10,000 개 워크스페이스에서 목록을 처음 받는 시간이 코어 설계 「성능」 절의 목표를 넘지 않아야 한다. 만드는 사람이 `pnpm perf:fixtures`·`pnpm perf:measure`(`docs/guides/development.md`)로 재서 보고한다. 넘으면 미리보기를 나중에 채우는 방식(목록 먼저, 미리보기는 뒤따라)으로 바꾼다.
- 미리보기를 켜면 행 높이는 **46px**(설계자 판단. 만드는 사람이 실제 글꼴로 보고 맞춰도 된다), 끄면 지금의 28px 이다. 가상 스크롤은 그 높이로 센다.
- 열린 메모를 고치면 저장될 때 목록 정보가 바뀌므로 미리보기도 그때 따라온다.

## 정렬

- 필터 칸 오른쪽에 **정렬 버튼**을 둔다. 누르면 네이티브 팝업 메뉴로 넷 중 하나를 고른다(사용자 요청: 조회 순·수정 순, 역순·정순). 지금 고른 것에 체크 표시가 있다.
  - **최근 수정순**(기본, 지금 동작) · **오래된 수정순** · **최근 조회순** · **오래된 조회순**
- 동점은 이름순이다(지금의 `byRecent` 와 같다).
- 고른 정렬은 `settings.json` 의 `sidebar.sort`(`"modified-desc"` 기본, `"modified-asc"`, `"viewed-desc"`, `"viewed-asc"`)에 남고 **모든 창·모든 워크스페이스에 같게** 쓰인다(설계자 판단: 미리보기 설정과 같은 자리).
- **조회 시각:** 메모가 칸의 활성 탭으로 보이게 된 순간이다 — 사이드바에서 열기, 탭 누르기, 다른 칸에서 끌어 오기, 단축키로 탭 옮기기 모두. **앱을 켜거나 워크스페이스를 열 때 세션이 되살린 활성 탭은 세지 않는다**(설계자 판단: 켤 때마다 순서가 흔들리지 않게).
- **조회 시각은 이 기기에만 둔다**(설계자 판단: `index.json` 에 두면 메모를 볼 때마다 색인이 바뀌어 백업 스냅샷이 생기고, 동기화가 붙으면 기기끼리 다툰다). 자리는 앱 데이터 폴더(`~/Library/Application Support/tote/` 아래, 워크스페이스 ID 별) 또는 워크스페이스의 기기별 세션 파일 중 만드는 사람이 정한다. 쓰기는 세션 파일처럼 변화가 멈추고 1초 뒤, 창을 닫거나 앱을 끌 때는 즉시다.
- **한 번도 본 적 없는 메모의 조회 시각은 그 메모의 수정 시각으로 친다**(설계자 판단: 처음 고른 순간에도 쓸 만한 순서가 나온다).
- 조회순일 때 메모를 열면 목록이 바로 다시 정렬된다. 스크롤 위치는 그대로 둔다.
- 같은 워크스페이스의 다른 창도 조회 시각을 함께 쓴다(메모 목록·색인을 함께 쓰는 것과 같다).

## 고정

- 행의 문맥 메뉴 둘째 항목이 **「맨 위에 고정」**, 이미 고정된 메모에서는 **「고정 해제」** 다.
- 고정된 메모는 **목록 맨 위의 고정 구역**에 모인다. 이 구역은 필터 칸 바로 아래에 있고 **아래 목록을 스크롤해도 움직이지 않는다**(사용자 요청: 「스크롤 해도 고정」). 구역과 목록 사이에 얇은 구분선을 둔다. 고정된 메모는 아래 목록에 다시 나오지 않는다.
- 고정 구역 안의 순서도 지금 고른 정렬을 따른다.
- 고정 구역이 메모 목록 높이의 **40%** 를 넘으면 구역 안에서만 스크롤된다(설계자 판단: 고정이 많아도 아래 목록이 보이게).
- 고정된 행에는 작은 핀 표시를 둔다(설계자 판단).
- 필터가 걸리면 고정 구역에도 맞는 것만 남고, 하나도 없으면 구역과 구분선이 숨는다.
- **고정은 메모의 성질이라 `index.json` 에 둔다** — 항목에 `pinned: true`(고정이 아니면 쓰지 않는다)(설계자 판단: 기기를 옮겨도 남고, 이름이 바뀌어도 ID 로 따라가고, 백업에 함께 담긴다). 메모를 지우면 함께 사라진다.
- 같은 워크스페이스의 다른 창 목록도 바로 따라온다.

## 테스트

- 단위(TS): 정렬 넷과 동점, 고정 구역과 나머지의 분리, 필터가 고정 구역에도 걸리는 것, 제목 일치와 내용 일치의 합집합, 미리보기 켜고 끌 때의 행 높이와 가상 스크롤 범위.
- 단위(Rust): 미리보기 글 규칙(제목 줄 건너뛰기, shebang, 마크다운 표지, 100자, 4KB 의 UTF-8 경계), `pinned` 의 읽기·쓰기·생략, 조회 시각 저장과 1초 미루기, 내용 일치의 대소문자 무시와 대상 제외 규칙.
- e2e(Playwright, `FakeBackend`): 사이드바에서 열려 있지 않은 메모와 열린 메모의 이름 바꾸기, 고정 구역이 스크롤에도 남는 것, 내용으로 맞은 행을 눌러 첫 일치 자리로 열기, 정렬 메뉴, 미리보기 설정 끄기, 「저장하지 않음」.
- 실기기(WKWebView) 확인: 문맥 메뉴와 정렬 메뉴가 네이티브 팝업으로 뜨는지, 고정 구역이 스크롤에 남는지, 미리보기 행이 실제 글꼴에서 잘리지 않는지. 확인 기록은 `docs/superpowers/reports/` 에 남긴다.

## 만드는 사람에게 남긴 것

- 문맥 메뉴·정렬 메뉴의 네이티브 팝업을 어떻게 띄우고 고른 항목을 페이지로 돌려줄지.
- 내용 일치에 기존 스트리밍 검색 명령을 쓸지 새 명령을 둘지.
- 조회 시각의 저장 자리(앱 데이터 폴더 대 기기별 세션 파일).
- 정렬 버튼의 아이콘과 고정 표시의 모양, 미리보기 행의 정확한 높이.
- 미리보기를 목록과 함께 줄지 뒤따라 채울지(성능 측정 결과에 따라).
