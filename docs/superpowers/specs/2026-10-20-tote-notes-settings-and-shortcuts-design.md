# tote-notes 설정 화면 개편·줄번호·단축키 설정 — 설계

2026-10-20. 사용자 요청: 빈 칸 안내의 간격을 붙이고, 줄번호를 보이고, 설정 화면 UI 를 「설정 내용에 따라 분리」하고, 단축키 설정 기능을 넣는다. 「추가적인 개선점은 직접 찾아서」 하라고 했으므로 그 밖의 결정은 아래에 **설계자 판단**으로 표시한다. 사용자는 이번에 세부 질문을 받지 않기로 했다.

이 문서는 코어 스펙(`docs/superpowers/specs/2026-10-07-tote-note-core-design.md`)의 「설정 화면은 최소로 둔다」 를 넓힌다. 구현하는 브랜치가 코어 스펙의 그 문장과 settings.json 설명을 이 문서에 맞게 고친다.

## 왜

- 빈 칸 안내 세 줄(「새 메모를 만드세요」, 보조 문구, 「새 메모」 버튼)이 칸 높이 전체에 1/6·1/2·5/6 지점으로 흩어져 한 덩어리로 읽히지 않는다. 원인은 `.editor-placeholder` 가 `inset: 0` 의 grid 이고 자식마다 암시적 행이 생겨 남는 높이를 나눠 갖기 때문이다. 같은 자리를 쓰는 「열 수 없음」 류 문제 화면도 문구와 버튼이 1/4·3/4 로 벌어진다.
- 편집기에 줄번호가 없다.
- 설정 화면은 모달 한 장에 워크스페이스·테마·확장이 세로로 이어져 있고, 편집기 설정은 하나도 없다.
- 단축키는 메뉴에 박혀 있어 바꿀 수 없다.

## 목표

1. 빈 칸 안내와 문제 화면이 칸 가운데에 **한 묶음**으로 보인다.
2. 편집기에 줄번호가 보이고, 설정에서 끌 수 있다.
3. 설정 화면이 성격별 구역으로 나뉘고, 한 번에 한 구역만 보인다.
4. 앱 명령의 단축키를 설정에서 바꾸거나 지우거나 새로 붙일 수 있고, 바꾼 단축키가 메뉴와 화면 문구에 바로 반영된다.

## 하지 않는 것

- 편집기 안 명령(CodeMirror keymap: ⌘F, ⌘D, ⌘L, ⌘/, ⇧⌘D 등)의 단축키 바꾸기. 목록에는 「편집기(고정)」 로 보여 충돌 검사에만 쓴다.
- 시스템 편집 메뉴(⌘Z, ⇧⌘Z, ⌘X, ⌘C, ⌘V, ⌘A)와 전체 화면·최소화 같은 macOS 기본 항목 바꾸기. Tauri 의 predefined 항목이라 바꿀 수 없다.
- ⌃1~⌃9 워크스페이스 전환 바꾸기(고정으로 보인다).
- 설정을 별도 창으로 띄우기. 지금처럼 모달이다.
- 대용량 뷰어(`large-text`)의 줄번호·글꼴. 대용량 뷰어는 줄 높이 20px 고정 가상 스크롤이라 지금 값(14px, 기본 글꼴)에 **묶어 둔다**(설계자 판단). 지금은 편집기와 같은 `--editor-size`·`--editor-font` 를 쓰므로 대용량 뷰어용 변수를 따로 둬서 편집기 글꼴 설정이 그쪽으로 새지 않게 한다.
- 단축키 설정 내보내기·가져오기, 키 두 번 누르기(chord).

## 하면 실패인 것

- 단축키를 바꾸는 중에 누른 키가 그 명령을 실제로 실행한다(⌘N 을 녹음하려다 새 메모가 생김).
- 저장된 단축키 하나가 잘못돼 있어 다른 단축키나 설정 전체가 기본값으로 돌아간다.
- 설정 화면을 다시 열 수 없게 된다(설정 단축키를 지웠는데 메뉴로도 못 엶).
- 바꾼 단축키가 화면 문구(「⌘N 을 누르세요」)와 다르다.
- 빈 칸 안내를 고치다 기존 e2e 셀렉터(`.editor-placeholder p` 와 그 순서)가 깨진다.

## 1. 빈 칸 안내와 문제 화면

- `showPlaceholder` 가 만드는 자식(`<p>` 제목, 선택적 `<p class="editor-placeholder-hint">`, 선택적 `<button>`)을 **한 묶음 요소로 감싼다**(설계자 판단: `div.editor-placeholder-body`, 세로 flex, 간격 8px 안팎). `.editor-placeholder` 는 그 묶음 하나를 가운데에 놓는다. `<p>` 의 수와 순서는 그대로다.
- 제목은 본문 색(`--fg`)·15px 안팎, 보조 문구는 `--muted`·12px, 빈 칸의 「새 메모」 버튼은 `primary`(설계자 판단). 문제 화면의 「텍스트로 열기」 는 지금처럼 기본 버튼.
- 보조 문구와 미리보기 안내(`PREVIEW_HINT`)에 들어 있는 단축키 표기(⌘N, ⇧⌘V)는 **지금 그 명령에 걸린 단축키**로 만든다. 단축키가 없으면 단축키 부분을 뺀 문장을 쓴다(예: 「메모 목록에서 메모를 여세요」). 표기는 macOS 기호(⌃⌥⇧⌘ 순서, 글자는 대문자).

## 2. 줄번호와 편집기 설정

- CodeMirror `lineNumbers()` 와 `highlightActiveLineGutter()` 를 새 Compartment 로 넣는다. 기본은 **켬**(사용자가 「줄번호 표시」 를 요청했으므로).
- 거터 색은 테마 변수로 칠한다: 배경은 편집기 배경과 같게, 숫자는 `--muted`, 활성 줄 숫자는 `--fg`. VS Code 테마 매핑에 `editorLineNumber.foreground`·`editorLineNumber.activeForeground` 를 더한다(설계자 판단). 거터와 본문 사이에 얇은 경계는 두지 않는다.
- 같은 「편집기」 구역에 **글꼴 크기**(11~24, 기본 14)와 **글꼴**(자유 입력, 비우면 기본 글꼴)를 더한다(설계자 판단: 줄번호를 켜면 자연스럽게 찾는 항목이고, 지금은 CSS 변수로만 정해져 있다). 값은 `--editor-size`·`--editor-font` 로 반영한다.
- 각 탭이 자기 `EditorState` 를 가지므로 설정이 바뀌면 **보이지 않는 탭의 상태까지** 다시 설정한다(언어 재설정과 같은 방식).
- 설정이 바뀌면 열린 모든 창에 바로 반영된다(기존 `tote://config` 경로).

## 3. 설정 화면

- 모달은 그대로 두고, **왼쪽에 구역 목록, 오른쪽에 그 구역 내용**인 두 칸 배치로 바꾼다(설계자 판단: macOS 설정·VS Code 설정과 같은 모양). 구역은 이 순서다.
  1. **일반**: 워크스페이스 루트.
  2. **편집기**: 줄번호, 글꼴 크기, 글꼴.
  3. **모양**: 라이트 테마, 다크 테마.
  4. **단축키**: 아래 4절.
  5. **확장**: 설치·목록·활성·제거·문제·우선순위.
- 처음 열면 「일반」. 같은 창에서 다시 열면 마지막에 본 구역(앱을 다시 켜면 잊어도 된다).
- 저장 방식은 하나로 맞춘다: **바꾸는 즉시 저장**. 워크스페이스 루트만 경로라서 입력 중에 저장하지 않고 「적용」(기본 버튼, primary 아님)이나 Enter 로 저장한다. 그래서 모달 안 primary 버튼은 「닫기」 하나다.
- 접근성: 모달에 `aria-modal="true"`·`aria-labelledby`, 구역 목록은 `role="tablist"`/`tab`/`tabpanel` 과 ↑↓ 이동, 입력마다 `<label>`, 오류 문구는 `aria-live="polite"`. 다른 모달(`dialogs.ts`, 버전 창)에도 `aria-modal`·`aria-labelledby` 를 붙인다(설계자 판단: 같은 결함이다).
- 다크 기본 테마에서 primary 버튼(흰 글자 위 `#4c9aff`, 대비 약 2.8:1)을 4.5:1 이상으로 올린다. 방법은 빌더에게 맡긴다(버튼 배경용 변수를 따로 두는 식).
- 모달 크기는 지금(`min(720px, 90vw)`, `max-height: 85vh`)에서 구역 목록이 들어갈 만큼만 넓힌다. 구역을 바꿔도 모달 크기가 출렁이지 않게 높이를 고정한다.

## 4. 단축키 설정

### 무엇을 바꿀 수 있나

- **앱 명령**: 메뉴에 id 가 있는 모든 사용자 정의 메뉴 항목(새 메모, 새 창, 파일 열기, 저장, 가져오기, 이름 바꾸기, 이전 버전, 백업 폴더 열기, 탭 닫기, 창 닫기, 워크스페이스 열기, 새 워크스페이스, 워크스페이스 검색, 오른쪽·아래로 나누기, 네 방향 칸 이동, 다음·이전 탭, 미리보기 전환, 탭을 새 창으로 옮기기, 셸 명령 설치, 종료). 지금 단축키가 없는 명령에도 붙일 수 있다.
- **설정…(⌘,)은 고정**이다(설계자 판단: 설정을 다시 열 길을 잃지 않게).
- **고정 단축키**(설계자 판단)는 넷이다: 설정…(⌘,), ⌃1~⌃9, 시스템 편집 메뉴(⌘Z, ⇧⌘Z, ⌘X, ⌘C, ⌘V, ⌘A), macOS 기본 메뉴 항목(⌘H 숨기기, ⌥⌘H 다른 앱 숨기기, ⌘M 최소화, ⌃⌘F 전체 화면). 앱 명령에 고정 단축키를 걸면 **거절**한다. 목록 맨 아래 「고정」 묶음에 회색으로 보인다.
- **편집기 단축키는 고정이 아니다**(설계자 판단). 편집기 키맵(`zedKeymap`, CodeMirror 의 close-brackets·default·search·history 키맵)을 실행 중에 읽어 만든 표와 겹치면 **허용하되 경고**한다: 그 줄에 「편집기의 〈명령〉 을 가립니다」. 메뉴 단축키가 편집기보다 먼저 키를 받기 때문이다. 이유: 지금 기본값 가운데 ⇧⌘\(아래로 나누기)·⌥⌘↑↓(칸 이동)가 이미 편집기 키와 겹치고, ⌃+글자 대부분이 macOS 의 emacs 식 편집기 키라서, 거절로 하면 기본값으로 되돌리기조차 막힌다. 표는 키맵에서 꺼내므로 키맵이 바뀌어도 낡지 않는다. 편집기 단축키는 목록에 따로 보이지 않고 경고로만 드러난다.

### 화면

- 명령마다 한 줄: 메뉴 이름(어느 메뉴인지 작게), 지금 단축키, 「기본값」 표시 또는 바뀐 표시, 행 끝에 「되돌리기」(기본값과 다를 때만).
- 맨 위 검색 칸으로 명령 이름·단축키 표기로 거른다. 구역 하단에 「모두 기본값으로」(확인 대화상자를 거친다).
- 단축키 칸을 누르면 **녹음** 상태가 된다: 「키를 누르세요」 가 보이고, 다음 키 조합을 받는다.
  - 보조키 없는 글자·숫자는 받지 않는다(⌘·⌃·⌥ 중 하나는 있어야 한다. F1~F12 는 보조키 없이 허용).
  - Esc 는 녹음 취소, Backspace·Delete 는 「단축키 없음」 으로 저장.
  - 다른 곳을 누르거나 포커스가 빠지면 취소.
- 충돌하면 저장하지 않고 그 줄 아래에 이유를 보인다: 다른 앱 명령과 같으면 「〈명령 이름〉 에 이미 쓰고 있습니다」 와 함께 「바꾸기」(상대 명령의 단축키를 지우고 이쪽에 건다), 고정 단축키와 같으면 「〈이름〉 에 고정된 단축키입니다」(바꾸기 없음). 편집기 키와 겹치는 것은 저장하고 경고만 남긴다(위).

### 녹음 중에 명령이 실행되지 않게

네이티브 메뉴 단축키는 웹뷰보다 먼저 키를 가로챌 수 있다. 그래서 **녹음을 시작할 때 백엔드에 알려 모든 사용자 정의 메뉴 항목의 단축키를 잠시 떼고, 끝날 때 되돌린다**(설계자 판단: 웹뷰가 먼저 받는지 실제 앱으로 재기 전이라 어느 쪽이든 안전한 방법을 고른다). 녹음을 연 창이 닫히거나 새로 고쳐지거나 앱이 포커스를 잃으면 되돌린다. 되돌리기를 잊는 경로가 없어야 한다.

macOS 기본 메뉴 항목(⌘H, ⌥⌘H, ⌘M, ⌃⌘F)은 Tauri predefined 라 뗄 수 없다. 녹음 중에 이 키를 누르면 창이 실제로 숨겨지거나 최소화될 수 있다(설계자 판단: 받아들인다. 어차피 고정이라 거절될 키이고, 글을 잃거나 되돌릴 수 없는 동작이 아니다). 시스템 편집 단축키는 녹음 칸이 글 입력 칸이 아니라서 영향이 없다. 이 한계는 화면 확인 목록에 적는다.

### 저장과 적용

- `settings.json` 에 `shortcuts` 필드를 더한다: 명령 id → 단축키 문자열 또는 `null`(단축키 없음). **기본값과 다른 것만** 적는다. 키가 없으면 기본값.
- 문자열은 Tauri accelerator 표기(`CmdOrCtrl+Shift+N` 꼴)로 저장한다.
- 읽을 때 **항목마다** 검사한다: 모르는 명령 id, 고정 명령 id, 파싱할 수 없는 문자열, 고정 단축키와 같은 항목, 다른 앱 명령의 결과 단축키와 겹치는 항목은 그 항목만 버리고 나머지는 살린다(겹칠 때는 기본값이 아니라 사용자가 적은 쪽을 버린다. 둘 다 사용자가 적었으면 명령 id 순서로 뒤의 것을 버린다). 편집기 키와 겹치는 것은 버리지 않는다. 필드 모양 자체가 틀리면 `shortcuts` 만 기본값으로 돌아간다(기존 `lenient` 방식).
- Tauri `set_accelerator` 는 파싱에 실패한 문자열을 오류 없이 「단축키 없음」 으로 만든다. 그래서 Rust 가 파싱을 먼저 확인하고, 실패하면 저장을 거절한다. TS 도 같은 규칙으로 미리 막는다.
- 앱을 켤 때 저장된 단축키로 메뉴를 만들고, 설정이 바뀌면 이미 만든 메뉴 항목의 단축키를 바꾼다. 메뉴는 앱에 하나이므로 모든 창에 함께 적용된다.
- 화면 문구(빈 칸 보조 문구, 미리보기 안내)와 설정 화면의 표기는 같은 출처(현재 단축키 표)에서 만든다.

## 시험이 보여야 하는 것

- 빈 칸 안내 세 요소가 칸 가운데의 한 묶음 안에 있고, 기존 `.editor-placeholder p` 셀렉터와 순서가 그대로다.
- 줄번호를 끄고 켜면 보이는 탭과 숨은 탭 모두 바뀌고, 다른 창에도 퍼진다.
- 설정 구역을 오가도 저장된 값이 유지되고, 각 구역의 기존 시험(루트·테마·확장)이 새 배치에서 그대로 통과한다.
- 단축키: 녹음·지우기·되돌리기·모두 기본값·충돌(앱 명령끼리는 바꾸기, 고정과는 거절)·잘못된 저장 항목 하나만 버려짐·녹음 중 메뉴 단축키를 떼고 되돌림(Rust 시험)·바꾼 단축키가 빈 칸 문구에 반영됨.
- e2e 는 메뉴 단축키를 실제로 누르지 못한다(가짜 백엔드가 메뉴 id 를 직접 보낸다). 실제 메뉴에 단축키가 걸리는지는 Rust 시험과 나중 화면 확인으로 본다.

## 빌더에게 맡기는 것

- 구역 목록·단축키 행의 세부 모양, 간격, 아이콘 유무.
- 다크 primary 대비를 올리는 구체적 방법.
- 단축키 표기 함수의 위치와 이름, 메뉴 항목 핸들을 보관할 자리.
- 글꼴 입력 칸의 검증 정도(존재하지 않는 글꼴은 브라우저가 기본으로 떨어지므로 막지 않아도 된다).
