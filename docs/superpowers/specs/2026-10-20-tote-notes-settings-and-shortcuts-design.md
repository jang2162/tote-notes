# tote-notes 설정 화면 개편·줄번호·단축키 설정 — 설계

2026-10-20. 사용자 요청: 빈 칸 안내의 간격을 붙이고, 줄번호를 보이고, 설정 화면 UI 를 「설정 내용에 따라 분리」하고, 단축키 설정 기능을 넣는다. 「추가적인 개선점은 직접 찾아서」 하라고 했으므로 그 밖의 결정은 아래에 **설계자 판단**으로 표시한다. 사용자는 이번에 세부 질문을 받지 않기로 했다.

이 문서는 코어 스펙(`docs/superpowers/specs/2026-10-07-tote-note-core-design.md`)의 「설정 화면은 최소로 둔다」 를 넓힌다. 구현하는 브랜치가 코어 스펙의 그 문장과 settings.json 설명을 이 문서에 맞게 고친다.

## 왜

- 빈 칸 안내 세 줄(「새 메모를 만드세요」, 보조 문구, 「새 메모」 버튼)이 칸 높이 전체에 1/6·1/2·5/6 지점으로 흩어져 한 덩어리로 읽히지 않는다. 원인은 `.editor-placeholder` 가 `inset: 0` 의 grid 이고 자식마다 암시적 행이 생겨 남는 높이를 나눠 갖기 때문이다. 같은 자리를 쓰는 「열 수 없음」 류 문제 화면도 문구와 버튼이 1/4·3/4 로 벌어진다.
- 편집기에 줄번호가 없다.
- 설정 화면은 모달 한 장에 워크스페이스·테마·확장이 세로로 이어져 있고, 편집기 설정은 하나도 없다.
- 단축키는 메뉴에 박혀 있어 바꿀 수 없다.

## 목표

1. 빈 칸 안내와 문제 화면이 칸 가운데에 **한 묶음**으로 보인다.
2. 편집기에 줄번호가 보이고, 설정에서 끌 수 있다.
3. 설정 화면이 성격별 구역으로 나뉘고, 한 번에 한 구역만 보인다.
4. 앱 명령의 단축키를 설정에서 바꾸거나 지우거나 새로 붙일 수 있고, 바꾼 단축키가 메뉴와 화면 문구에 바로 반영된다.

## 하지 않는 것

- 편집기 안 명령(CodeMirror keymap: ⌘F, ⌘D, ⌘L, ⌘/, ⇧⌘D 등)의 단축키 바꾸기. 목록에는 「편집기(고정)」 로 보여 충돌 검사에만 쓴다.
- 시스템 편집 메뉴(⌘Z, ⇧⌘Z, ⌘X, ⌘C, ⌘V, ⌘A)와 전체 화면·최소화 같은 macOS 기본 항목 바꾸기. ⌘X·⌘C·⌘V·⌘A 와 macOS 기본 항목은 Tauri 의 predefined 항목이라 바꿀 수 없다. 실행 취소(⌘Z)·실행 복귀(⇧⌘Z)는 앱 항목(id `undo`·`redo`)이지만 키는 고정이다 — 시스템 항목은 WebKit 의 되돌리기 기록만 거슬러 가서 편집기가 낸 변경(모두 바꾸기 등)을 되돌리지 못한다(검색 띠 설계 「바꾸기」). 녹음 중에는 설정…·tote 종료처럼 이 둘의 키도 뗀다.
- ⌃1~⌃9 워크스페이스 전환 바꾸기(고정으로 보인다).
- 설정을 별도 창으로 띄우기. 지금처럼 모달이다.
- 대용량 뷰어(`large-text`)의 줄번호·글꼴. 대용량 뷰어는 줄 높이 20px 고정 가상 스크롤이라 지금 값(14px, 기본 글꼴)에 **묶어 둔다**(설계자 판단). 지금은 편집기와 같은 `--editor-size`·`--editor-font` 를 쓰므로 대용량 뷰어용 변수(`--large-text-font`·`--large-text-size`)를 따로 둬서 편집기 글꼴 설정이 그쪽으로 새지 않게 했다.
- 단축키 설정 내보내기·가져오기, 키 두 번 누르기(chord).

## 하면 실패인 것

- 단축키를 바꾸는 중에 누른 키가 그 명령을 실제로 실행한다(⌘N 을 녹음하려다 새 메모가 생김).
- 저장된 단축키 하나가 잘못돼 있어 다른 단축키나 설정 전체가 기본값으로 돌아간다.
- 설정 화면을 다시 열 수 없게 된다(설정 단축키를 지웠는데 메뉴로도 못 엶).
- 바꾼 단축키가 화면 문구(「⌘N 을 누르세요」)와 다르다.
- 빈 칸 안내를 고치다 기존 e2e 셀렉터(`.editor-placeholder p` 와 그 순서)가 깨진다.

## 1. 빈 칸 안내와 문제 화면

- `showPlaceholder` 가 만드는 자식(`<p>` 제목, 선택적 `<p class="editor-placeholder-hint">`, 선택적 `<button>`)을 **한 묶음 요소로 감싼다**(설계자 판단: `div.editor-placeholder-body`, 세로 flex, 간격 8px 안팎). `.editor-placeholder` 는 그 묶음 하나를 가운데에 놓는다. `<p>` 의 수와 순서는 그대로다.
- 제목은 본문 색(`--fg`)·15px 안팎, 보조 문구는 `--muted`·12px, 빈 칸의 「새 메모」 버튼은 `primary`(설계자 판단). 문제 화면의 「텍스트로 열기」 는 지금처럼 기본 버튼.
- 보조 문구와 미리보기 안내(`PREVIEW_HINT`)에 들어 있는 단축키 표기(⌘N, ⇧⌘V)는 **지금 그 명령에 걸린 단축키**로 만든다. 단축키가 없으면 단축키 부분을 뺀 문장을 쓴다(예: 「메모 목록에서 메모를 여세요」). 창이 아직 표를 읽지 못했으면 보조 문구를 아예 그리지 않는다(제목과 버튼만). 그래서 기본값 사용자는 시작할 때 다른 문구를 잠깐 보지 않는다. 첫 표 읽기가 실패하면 다음 설정 변경까지 보조 문구가 비어 있다(오류는 상태 표시줄에 보인다). 표기는 macOS 기호(⌃⌥⇧⌘ 순서, 글자는 대문자).

## 2. 줄번호와 편집기 설정

- CodeMirror `lineNumbers()` 와 `highlightActiveLineGutter()` 를 새 Compartment 로 넣는다. 기본은 **켬**(사용자가 「줄번호 표시」 를 요청했으므로).
- 거터 색은 테마 변수로 칠한다: 배경은 편집기 배경(`--bg`)과 같게, 숫자는 `--line-number`(없으면 `--muted`), 활성 줄 숫자는 `--line-number-active`(없으면 `--fg`). VS Code 테마 매핑에 `editorLineNumber.foreground`·`editorLineNumber.activeForeground` 를 더한다(설계자 판단). 거터와 본문 사이에 얇은 경계는 두지 않는다.
- 같은 「편집기」 구역에 **글꼴 크기**(11~24, 기본 14)와 **글꼴**(자유 입력, 비우면 기본 글꼴)를 더한다(설계자 판단: 줄번호를 켜면 자연스럽게 찾는 항목이고, 지금은 CSS 변수로만 정해져 있다). 값은 루트의 `--editor-size`·`--editor-font`(편집기 글꼴을 쓰는 다른 화면용)와 편집기 상태의 글꼴 테마(`fontEffect`, `src/editor/setup.ts`) 두 곳에 반영한다. 편집기는 테마로 받아야 한다: CodeMirror 는 테마가 바뀌거나 다시 그릴 때만 줄 높이를 다시 재는데, 편집기 내용 칸은 글꼴과 상관없이 칸 높이라서 CSS 변수만 바꾸면 줄번호가 옛 줄 높이에 남는다(창 크기를 바꿀 때까지).
- 글꼴 칸의 값(이름 하나나 쉼표 목록)은 그 뒤에 기본 고정폭 목록(`--large-text-font`)을 붙여 쓴다(`src/app/editor-font.ts` `editorFontStack`). 그래서 설치되지 않은 글꼴은 브라우저 기본(세리프)이 아니라 기본 고정폭으로 떨어진다. CSS 가 따옴표 없이 읽지 못하는 이름(`3270 Nope`, 따옴표·세미콜론이 든 것)은 따옴표로 감싸 한 글꼴 이름으로 읽힌다 — 선언 전체가 무효가 되어 기본으로 떨어지는 일이 없다. 따옴표 안의 줄바꿈·캐리지 리턴·폼 피드(손으로 고친 settings.json 에만 있을 수 있다)는 CSS 이스케이프(`\a ` 등)로 쓴다. 그대로 두면 CSS 문자열이 끝나 편집기 테마 규칙 전체가 버려지고 글꼴 크기까지 기본(13px)으로 떨어진다.
- 각 탭이 자기 `EditorState` 를 가지므로 설정이 바뀌면 **보이지 않는 탭의 상태까지** 다시 설정한다(언어 재설정과 같은 방식).
- 설정이 바뀌면 열린 모든 창에 바로 반영된다(기존 `tote://config` 경로).

## 3. 설정 화면

- 모달은 그대로 두고, **왼쪽에 구역 목록, 오른쪽에 그 구역 내용**인 두 칸 배치로 바꾼다(설계자 판단: macOS 설정·VS Code 설정과 같은 모양). 구역은 이 순서다.
  1. **일반**: 워크스페이스 루트.
  2. **편집기**: 줄번호, 글꼴 크기, 글꼴.
  3. **모양**: 라이트 테마, 다크 테마.
  4. **단축키**: 아래 4절.
  5. **확장**: 설치·목록·활성·제거·문제·우선순위.
- 처음 열면 「일반」. 같은 창에서 다시 열면 마지막에 본 구역(앱을 다시 켜면 잊어도 된다).
- 저장 방식은 하나로 맞춘다: **바꾸는 즉시 저장**. 워크스페이스 루트만 경로라서 입력 중에 저장하지 않고 「적용」(기본 버튼, primary 아님)이나 Enter 로 저장한다. 그래서 모달 안 primary 버튼은 「닫기」 하나다.
- 접근성: 모달에 `aria-modal="true"`·`aria-labelledby`, 구역 목록은 `role="tablist"`/`tab`/`tabpanel` 과 ↑↓ 이동, 입력마다 `<label>`, 오류 문구는 `aria-live="polite"`. 다른 모달(`dialogs.ts`, 버전 창)에도 `aria-modal`·`aria-labelledby` 를 붙인다(설계자 판단: 같은 결함이다). 구현은 `modal()` 한 곳이다: 모든 모달에 `aria-modal` 을 붙이고, `aria-labelledby` 가 없으면 첫 제목·문단을 이름으로 삼는다. 처음 포커스는 `data-autofocus` 가 있으면 그것이다(설정 화면은 고른 구역의 탭).
- 다크 기본 테마에서 primary 버튼(흰 글자 위 `#4c9aff`, 대비 약 2.8:1)을 4.5:1 이상으로 올렸다. 방법: 글자색 변수 `--accent-fg` 를 두고 다크에서 `#10151c`(대비 6.43:1)로 한다. 라이트는 흰 글자 그대로(5.19:1). 이 변수는 `button.primary` 전체에 걸리므로 빈 칸의 「새 메모」뿐 아니라 확인 대화상자·버전 창·설정 「닫기」도 다크에서 어두운 글자가 된다. 테마가 `--accent` 를 덮으면 `--accent-fg` 도 함께 정한다(`src/theme/vscode-theme.ts` `themeVariables`): `--accent` 가 `button.background` 에서 오고 `button.foreground` 가 있으면 그 색, `--accent` 가 다른 키(`focusBorder`·`textLink.foreground`)에서 오거나 `button.foreground` 가 없으면 tote 의 두 글자색(`#ffffff`·`#10151c`) 중 그 `--accent` 위에서 대비가 큰 쪽이다. 반투명한 `--accent` 는 `--bg` 위에 섞어 재고, 색을 읽지 못하면 그 모양의 기본 글자색을 쓴다. 테마가 `--accent` 를 주지 않으면 `button.foreground` 가 있어도 기본 글자색을 그대로 둔다.
- 모달 크기는 `width: min(760px, 90vw)`, `height: min(560px, 85vh)` 로 고정한다(옛 `min(720px, 90vw)`, `max-height: 85vh`). 구역 목록은 왼쪽 140px 이고, 구역을 바꿔도 모달 크기가 출렁이지 않는다. 스크롤은 오른쪽 패널만 한다.
- 글꼴 크기는 반올림해 11~24 로 묶은 값을 칸에 보인 뒤 저장한다. 비었거나 숫자가 아니면 저장된 값으로 되돌리고 보내지 않는다. 저장이 실패하면 칸은 이전 값으로 돌아가고, 같은 값을 다시 입력하면 다시 저장을 시도한다.

## 4. 단축키 설정

### 무엇을 바꿀 수 있나

- **앱 명령**: 메뉴에 id 가 있는 모든 사용자 정의 메뉴 항목(새 메모, 새 창, 파일 열기, 저장, 가져오기, 이름 바꾸기, 이전 버전, 백업 폴더 열기, 탭 닫기, 창 닫기, 워크스페이스 열기, 새 워크스페이스, 워크스페이스 검색, 오른쪽·아래로 나누기, 네 방향 칸 이동, 다음·이전 탭, 미리보기 전환, 탭을 새 창으로 옮기기, 셸 명령 설치). 지금 단축키가 없는 명령에도 붙일 수 있다.
- **설정…(⌘,)은 고정**이다(설계자 판단: 설정을 다시 열 길을 잃지 않게).
- **tote 종료(⌘Q)도 고정**이다(종료할 길을 단축키에서 잃지 않게 — 사용자 결정 2026-10-21). 메뉴 항목 id `quit` 은 그대로이고 앱 명령이 아니라 고정 항목이다. 예전 settings.json 의 `quit` 항목은 모르는 id 로 버려진다.
- **고정 단축키**(설계자 판단)는 다섯이다: 설정…(⌘,), tote 종료(⌘Q), ⌃1~⌃9, 시스템 편집 메뉴(⌘Z, ⇧⌘Z, ⌘X, ⌘C, ⌘V, ⌘A), macOS 기본 메뉴 항목(⌘H 숨기기, ⌥⌘H 다른 앱 숨기기, ⌘M 최소화, ⌃⌘F 전체 화면). 앱 명령에 고정 단축키를 걸면 **거절**한다. 목록 맨 아래 「고정」 묶음에 회색으로 보인다.
- **편집기 단축키는 고정이 아니다**(설계자 판단). 편집기 키맵(`zedKeymap`, CodeMirror 의 close-brackets·default·search·history 키맵)을 실행 중에 읽어 만든 표와 겹치면 **허용하되 경고**한다: 그 줄에 「편집기의 〈명령〉 을 가립니다」. 겹치는 키는 **메뉴가 이긴다.** 실제 앱(WKWebView)은 키를 페이지에 먼저 주고 페이지가 처리하지 않을 때만 메뉴로 넘기므로(실측: 설정 스모크 B-3 에서 ⌘L 을 편집기의 `selectLine` 이 받았다) 그대로 두면 편집기가 이긴다. 그래서 페이지 쪽에서 메뉴를 이기게 한다: 사용자의 단축키 가운데 편집기 키와 겹치는 것을 편집기 키맵보다 앞(`Prec.highest`)에 그 키 이름 그대로 걸고, 누르면 그 명령을 메뉴 항목을 고른 것과 같은 길(`run_menu_command` → `menu::run_command`, 메뉴 이벤트와 같은 분기에 그 창을 넘긴다)로 실행하고 키를 막는다(`src/shortcuts/keys.ts` `menuKeymap`). 범위는 편집기와 검색 띠 입력칸(`editor search-panel`)이라 검색 띠의 ⌘G·⌘↩ 등도 메뉴에 진다. 단축키 표가 바뀌면 보이지 않는 탭의 상태까지 다시 건다(줄번호와 같은 방식). 편집기 키와 겹치지 않는 키는 페이지가 처리하지 않으므로 메뉴가 그대로 받는다. 이유: 지금 기본값 가운데 ⇧⌘\(아래로 나누기)·⌥⌘↑↓(칸 이동)가 이미 편집기 키와 겹치고, ⌃+글자 대부분이 macOS 의 emacs 식 편집기 키라서, 거절로 하면 기본값으로 되돌리기조차 막힌다. 표는 키맵에서 꺼내므로 키맵이 바뀌어도 낡지 않는다. 편집기 단축키는 목록에 따로 보이지 않고 경고로만 드러난다.
  - 경고는 녹음한 직후만이 아니라 **지금 단축키가 편집기 키와 겹치는 줄이면 언제나** 보인다(표를 다시 읽어도 사라지지 않는다). 기본값에서 세 줄에 뜬다: 아래로 나누기(⇧⌘\ → `cursorMatchingBracket`), 위쪽 칸으로(⌥⌘↑ → `addCursorAbove`), 아래쪽 칸으로(⌥⌘↓ → `addCursorBelow`). 방금 저장한 줄의 경고만 `role=status` 로 읽힌다.
  - 〈명령〉 은 키맵 함수의 이름이다. 표에 없는 함수(키맵의 모든 명령은 표에 있으므로 사실상 나오지 않는다)이면 「편집기 단축키를 가립니다」 라고만 쓴다(내부 이름은 「편집기 명령」).
  - 이름은 `Function.name` 이 아니라 키맵에 걸린 명령만 명시 import 한 이름 표(`src/shortcuts/command-names.ts`)에서 얻는다. 배포 빌드가 함수 이름을 압축해도 import 이름은 남는다. 모든 바인딩이 이름을 얻는다는 단위 시험(`src/shortcuts/command-names.test.ts`)이 표에서 빠진 명령을 잡는다.

### 화면

- 명령마다 한 줄: 이름과 그 오른쪽에 작게 메뉴 이름, 지금 단축키(없으면 「없음」), 「기본값」(바뀐 줄은 「기본값 ⌘N」), 행 끝에 「되돌리기」(기본값과 다를 때만). 목록은 4열 grid 이고 줄이 `subgrid` 로 열을 함께 써서 「되돌리기」 가 없는 줄도 열이 맞는다. 알림은 줄 아래 전체 폭이다.
- 맨 위 검색 칸으로 명령 이름·단축키 표기로 거른다. 이름은 부분 일치, 단축키는 표기 전체가 같아야 맞는다(「⌘N」 이 ⌥⌘N 에 걸리지 않는다). 보조키 기호만 치면 그 기호를 모두 가진 단축키를 보인다. 맞는 것이 없으면 「맞는 명령이 없습니다」. 구역 하단에 「모두 기본값으로」(확인 대화상자를 거친다).
- 단축키 칸을 누르면 **녹음** 상태가 된다: 「키를 누르세요」 가 보이고, 다음 키 조합을 받는다.
  - 보조키 없는 글자·숫자는 받지 않는다(⌘·⌃·⌥ 중 하나는 있어야 한다. F1~F12 는 보조키 없이 허용). ⇧ 만 붙은 키는 F 키도 받지 않는다(Rust `recordable` 과 같은 규칙). 글자는 `event.code` 로 읽어 한글 입력기나 ⌥ 변형 글자에도 흔들리지 않는다.
  - Insert, Help, 키패드 ↩(「키패드 ↩」 로 보인다)도 녹음한다. ISO 자판의 §(`IntlBackslash`)는 muda 가 macOS 메뉴에 걸지 못해 녹음에서 반응하지 않고, settings.json 에 손으로 쓴 그 항목은 버려진다.
  - **키패드의 나머지 키는 키패드 키로 녹음하지 않는다.** muda 는 항목의 modifier mask 에 `NSEventModifierFlagNumericPad` 를 넣지만 AppKit 은 키를 맞출 때 그 플래그를 보지 않는다. 그래서 키패드 1 로 건 항목은 메인 줄 ⌘1 에도 실행되고(설정 스모크 B-8, 두 번 재현), 메인 줄 ⌘1 로 건 항목도 키패드 1 에 실행된다(`src-tauri/tests/menu_keypad.rs`). 같은 키를 쓰는 두 항목이 있으면 메뉴 순서로 앞의 것만 실행된다.
    - 키패드 0~9·−·.·÷·= 는 메인 줄의 같은 글자 키로 녹음한다(⌘키패드 1 → 「⌘1」). 양쪽 다 실행되는 것이 실제 동작이므로 그 키 이름이 맞고, 메인 줄 키를 쓰는 다른 명령과는 같은 키로 충돌 검사를 받는다(옛 동작은 「⌘키패드 1」 로 저장돼 ⌘1 을 쓰는 명령과 조용히 겹쳤다).
    - 키패드 ＋·× 는 녹음에서 반응하지 않는다. 그 항목은 메인 줄 ⇧⌘=·⇧⌘8 에도 실행되는데, 메인 줄 쪽(⇧⌘=)으로 걸면 키패드 ＋ 로는 실행되지 않는다. 어느 이름으로 걸어도 동작을 말하지 못한다.
    - settings.json 의 키패드 항목(손으로 쓴 것, 이 규칙 전에 녹음한 것)은 읽을 때 위의 짝 키로 옮긴다(`CmdOrCtrl+Numpad1` → `CmdOrCtrl+1`, `from_keypad`, `src-tauri/src/shortcuts.rs`). 그 항목은 원래 메인 줄 키에도 실행됐으므로 옮겨도 동작이 같다. 옮긴 키가 다른 명령의 키와 겹치면 다른 재정의의 겹침과 같이 정한다(기본값과는 기본값이, 두 재정의 사이에서는 메뉴 순서로 앞의 것이 남는다). 짝이 없는 키패드 ＋·× 항목은 버려지고 그 명령은 기본값으로 돌아간다(`recordable`). ↩ 는 그대로다. 화면이 보내는 바꿈에는 키패드 키가 들지 않으므로, 바꿈에 든 키패드 항목(↩ 말고)은 거절한다.
    - 메뉴 쪽에서 가르는 길(AppKit 메뉴 대리자 `menuHasKeyEquivalent:forEvent:target:action:` 로 키 맞추기를 대신하는 것)은 muda 가 만든 메뉴의 대리자를 바꿔야 해서 고르지 않았다. 숫자패드 녹음은 사용자 결정이 아니라 틈 메우기 계획 Task 5 의 결정이었다.
  - Esc 는 녹음 취소(첫 Esc 가 녹음을 끝내고 두 번째 Esc 가 설정 화면을 닫는다), Backspace·Delete 는 「단축키 없음」 으로 저장.
  - 다른 곳을 누르거나(바깥 pointerdown) 창이 포커스를 잃거나 페이지가 사라지거나 다른 창이 단축키 표를 바꾸면 취소. 표가 바뀌지 않는 설정 변경(예: 다른 창의 테마)은 녹음을 끊지 않는다.
  - 녹음 중에는 window capture 에서 keydown·keyup 을 막아(`preventDefault`·`stopImmediatePropagation`) 편집기·⌃1~⌃9·모달 Esc 가 그 키를 받지 않는다.
- 충돌하면 저장하지 않고 그 줄 아래에 이유를 보인다: 다른 앱 명령과 같으면 「〈명령 이름〉 에 이미 쓰고 있습니다」 와 함께 「바꾸기」(상대 명령의 단축키를 지우고 이쪽에 건다), 고정 단축키와 같으면 「〈이름〉 에 고정된 단축키입니다」(바꾸기 없음). 편집기 키와 겹치는 것은 저장하고 경고만 남긴다(위). 지금 값과 같은 키를 녹음하면 저장하지 않는다. 「바꾸기」 는 `{상대: null, 이쪽: 새 키}` 를 한 번에 저장하고, 저장 맵은 기본값과 같아진 명령을 뺀 전체다. 저장이 실패하면 그 줄 아래에 이유를 보이고 표는 그대로 두므로 같은 키로 다시 시도할 수 있다. 「모두 기본값으로」 의 실패는 구역 위 문구로 보인다. 저장은 마지막으로 읽은 저장 맵을 `shortcutsExpected` 로 함께 보내고, 그 사이 다른 창이 맵을 바꿨으면 백엔드가 패치 전체를 거절(`bad-request` 「shortcuts changed」)해 표를 다시 읽고 「다른 창에서 단축키가 바뀌어 다시 읽었습니다. 다시 해 주세요」 를 보인다.

### 녹음 중에 명령이 실행되지 않게

녹음 중 키를 막는 것은 녹음기다: window capture 에서 keydown 을 `preventDefault` 하고, 실제 앱은 키를 웹뷰에 먼저 주므로 막힌 키는 메뉴로 가지 않는다(실측: 설정 스모크 B-1·B-2·A-11 에서 메뉴 키가 실제로 떼어지지 않았는데도 ⌘N·⌘Q·⌘M·⌘H 가 녹음 중 아무것도 실행하지 않았다). 그래도 **녹음을 시작할 때 백엔드에 알려 모든 사용자 정의 메뉴 항목의 단축키를 잠시 떼고, 끝날 때 되돌리는 것은 남긴다**(설계자 판단: 웹뷰가 먼저 받는다는 것은 위 다섯 키로 잰 것이지 WebKit 이 모든 키·모든 순간에 보장한다고 확인한 것이 아니다. 떼기는 이제 실제로 동작하고 값이 싸서, 웹뷰를 거치지 않는 키가 있을 때의 안전망으로 둔다). 녹음을 연 창이 닫히거나 새로 고쳐지거나 앱이 포커스를 잃으면 되돌린다. 되돌리기를 잊는 경로가 없어야 한다. 구현: 메뉴 단축키는 메인 스레드에서만 만지고(`MenuShortcuts` 가 만든 스레드를 `debug_assert` 로 확인), 녹음 창이 새로 고쳐지면(`on_page_load`) 되돌린다. 단축키를 바꾸거나 두 창이 연달아 저장해도 메뉴는 메인 스레드 클로저 안에서 읽은 마지막 저장과 같다(`follow_settings`).

macOS 기본 메뉴 항목(⌘H, ⌥⌘H, ⌘M, ⌃⌘F)은 Tauri predefined 라 뗄 수 없다. 이 키는 녹음기의 `preventDefault` 만이 막는다(실측: 설정 스모크 B-2 에서 녹음 중 ⌘M·⌘H 가 창을 최소화하거나 숨기지 않았다). 웹뷰를 거치지 않는 경우가 있다면 창이 숨거나 최소화될 수 있다(설계자 판단: 받아들인다. 어차피 고정이라 거절될 키이고, 글을 잃거나 되돌릴 수 없는 동작이 아니다). 시스템 편집 단축키는 녹음 칸이 글 입력 칸이 아니라서 영향이 없다. 이 한계는 화면 확인 목록에 적는다. 녹음을 끝낸 조합의 주 키 keyup 은 그 키가 놓일 때까지 window capture 에서 막는다(수식키 keyup 은 막지 않는다). WebKit 은 ⌘ 를 누른 채 누른 키의 keyup 을 보내지 않으므로 ⌘ keyup 이 오면, 그리고 창이 포커스를 잃거나 설정 화면이 닫히면 목록을 비운다.

### 저장과 적용

- `settings.json` 에 `shortcuts` 필드를 더한다: 명령 id → 단축키 문자열 또는 `null`(단축키 없음). **기본값과 다른 것만** 적는다. 키가 없으면 기본값.
- 문자열은 Tauri accelerator 표기(`CmdOrCtrl+Shift+N` 꼴)로 저장한다.
- 읽을 때 **항목마다** 검사한다: 모르는 명령 id, 고정 명령 id, 파싱할 수 없는 문자열, 녹음 규칙(⌘·⌃·⌥ 중 하나 + 키, 또는 보조키 없는 F1~F12)에 맞지 않는 항목, 고정 단축키와 같은 항목, 다른 앱 명령의 결과 단축키와 겹치는 항목은 그 항목만 버리고 나머지는 살린다(겹칠 때는 기본값이 아니라 사용자가 적은 쪽을 버린다. 둘 다 사용자가 적었으면 명령 표(메뉴 순서)에서 뒤의 것을 버린다). 편집기 키와 겹치는 것은 버리지 않는다. 문자열도 `null` 도 아닌 값의 항목도 그 항목만 버린다. 필드 모양 자체가 틀리면 `shortcuts` 만 기본값으로 돌아간다(기존 `lenient` 방식). 버린 항목이 메모리에 남아 이후 모든 패치를 거절시키지 않도록 읽을 때(`shortcut_overrides`) 거른다.
- Tauri `set_accelerator` 는 파싱에 실패한 문자열을 오류 없이 「단축키 없음」 으로 만든다. 그래서 Rust 가 파싱을 먼저 확인하고, 실패하면 저장을 거절한다. TS 도 같은 규칙으로 미리 막는다.
- muda(0.20, 최신 0.21.2 도 같다)의 macOS `set_accelerator` 는 「단축키 없음」 을 받으면 `NSMenuItem` 의 키를 **지우지 않는다.** 그래서 메뉴 항목의 단축키를 떼는 모든 길(「없음」 저장, 「모두 기본값으로」 로 기본값이 없는 명령, 녹음 중 떼기)은 tauri 로 muda 의 기록을 맞춘 뒤 그 항목의 key equivalent 를 AppKit 에서 직접 비운다(`src-tauri/src/app/key_equivalents.rs`, 메뉴 막대의 하위 메뉴 제목과 항목 이름으로 찾는다). 메뉴에 거는 순간 파싱되지 않는 문자열도 같은 길로 떼어, 옛 키가 남지 않는다.
- 앱을 켤 때 저장된 단축키로 메뉴를 만들고, 설정이 바뀌면 이미 만든 메뉴 항목의 단축키를 바꾼다. 메뉴는 앱에 하나이므로 모든 창에 함께 적용된다.
- 화면 문구(빈 칸 보조 문구, 미리보기 안내)와 설정 화면의 표기는 같은 출처(현재 단축키 표)에서 만든다.

## 시험이 보여야 하는 것

- 빈 칸 안내 세 요소가 칸 가운데의 한 묶음 안에 있고, 기존 `.editor-placeholder p` 셀렉터와 순서가 그대로다.
- 줄번호를 끄고 켜면 보이는 탭과 숨은 탭 모두 바뀌고, 다른 창에도 퍼진다.
- 설정 구역을 오가도 저장된 값이 유지되고, 각 구역의 기존 시험(루트·테마·확장)이 새 배치에서 그대로 통과한다.
- 단축키: 녹음·지우기·되돌리기·모두 기본값·충돌(앱 명령끼리는 바꾸기, 고정과는 거절)·잘못된 저장 항목 하나만 버려짐·녹음 중 메뉴 단축키를 떼고 되돌림(Rust 시험)·바꾼 단축키가 빈 칸 문구에 반영됨.
- 편집기나 검색 띠 입력칸에 포커스를 둔 채 편집기 키와 겹치는 앱 단축키를 누르면 편집기 명령이 아니라 그 앱 명령이 실행되고(가짜 백엔드의 `menuCommandRuns`), 앱 단축키가 없는 편집기 키는 편집기가 받고, 표가 바뀌면 보이지 않던 탭까지 따른다(`tests/e2e/shortcuts.spec.ts`). 이 시험은 페이지가 키를 넘기는지를 본다. 넘긴 명령이 실제 메뉴와 같은 일을 하는지는 Rust 의 같은 분기(`menu::run`)이고, 실제 앱에서 키가 페이지에 먼저 온다는 전제는 화면 확인이다.
- e2e 는 메뉴 단축키를 실제로 누르지 못한다(가짜 백엔드가 메뉴 id 를 직접 보낸다). 실제 메뉴에 단축키가 걸리는지는 Rust 시험과 나중 화면 확인으로 본다. `menu.rs` 의 시험은 가짜 항목에 무엇을 거는지만 본다. 떼어 낸 키가 실제 `NSMenuItem` 에서 사라지는지는 AppKit 메뉴를 메인 스레드에서 만드는 `src-tauri/tests/menu_key_equivalents.rs`(시험 하네스 없이 도는 시험)가 본다. 그 시험은 muda 가 스스로 키를 지우게 되면 실패해 우회를 걷을 때를 알린다. tauri `MenuItem` 에서 그 우회로 이어지는 연결(`MenuEntry::clear`)은 시험이 닿지 않아 화면 확인으로 본다.

## 빌더에게 맡기는 것

- 구역 목록·단축키 행의 세부 모양, 간격, 아이콘 유무.
- 다크 primary 대비를 올리는 구체적 방법.
- 단축키 표기 함수의 위치와 이름, 메뉴 항목 핸들을 보관할 자리.
- 글꼴 입력 칸의 검증 정도(존재하지 않는 글꼴은 기본 고정폭으로 떨어지므로 막지 않아도 된다).

## 알려진 한계

- 녹음 중 ⌘H·⌘M 은 녹음기만이 막는다. 키가 웹뷰를 거치지 않으면 창을 숨기거나 최소화할 수 있다(위 「녹음 중에 명령이 실행되지 않게」).
- 편집기·검색 띠 밖의 글 입력칸(메모 목록 거르기, 워크스페이스 검색, 설정의 입력칸, 대화상자)은 메뉴가 이기게 하지 않았다. 그 칸이 글 편집 키(⌘←·⌥← 류)로 쓰는 키를 사용자가 앱 단축키로 걸면 어느 쪽이 받는지는 화면 확인 전이다. 기본값에는 그런 키가 없다.
- 단축키 줄의 `subgrid` 는 WebKit 16(macOS 13)부터 된다. 그보다 낮은 macOS 에서는 줄이 한 열로 무너진다. `tauri.conf.json` 이 최소 macOS 13(WebKit 16)을 정하므로 subgrid 를 그대로 쓴다.
- 편집기 키 이름은 키맵에 걸린 명령만 명시 import 한 이름 표(`src/shortcuts/command-names.ts`)에서 얻는다. 키맵에 명령을 더하면 표에도 더해야 하고, 빠뜨리면 단위 시험이 실패한다.
- TS 파서는 muda 보다 아는 키 이름이 적다. 녹음으로 만들 수 있는 키는 모두 읽지만, settings.json 을 손으로 고친 값은 Rust 만 아는 이름이 있을 수 있다(표기가 원문 그대로 나온다).
