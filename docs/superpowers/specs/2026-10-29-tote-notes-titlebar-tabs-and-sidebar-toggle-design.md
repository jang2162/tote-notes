# tote-notes 제목 줄 탭·사이드바 접기 설계

2026-10-29. 사용자 요청: 「macOS 에서 탭을 닫기 버튼이랑 같은 라인에 배치해줘」, 이어서 「사이드바를 접고 펼 수 있는 요소도 추가하고 싶어」. 사용자가 본보기로 든 것은 Orca(사이드바 윗줄에 신호등 버튼·앱 이름, 같은 줄 오른쪽에 탭)와 Chrome(신호등 바로 뒤에 탭)이다. 웹 시안 두 개 중 **A** 를 골랐다. 사용자가 정한 것은 그대로 적고, 그 밖의 결정은 **설계자 판단**으로 표시한다.

## 왜

- 지금 창은 macOS 기본 제목 표시줄(신호등 버튼과 창 제목만 있는 줄) 아래에 사이드바와 탭 줄이 있다. 제목 표시줄 한 줄이 아무 일도 하지 않으면서 세로 공간을 먹는다.
- 사이드바는 늘 240px 를 차지하고 숨길 방법이 없다. 창이 좁거나 칸을 좌우로 나누면 편집 영역이 먼저 좁아진다.

## 목표

1. macOS 에서 **창 맨 윗줄에 신호등 버튼과 탭이 함께** 놓인다. 기본 제목 표시줄은 보이지 않는다.
2. 사이드바 윗줄에 신호등 버튼, 그 오른쪽에 **앱 이름 「Tote Notes」**, 줄 오른쪽 끝에 **사이드바 접기 버튼**이 있다(사용자 결정: 앱 이름 표시, 시안 A).
3. 사이드바를 **접고 펼 수 있다.** 버튼, 메뉴, 단축키 **⌘B**(사용자 결정) 세 길이 있다.
4. 창의 빈 윗부분을 끌어 창을 옮길 수 있다.

## 하지 않는 것

- 다른 OS 의 창 틀 바꾸기. macOS 가 아니면 기본 제목 표시줄을 그대로 쓴다.
- 사이드바 너비 조절, 아이콘만 남는 좁은 사이드바(rail). 접으면 완전히 사라진다.
- 신호등 버튼 모양·크기 바꾸기. 시스템 버튼을 그대로 쓰고 위치만 맞춘다.
- 창 제목 문자열 바꾸기. 제목은 화면에 안 보여도 지금처럼 정한다(창 메뉴·Mission Control·손쉬운 사용이 읽는다).

## 실패로 치는 것

- 탭 끌기(칸 사이 옮기기, 창 밖으로 떼어 내기)가 창 끌기로 바뀌거나, 창 끌기가 탭 끌기를 막는다.
- 탭 줄 빈 곳 두 번 누르기가 새 탭 대신 창 확대를 한다.
- 신호등 버튼이 탭·앱 이름·워크스페이스 고르개를 덮는다.
- 사이드바를 접었는데 키보드 포커스가 보이지 않는 사이드바 안에 남는다.
- 접은 상태가 다음 실행에서 펼친 상태로 돌아온다.
- macOS 가 아닌 곳(브라우저 미리보기 포함)에서 맨 윗줄에 신호등 자리만큼 빈칸이 생긴다.

## 창 틀 (macOS)

- 창을 만들 때(`src-tauri/src/app/windows.rs` 의 `WebviewWindowBuilder`) 제목 표시줄을 내용 위에 겹치는 방식으로 바꾸고 제목 글자를 숨긴다. Tauri 2 의 `title_bar_style(TitleBarStyle::Overlay)`·`hidden_title(true)` 가 그 자리다.
- 신호등 버튼은 **맨 윗줄의 세로 가운데**에 오게 위치를 준다(`traffic_light_position`). 가로 위치는 시스템 기본과 비슷하게 둔다(설계자 판단).
- 맨 윗줄 높이는 탭 줄 높이와 같다. 신호등이 가운데에 예쁘게 오도록 지금 탭 줄(위아래 6px 여백)보다 몇 px 키워도 된다(설계자 판단: 34~38px 안에서 만드는 사람이 정한다). 이 높이는 사이드바 윗줄과 탭 줄이 **함께** 쓰는 CSS 변수 하나로 둔다.
- 전체 화면에서는 신호등이 사라지지만 배치는 바꾸지 않는다(설계자 판단). 앱 이름과 접기 버튼은 그 자리에 그대로 있다.

## 맨 윗줄 배치

### 사이드바가 펼쳐져 있을 때 (시안 A)

```
[● ● ●  Tote Notes        ▯] [탭 1 ×][탭 2 ×][탭 3 ×]   (빈 곳)
[워크스페이스 고르개 ▾     ] [편집기                         ]
[제목 거르기               ] [                               ]
[메모 목록 …               ] [                               ]
```

- 사이드바 맨 위에 새 줄이 생긴다: 신호등 자리 → 「Tote Notes」(굵게) → 빈 곳 → 접기 버튼(오른쪽 끝). 배경은 `--sidebar-bg`, 아래 경계선은 탭 줄과 같은 `--border` 라서 두 줄이 한 줄로 이어져 보인다.
- 워크스페이스 고르개와 그 아래는 지금 그대로, 새 줄 바로 아래에서 시작한다.

### 사이드바를 접었을 때

```
[● ● ●  ▯ | 탭 1 ×][탭 2 ×][탭 3 ×]   (빈 곳)
[편집기                                       ]
```

- 사이드바 열이 0 이 되고, **왼쪽 맨 위 칸의 탭 줄 맨 앞**에 신호등 자리와 펼치기 버튼이 붙는다. 앱 이름은 접으면 보이지 않는다(시안 A 그대로).
- 이 앞머리는 탭이 아니다. 탭을 끌어 그 위에 놓으면 첫 탭 앞에 놓인다(지금 `indexAt` 이 첫 탭 왼쪽을 0 으로 읽는 대로).

### 칸을 나눴을 때

- 맨 윗줄에 닿은 칸(칸 사각형의 위쪽이 편집 영역 위쪽과 같은 칸)의 탭 줄만 이 줄에 있는 셈이다. 칸은 이미 편집 영역 맨 위부터 그려지므로 탭 줄 위치는 바뀌지 않는다.
- 아래쪽 칸의 탭 줄은 지금 그대로다. 창 끌기 대상도 아니다(창 가운데에서 창이 끌리면 안 된다).
- 접었을 때 앞머리(신호등 자리·펼치기 버튼)는 **왼쪽 맨 위 칸 하나**에만 붙는다. 칸 구조가 바뀌어(나누기·닫기·끌어 놓기) 왼쪽 맨 위 칸이 바뀌면 앞머리도 따라간다.

### macOS 가 아닐 때

- 기본 제목 표시줄이 있으므로 신호등 자리를 비우지 않는다. 사이드바 윗줄에는 「Tote Notes」 없이 접기 버튼만 오른쪽에 둔다(설계자 판단: 제목 표시줄이 이미 창 이름을 보여 준다). 접었을 때 앞머리에는 펼치기 버튼만 있다.
- 브라우저 미리보기와 e2e 는 macOS 가 아닌 쪽으로 본다. e2e 가 macOS 배치를 검사할 수 있게, macOS 배치는 `<html>` 의 클래스 같은 **한 스위치**로 켜지게 만든다(이름은 만드는 사람이 정한다). 앱은 플랫폼을 보고 그 스위치를 켠다.

## 창 끌기

- 끌리는 곳: 사이드바 윗줄의 빈 곳(신호등 자리·앱 이름 포함), 맨 윗줄 칸들의 탭 줄에서 탭이 없는 빈 곳, 접었을 때의 앞머리 빈 곳. 버튼과 탭 위에서는 끌리지 않는다.
- 사이드바 윗줄을 두 번 누르면 **창 확대(zoom)를 켜고 끈다**(설계자 판단). 시스템 설정의 「제목 막대 이중 클릭」(확대·최소화·아무것도 안 함)은 따르지 않는다 — Overlay 에서는 그 자리의 클릭을 웹뷰가 받아 네이티브 제목 막대가 처리하지 않고, Tauri 의 끌기 영역은 두 번 누르기에 늘 확대 토글을 붙인다. 설정까지 따르려면 `AppleActionOnDoubleClick` 을 읽는 네이티브 코드가 따로 든다.
- **탭 줄 빈 곳을 두 번 누르면 지금처럼 새 탭**이다. 창 확대가 함께 일어나면 안 된다. Tauri 의 `data-tauri-drag-region` 은 두 번 누르기에 창 최대화를 붙이므로, 탭 줄 빈 곳은 그 속성 대신 `mousedown` 에서 직접 `startDragging()` 을 부르는 식이 필요할 수 있다. 어느 쪽이든 두 동작이 겹치지 않는 것이 요구다.
- 탭 줄의 `dblclick` 은 지금 「`event.target` 이 탭 줄 자신일 때만」 이다. 창 끌기를 붙여도 이 판정이 그대로 서야 한다.
- 권한: 지금 `src-tauri/capabilities/default.json` 은 `core:default`·`dialog:allow-open` 뿐이다. 창 끌기에 필요한 권한(`core:window:allow-start-dragging`)을 넣는다. 창 확대를 앱 쪽에서 부르게 되면 그 권한도.

## 사이드바 접기

- **세 길:** 사이드바 윗줄 오른쪽 끝의 버튼(펼쳤을 때) / 탭 줄 앞머리의 버튼(접었을 때), 「보기」 메뉴의 새 명령, 단축키 **⌘B**(사용자 결정).
- 명령: `src-tauri/src/shortcuts.rs` 의 명령 표에 「보기」 메뉴 명령을 하나 더한다. id 는 `toggle-sidebar`, 메뉴 이름은 「사이드바 접기/펼치기」, 기본 키 `CmdOrCtrl+B`(설계자 판단: 이름은 창마다 상태가 달라 고정 문구로 둔다). 명령 표에 들어가므로 단축키 설정 화면에 저절로 나오고 바꿀 수 있다. 메뉴에서의 자리는 명령 표가 아니라 `src-tauri/src/app/menu.rs` 의 「보기」 메뉴 Slot 목록이 정하므로 거기에도 넣는다. 미리보기용 표(`src/backend/fake-shortcuts.ts`)도 맞춘다.
- **⌘B 를 이미 다른 명령에 걸어 둔 사람:** 지금 `shortcuts.rs` 는 다른 명령의 기본 키와 겹치는 저장된 단축키를 버린다. 새 기본 키 때문에 사람이 직접 걸어 둔 키가 소리 없이 사라지면 안 된다. **저장된 사람의 키가 이기고, `toggle-sidebar` 는 키 없이 시작한다**(설계자 판단). 메뉴와 버튼으로는 그대로 쓸 수 있고, 단축키 설정에서 다른 키를 걸 수 있다.
- ⌘B 는 지금 앱 명령·편집기 keymap 어디에도 걸려 있지 않다(`grep -rnE 'Mod-b|CmdOrCtrl\+B' src src-tauri/src` 로 다시 잴 수 있다. CodeMirror 기본 keymap 은 따로 본다).
- 버튼: 아이콘은 시안의 사각형+왼쪽 세로줄. `aria-label` 과 `title` 은 상태에 따라 「사이드바 접기」/「사이드바 펼치기」, `title` 에는 지금 걸린 단축키를 붙인다(단축키 표기는 설정 설계의 다른 화면 문구와 같은 방식). `aria-expanded` 로 상태를 알린다. 키 순서(Tab)에 넣을지는 다른 도구 버튼들의 관례를 따른다.
- 애니메이션: 사이드바 열 너비가 0.16초 동안 줄고 는다. `prefers-reduced-motion` 이면 바로 바뀐다(설계자 판단).
- **포커스:** 접을 때 포커스가 사이드바 안에 있으면 포커스된 칸의 편집기로 옮긴다. 접힌 사이드바의 내용은 키 순서와 손쉬운 사용 트리에서 빠진다(`hidden` 이나 `inert`).
- **자동으로 펼치기:** 접힌 채로 사이드바가 필요한 명령을 쓰면 먼저 펼친다. 지금 그런 명령은 워크스페이스 검색(⌘⇧F) 하나다. `Controller` 의 다른 `this.sidebar.show(...)` 자리는 성능 측정용이거나 사이드바가 보일 때만 일어나는 검색 패널의 Esc 다(`grep -n 'sidebar\.show' src/app/controller.ts` 로 다시 센다). 자동으로 펼친 사이드바는 **그대로 펼쳐 둔다** — 검색을 닫아도 다시 접지 않고, 펼친 상태가 세션에 저장된다(설계자 판단: 상태는 접힘·펼침 둘뿐이다).
- **업데이트 알림:** 업데이트를 찾았다는 표시는 사이드바 맨 아래 버튼(`Sidebar` 의 `update.el`)뿐이라 접으면 사라진다. 접힌 동안 업데이트가 있으면 **앞머리의 펼치기 버튼에 작은 점**을 찍고, 버튼 `title`·`aria-label` 에 「업데이트 있음」 을 덧붙인다(설계자 판단). 펼치면 지금의 버튼이 그대로 보인다.
- 최소 창 너비(480px)는 바꾸지 않는다.

## 세션

- 접힌 상태는 **창마다** 저장하고, 다음 실행에서 그 창이 접힌 채로 돌아온다(설계자 판단).
- 자리는 창 세션(`src/core/session.ts` 의 `WindowSession`)이다. `frame`·`layout`·`focusedPane` 옆에 선택 필드(예: `sidebarCollapsed`)를 더한다. 없거나 읽을 수 없으면 펼친 상태다. 그래서 옛 세션 파일이 그대로 읽힌다.
- 새 창(⌥⌘N), 탭을 떼어 낸 창, 워크스페이스를 처음 여는 창은 펼친 상태로 시작한다(설계자 판단).
- 「창마다」의 실제 뜻은 지금 세션이 창을 기억하는 단위와 같다: 세션 파일은 워크스페이스마다(`.tote/sessions/<device>.json`) 있고 그 안의 창 순서대로 돌아온다.
- 창이 워크스페이스를 바꿔도(⌃1~⌃9, 고르개) **그 창의 지금 접힌 상태를 유지한다**(설계자 판단: 창의 모양이지 워크스페이스의 것이 아니다). 지금 `AppCore::switch_window` 는 창의 layout 을 대상 워크스페이스에 저장된 첫 창의 것으로 통째로 바꾸고 페이지를 다시 읽으므로, 필드만 더하면 대상 쪽에 저장된 값이 이긴다. 전환 전의 값이 다시 읽기를 건너가 대상 워크스페이스의 세션에 쓰이게 한다. 무엇으로 건너가게 할지(백엔드가 layout 에 옮겨 적기, 창별 저장소 등)는 만드는 사람이 정한다.
- **실행할 때 깜빡이지 않는다.** 세션은 페이지가 뜬 뒤 비동기로 읽히므로(`restoreSession`) 그냥 두면 접힌 창이 펼친 채로 한 번 그려졌다가 접힌다. 접힌 상태는 **첫 그림 전에** 페이지에 닿아야 한다(설계자 판단). 방법(창을 만들 때 넘기기, 초기 스크립트, `workspace_info` 에 싣기 등)은 만드는 사람이 정한다. 애니메이션도 첫 그림에서는 돌지 않는다.

## 지켜야 할 제약

- 탭 줄 DOM(`.tabbar`, `.tab`, `.tab-label`, `.tab-close`)과 그 역할(role) 구조는 e2e 와 손쉬운 사용이 기대는 것이다. 앞머리는 `.tabbar` 의 탭 목록과 섞이지 않게 둔다(`TabBar.render` 가 `replaceChildren` 으로 탭을 다시 그리므로, 앞머리를 같은 부모에 두면 지워진다). `role=tablist` 안에 탭이 아닌 버튼이 들어가지 않게 한다.
- 탭 끌기는 포인터 이벤트(`TabBar.follow`)다. 창 끌기는 탭 위에서 시작되지 않아야 하고, 탭 끌기 중에 빈 곳으로 지나가도 창이 끌리면 안 된다.
- 테마 색은 VS Code 테마가 채우는 변수다(`src/styles.css` 머리). 새 색을 하드코딩하지 않는다. 새 변수가 테마에서 오지 않는 값이면 `src/theme/default-variables.test.ts` 의 `NOT_THEMED` 에도 넣는다.
- 기존 「창이 비활성일 때 첫 클릭도 페이지에 닿는다」(`accept_first_mouse`)는 그대로다.

## 만드는 사람에게 맡기는 것

- 맨 윗줄 높이의 정확한 값과 신호등 위치 좌표.
- macOS 스위치의 이름과, 플랫폼을 알아내는 방법.
- 창 끌기를 `data-tauri-drag-region` 으로 할지 `startDragging()` 으로 할지(두 번 누르기 요구만 지키면 된다).
- 앞머리를 왼쪽 맨 위 칸의 탭 줄에 넣는 방법(칸 DOM 안에 둘지, 편집 영역 위에 겹쳐 두고 그 칸 탭 줄에 왼쪽 여백을 줄지).
- 실제 앱(macOS)에서 신호등·창 끌기·두 번 누르기·전체 화면을 눈으로 확인하는 것. e2e 는 브라우저라 신호등과 창 끌기를 볼 수 없다.
