# tote-notes 메모 휴지통·줄번호 글자 크기 설계

2026-11-01. 사용자 요청 둘을 함께 다룬다. 사용자가 정한 것은 그대로 적고, 그 밖의 결정은 **설계자 판단**으로 표시한다.

## 요청 (사용자 원문)

- 「줄번호 폰트 사이즈 줄려주고 제목을 수정한 노트를 삭제 하는 방법이 없어 우측 노트 목록에 노트 삭제 옵션 추가해줘」
- 지우는 곳을 물었을 때: 「macOS 휴지통」 → 이어서 「그냥 .trash 만들고 앱에 서 삭제 메모 관리해줘. .trash 에서 지우면 휴지통 보내지 말고 아예 삭제. 휴지통 확인 하는 기능이랑 복구 하는 기능도 추가해줘」
- 확인 창: 「바로 삭제」(휴지통으로 옮길 때 묻지 않는다)
- 휴지통 화면 자리: 시안 셋(사이드바가 휴지통으로 바뀜 / 메모 목록 아래 접히는 구역 / 따로 뜨는 창) 가운데 **A, 사이드바가 휴지통으로 바뀜**
- 자동 비우기: 「기본 60일 설정해서 바꿀 수 있도록 해줘」
- 저장 방식: 아래 「접근」 의 **방법 1**

## 왜

메모를 지우는 길이 없다. 지금 앱이 메모를 지우는 것은 자동 제목인 빈 메모를 닫을 때뿐이다(`src/app/docs.ts` 의 `close`). 그래서 이름을 손으로 바꾼 메모는 Finder 로 워크스페이스 폴더(`~/.tote/<워크스페이스>`, Finder 에서 숨김)를 찾아가야만 지울 수 있다. 사용자는 지운 것을 되살릴 길도 원했다. macOS 휴지통은 숨겨진 폴더로 되돌려 놓기가 번거로워서, 앱 안에서 지운 메모를 보고 되살리는 휴지통을 고른 것이다.

## 목표

1. 메모 목록 행의 문맥 메뉴에서 메모를 **휴지통으로 옮긴다.** 묻지 않고 바로 옮긴다.
2. 휴지통은 워크스페이스 안의 `.trash` 폴더다. 앱 안에서 **지운 메모 목록을 보고, 내용을 보고, 복구하고, 영구 삭제하고, 비운다.**
3. 휴지통에서 지우면 macOS 휴지통을 거치지 않고 **파일이 없어진다.**
4. 휴지통에 **60일**(기본) 넘게 있던 메모는 저절로 영구 삭제된다. 기한은 설정에서 바꾸고 끌 수 있다.
5. 편집기 줄번호의 글자를 본문보다 작게 한다.

## 하지 않는 것

- macOS 휴지통으로 보내기(사용자 결정).
- 여러 메모를 골라 한꺼번에 휴지통으로 옮기기·복구하기.
- 워크스페이스 밖 파일(외부 파일 탭)을 휴지통으로 옮기기. 휴지통은 메모만 받는다.
- 휴지통으로 옮기기의 실행 취소(⌘Z). 복구가 그 몫이다.
- 휴지통 메모의 「버전」 창. 복구한 뒤에 본다(같은 ID 라 기록이 이어진다).
- 휴지통을 백업에 담기. 백업은 지금처럼 워크스페이스 바로 아래 메모만 담는다(`memo_files`). 지운 메모의 옛 내용은 그 전 백업에 남아 있다.
- 메뉴 막대·단축키로 휴지통으로 옮기기(설계자 판단: 요청은 목록 행에 관한 것이다. 넣는다면 다음 요청으로).

## 하면 실패인 것

- 휴지통으로 옮기거나 닫는 사이에 **저장 안 된 글을 조용히 잃는다.** 어느 창의 탭이든 마찬가지다.
- 휴지통의 메모가 메모 목록·목록 필터·워크스페이스 검색·빠른 열기에 나온다.
- 복구가 같은 이름의 다른 메모를 **덮어쓴다.**
- 자동 비우기가 기한이 안 된 메모를 지운다. 시계가 거꾸로 가거나 `trash.json` 을 읽지 못할 때도 마찬가지다 — 모를 때는 지우지 않는다.

## 접근

세 방법을 견줬고 사용자가 1 을 골랐다.

1. **`.trash` 안에 파일과 정보를 함께 둔다 (고름).** 메모마다 `.trash/<메모 ID>/<원래 파일 이름>` 으로 옮기고, 정보(원래 이름·지운 시각·자동 제목·언어·고정)는 `.trash/trash.json` 에 둔다. 메모 정보 `index.json` 에서는 항목을 뺀다. 메모 목록·파일 감시·백업은 워크스페이스 바로 아래의 점으로 시작하지 않는 파일만 보므로(`src-tauri/src/workspace/index.rs` `memo_files`, `src-tauri/src/backup/snapshot.rs` `fill`) `.trash` 안은 저절로 빠진다. 같은 이름을 여러 번 지워도 ID 폴더라 겹치지 않고, 복구하면 같은 ID 를 되찾아 버전 기록이 이어진다. 대가는 정보 파일 하나를 더 관리하는 것이다.
2. 파일만 `.trash` 로 옮기고 정보는 `index.json` 항목에 「지운 시각」 으로 표시한다. 정보 파일은 하나지만, `index.json` 은 「폴더 바로 아래 파일 = 메모」 를 전제로 맞춰지므로(`MemoIndex::reconcile`) 목록 맞추기·검색·백업·버전처럼 그것을 읽는 곳마다 지운 항목을 걸러야 하고, 하나를 빠뜨리면 지운 메모가 되살아난다.
3. macOS 휴지통(`NSFileManager` 또는 Finder AppleScript). 사용자가 앱 안 휴지통을 골라 버렸다.

## 저장

- 자리: `<워크스페이스>/.trash/`. 메모 하나는 `.trash/<id>/<옮길 때의 파일 이름>` 이다.
- 정보: `.trash/trash.json` (설계자 판단: 파일과 같은 자리에 두어 `.trash` 를 통째로 지우면 정보도 함께 사라진다).
  ```json
  {
    "version": 1,
    "items": {
      "<id>": {
        "file": "회의록.md",
        "deletedAt": 1793464405000,
        "autoTitle": false,
        "language": "markdown",
        "pinned": true
      }
    }
  }
  ```
  `language`·`pinned` 는 `index.json` 의 `MemoEntry` 와 같은 규칙으로 없으면 쓰지 않는다. 쓰기는 다른 정보 파일처럼 원자적으로 한다(`persist::write_json`).
- 휴지통 정보는 읽을 때마다 `.trash/<id>/` 폴더들과 맞춘다(`MemoIndex::reconcile` 와 같은 방식). 정보에는 있는데 폴더가 없는 항목은 버린다. **폴더는 있는데 정보에 없는 항목**(옮긴 뒤 `trash.json` 을 쓰기 전에 앱이 죽은 경우)과, `trash.json` 이 없거나 읽을 수 없어 다시 만든 항목은 목록에 넣되 **`deletedAt` 을 맞춘 그 시각(지금)으로 둔다**(설계자 판단: 폴더 수정 시각은 복사·동기화로 바뀌어 믿을 수 없다. 지금으로 두면 자동 비우기는 기한을 처음부터 다시 세므로 예정보다 일찍 지우는 일이 없다 — 「하면 실패인 것」 넷째 줄). 원래 이름은 폴더 안 파일 이름이고, `autoTitle`·`language`·`pinned` 는 기본값(꺼짐·없음·꺼짐)이다. 읽지 못한 `trash.json` 은 `index.json` 처럼 옆으로 치워 둔다(`MemoIndex::load` 와 같은 방식).
- 옮기기의 쓰기 순서는 **파일 → `index.json` → `trash.json`** 이다. 어느 사이에 앱이 죽어도 메모는 메모 목록(파일이 아직 바로 아래에 있으면)이나 휴지통(바로 위 문단의 맞추기) 가운데 한쪽에 남는다.
- `.trash/` 는 처음 휴지통으로 옮길 때 만든다.

## 휴지통으로 옮기기

- 메모 목록 행의 문맥 메뉴 맨 아래에 구분선을 두고 **「휴지통으로 이동」** 을 넣는다(설계자 판단: Finder 의 같은 동작 이름). 묻지 않는다(사용자 결정). 고정 구역의 행에서도 같다.
- 백엔드 명령 하나(`trash_memo(id)`)가 파일을 옮기고, `index.json` 에서 항목을 빼고, `trash.json` 에 적고, 그 메모의 `viewed` 기록을 지운다. 지금 `delete_memo` 가 정리하는 것(`last_written`·`inodes`)도 같이 정리한다. 다른 이름의 파일로 옮기는 것이 아니라 하위 폴더로 옮기는 것이므로 파일 감시가 이것을 「메모가 지워졌다」로 오해해 배너를 띄우지 않게 한다 — 앱이 스스로 한 변경으로 알아야 한다.
- **열린 탭:** 그 메모가 이 창이나 같은 워크스페이스의 다른 창에 열려 있으면 그 탭들을 닫는다(설계자 판단: 직접 지운 메모에 「삭제됨」 배너를 남기는 것은 어색하다). 닫기 전에 저장 안 된 수정분을 저장해서 휴지통의 파일이 마지막 내용을 갖게 한다. 저장이 실패하거나 충돌 배너가 떠 있으면 **옮기지 않고** 상태 표시줄에 알린다 — 「하면 실패인 것」 첫 줄. 다른 창의 탭을 어떤 순서로 저장·닫게 할지는 만드는 사람이 정하되, 그 계약은 이 문단이다.
- 옮긴 뒤 메모 목록에서 그 행이 빠지고, 같은 워크스페이스의 모든 창에서 같다.
- 빈 자동 제목 메모를 닫을 때 지우는 것(`docs.ts` `close`)은 **지금처럼 바로 지운다**(설계자 판단: 되살릴 내용이 없고 휴지통에 빈 파일만 쌓인다).

## 휴지통 화면 (시안 A)

- **여는 길:** 사이드바 맨 아래 줄, 설정 버튼 오른쪽에 휴지통 버튼(인라인 SVG 아이콘, `currentColor`). 접근 이름은 「휴지통」, `title` 은 「휴지통 (N개)」(설계자 판단: 숫자 배지는 두지 않는다 — 업데이트 버튼이 들어올 폭을 남긴다, `docs/superpowers/specs/2026-10-20-tote-notes-settings-and-shortcuts-design.md` 「설정 화면」). 업데이트 버튼은 그 오른쪽 남은 폭을 채운다.
- 누르면 메모 목록 자리가 **휴지통 목록**으로 바뀐다. 검색 패널이 그 자리를 차지하는 것과 같은 방식이다(`Sidebar.show`, `SidebarPane` 에 `"trash"` 를 더한다). 다시 누르거나 머리줄의 「← 메모」 를 누르면 메모 목록으로 돌아온다. 워크스페이스 고르개는 그대로 위에 있다.
- 머리줄: 「← 메모」, 오른쪽에 「휴지통 N」.
- 행: 원래 파일 이름(메모 목록과 같은 이름 표시 규칙), 아래 줄에 지운 시각(메모 목록 미리보기 행의 시각 표기와 같은 규칙). **최근에 지운 것부터.** 필터·정렬 메뉴는 없다.
- 행 문맥 메뉴: **「복구」**, 구분선, **「영구 삭제」**. 메모 목록 문맥 메뉴와 같은 네이티브 팝업이다.
- 맨 아래: **「휴지통 비우기」**(비었으면 비활성).
- 비었을 때: 목록 자리에 「휴지통이 비었습니다」.
- **영구 삭제·비우기는 확인 창을 한 번 띄운다**(설계자 판단: 되돌릴 수 없다. 사용자의 「바로 삭제」 는 휴지통으로 옮길 때에 관한 답이었다). 문구는 「「회의록.md」 를 영구 삭제할까요? 되돌릴 수 없습니다.」, 「휴지통의 메모 N개를 영구 삭제할까요? 되돌릴 수 없습니다.」, 버튼은 「취소」 와 위험 스타일의 「영구 삭제」 (`confirm` 에 위험 스타일 버튼이 없으면 `askUnsaved` 의 「저장하지 않음」 과 같은 `danger` 클래스를 쓴다).
- 같은 워크스페이스의 다른 창에서 휴지통이 바뀌면(옮기기·복구·영구 삭제·자동 비우기) 열려 있는 휴지통 목록도 따라 바뀐다. 메모 목록이 다른 창의 변경을 따라가는 길을 같이 쓴다.
- 워크스페이스를 바꾸면 휴지통 목록도 새 워크스페이스의 것이 된다.

## 내용 보기

- 휴지통 행을 누르면 그 메모가 **읽기 전용 탭**으로 열린다. 언어 하이라이트는 원래 언어로 한다. 탭 제목은 원래 이름이고, 휴지통 메모임을 탭에서도 알아보게 한다(설계자 판단: 제목을 흐리게. 정확한 모양은 만드는 사람이).
- 편집기 위 띠: 「휴지통에 있는 메모입니다 · <지운 시각>」, 버튼 **「복구」**, **「영구 삭제」**(확인 창은 위와 같다).
- 이미 같은 메모의 휴지통 탭이 열려 있으면 그 탭으로 간다(메모 목록에서 메모를 누를 때와 같다).
- 휴지통 탭은 세션에 남기지 않는다(설계자 판단: 다시 켰을 때 사라져도 잃는 것이 없다).
- 그 메모가 복구되면 탭은 보통 메모 탭이 된다(읽기 전용이 풀리고 띠가 사라진다). 영구 삭제되거나 자동으로 비워지면 탭을 닫는다. 다른 창에서 일어나도 같다.

## 복구

- 파일을 워크스페이스 바로 아래로 옮기고, 같은 ID 로 `index.json` 에 항목을 되돌린다(`autoTitle`·`language`·`pinned` 그대로). `trash.json` 에서 뺀다.
- 원래 이름이 이미 있으면 메모를 만들 때와 같은 규칙으로 「회의록 2.md」 처럼 번호를 붙인다(`Workspace::free_name`). **덮어쓰지 않는다.** 번호가 붙어도 `autoTitle` 은 지운 때의 값 그대로다(설계자 판단: `retitle_memo` 가 「제목 2」 를 붙여도 자동 제목을 켜 두는 것과 같다. 자동 제목 메모는 다음 제목 정하기 때 번호 없는 이름을 다시 찾는다).
- 복구한 메모는 메모 목록에 나타난다. 복구만 하고 열지는 않는다(설계자 판단).

## 자동 비우기

- 설정 `settings.json` 의 `trash.retentionDays`. 기본 **60**(사용자 결정). `null` 이면 자동으로 비우지 않는다. 1~3650 으로 묶는다(설계자 판단).
- 설정 화면 「일반」 구역에 「휴지통 자동 비우기」: 숫자 칸 「[60] 일 지난 메모」 와 「안 비움」 체크. 저장 방식은 다른 설정처럼 바꾸는 즉시 저장, 글꼴 크기 칸과 같은 묶기·되돌리기 규칙(`docs/superpowers/specs/2026-10-20-tote-notes-settings-and-shortcuts-design.md` 「설정 화면」).
- 언제: 워크스페이스를 열 때, 그리고 열려 있는 동안 한 시간마다(설계자 판단). `deletedAt` 이 `지금 - 기한` 보다 앞선 항목만 지운다. `deletedAt` 이 미래(시계가 돌아간 경우)면 지우지 않는다.
- 설정은 앱 전체에 하나이고 모든 워크스페이스에 같게 적용된다.

## 줄번호 글자 크기

- 편집기 줄번호 칸의 글자를 본문의 **0.85배**로 한다(설계자 판단: 사용자는 「줄여」 만 말했다. 본문 14px 이면 약 12px). 본문 글꼴 크기 설정을 바꾸면 함께 바뀐다.
- 줄 높이·세로 위치는 본문 줄과 맞아야 한다 — 숫자가 그 줄 글자와 같은 기준선(또는 가운데)에 오고, 줄이 많아도 어긋남이 쌓이지 않는다. 활성 줄 번호도 같은 크기다.
- 대용량 뷰어(`large-text`)에 줄번호 칸이 있으면 같은 비율을 쓴다. 그쪽 줄 높이 20px 고정은 바꾸지 않는다.

## 시험이 보여야 하는 것

- 백엔드: 옮기기·복구·영구 삭제·비우기·자동 비우기(기한 전/후/미래 시각), 복구 이름 충돌, `trash.json` 이 깨졌거나 없을 때 다시 만들기, 옮긴 뒤 메모 목록·검색에 안 나오는 것, 복구 뒤 같은 ID·고정·언어.
- 화면(e2e, 가짜 백엔드): 문맥 메뉴로 옮기기 → 목록에서 빠짐 → 휴지통 목록에 나옴 → 행을 눌러 읽기 전용 탭 → 띠의 복구 → 메모 목록에 되돌아옴. 영구 삭제·비우기의 확인 창. 저장 안 된 수정분이 휴지통 파일에 들어가는 것, 저장 실패 때 옮기지 않는 것. 다른 창의 탭이 닫히는 것. 설정 칸.
- 줄번호: 글자 크기가 본문의 0.85배이고, 몇 번째 줄에서든 숫자와 본문 글자의 세로 위치가 1px 안으로 맞는 것.
- 실기기(WKWebView) 확인: 문맥 메뉴의 새 항목, 휴지통 버튼과 업데이트 버튼이 함께 있을 때의 하단 줄, 줄번호의 기준선. 기록은 `docs/superpowers/reports/` 에 남긴다.

## 만드는 사람에게 맡기는 것

- 다른 창의 탭을 저장·닫게 하는 순서와 신호(계약은 「휴지통으로 옮기기」 의 「열린 탭」 문단).
- 휴지통 탭을 기존 탭 종류(메모·외부 파일) 옆에 어떻게 둘지.
- 파일 감시가 앱 자신의 옮기기·복구를 외부 변경으로 보지 않게 하는 방법.
- 휴지통 아이콘의 모양, 탭에서 휴지통 메모를 알아보게 하는 모양.
- 코어 스펙(`docs/superpowers/specs/2026-10-07-tote-note-core-design.md`)과 메모 목록 스펙(`docs/superpowers/specs/2026-10-30-tote-notes-memo-list-features-design.md`)의 문맥 메뉴 항목 문장을 이 문서에 맞게 고치는 것.
