# tote-notes 사이드바 너비 조절·전체 화면 맨 윗줄·신호등 첫 위치 설계

2026-10-30. 제목 줄 탭·사이드바 접기(`docs/superpowers/specs/2026-10-29-tote-notes-titlebar-tabs-and-sidebar-toggle-design.md`)를 실제 앱에서 본 사용자의 요청 셋이다. 이 문서는 그 설계의 「창 틀 (macOS)」 의 전체 화면 문장과 「하지 않는 것」 의 「사이드바 너비 조절」 을 대신한다. 사용자가 정한 것은 그대로 적고, 그 밖의 결정은 **설계자 판단**으로 표시한다. 아래 값은 설계자가 제안하고 사용자가 「바꿀 값 없어」 로 받아들였다.

## 1. 신호등이 첫 실행에서 위에 붙는다 (버그)

- 관찰(사용자): 디버그 앱을 처음 실행하면 신호등이 맨 윗줄(36px)의 세로 가운데가 아니라 창 위쪽에 붙는다. 누르기는 정상이다. **워크스페이스를 전환하면(페이지를 다시 읽으면) 제자리로 돌아온다.**
- 요구: 첫 표시, 크기 바꾸기, 전체 화면에서 돌아오기, 밝은/어두운 모양 바꾸기, 워크스페이스 전환 뒤 모두 신호등의 세로 가운데가 맨 윗줄의 세로 가운데에 있다(±1pt).
- 원인은 아직 모른다. 고치기 전에 Tauri/tao 가 inset 을 언제 적용하고 무엇이 그것을 되돌리는지 찾는다. 의존성 패치는 다른 길이 없을 때만이고, 그때는 사람에게 먼저 묻는다.

## 2. 전체 화면에서 맨 윗줄 (사용자 요청: 「최대화 할 때 신호등 있던 공간이 비어. Title 당겨줘」)

- macOS 전체 화면(초록 버튼, ⌃⌘F)에서는 신호등이 없으므로 **신호등 자리(`--traffic-lights-width`)를 0 으로 줄인다.** 사이드바 윗줄의 「Tote Notes」 가 왼쪽 여백에 붙고, 접혔을 때 탭 줄 앞머리의 펼치기 버튼도 왼쪽으로 붙는다.
- 전체 화면에서 나오면 자리가 돌아온다. 바뀔 때 애니메이션은 없다(설계자 판단: 시스템 전환 애니메이션과 겹친다).
- 「최대화」 는 macOS 의 확대(zoom, 사이드바 윗줄 두 번 누르기)가 아니라 전체 화면을 뜻한다. 확대된 창은 신호등이 그대로 있으므로 자리도 그대로다.
- 전체 화면 여부를 페이지가 아는 방법(창 이벤트, Rust 가 알려 주기 등)은 만드는 사람이 정한다. macOS 배치(`mac-titlebar`)가 아닐 때는 아무것도 바꾸지 않는다.

## 3. 사이드바 너비 조절 (사용자 요청: 「너비 조절 가능하도록. 너무 좁아지지 않게. 특정 기준 아래로 줄이면 사이드바 닫히도록」)

- 사이드바 오른쪽 경계에 **6px 손잡이**를 둔다. 칸 나눔 경계(`.pane-divider`)와 같은 모양·커서(`col-resize`)다. 맨 윗줄을 포함해 사이드바 높이 전체에 걸친다. 손잡이 위에서는 창 끌기가 시작되지 않는다.
- 값: **기본 240px, 최소 180px, 최대 480px.** 창 너비의 절반을 넘지 않는다(최대는 `min(480, 창 너비 / 2)`, 단 180 아래로는 내려가지 않는다).
- 끌기:
  - 포인터가 가리키는 너비로 바로 바뀐다. 끄는 동안 애니메이션은 없다.
  - **200px 아래로 가면 접힌다**(끄는 중에 바로. 사용자 요청: 「200 이하로 내려가면 접히도록」). 그래서 끌어서 만드는 가장 좁은 너비는 200px 이다(정확히 200px 은 접히지 않는다 — 설계자 판단). 놓기 전에 다시 200px 이상으로 끌면 펼쳐지고 너비는 포인터가 가리키는 너비다. 최소 180px 은 저장된 너비를 읽는 범위와 좁은 창의 최대값 하한으로 남는다.
  - 끌어서 접힌 것은 버튼·⌘B·메뉴로 접은 것과 같은 상태다(포커스 처리, `inert`, 세션 저장, 앞머리). 펼치면 **끌기를 시작하기 전의 너비**로 돌아온다.
  - 놓기가 오지 않아도 끌기는 끝난다(창 밖에서 놓기, 누른 채 다른 앱으로 가기). 버튼이 떼어진 포인터 움직임, 창이 포커스를 잃을 때, 포인터 캡처를 잃을 때 그때의 너비로 놓은 것과 같게 끝난다. 칸 나눔 경계도 같다(리뷰 뒤 판정).
  - 끄는 중에 버튼·⌘B·메뉴로 접거나 펴면 **토글이 이긴다.** 끌기가 그때의 너비로 먼저 끝나고 토글이 그 뒤에 일어나며, 이어지는 움직임은 아무것도 바꾸지 않는다(리뷰 뒤 판정).
- 경계를 **두 번 누르면 240px** 로 돌아간다.
- 저장: 너비는 **창마다 세션에** 남는다(접힘 상태와 같은 자리, 같은 규칙 — 첫 그림 전에 닿고, 워크스페이스 전환을 건너가고, 새 창·떼어 낸 창·세션이 없는 창은 기본 240px). 놓을 때 한 번 저장한다. 240px 이면 세션에 쓰지 않는다(설계자 판단: 펼친 기본 창의 세션이 지금과 같게). 읽을 때 180~480 의 수만 받고, 그 밖은 기본값이다.
- 창이 좁아져 최대가 저장된 너비보다 작아지면 **보이는 너비만 줄이고 저장된 너비는 그대로 둔다**(설계자 판단). 창이 다시 넓어지면 돌아온다.
- 접기·펼치기의 0.16초 전환은 그대로이며 펼칠 때 저장된 너비로 간다.
- 손잡이의 키보드·손잡이 안내(역할, 이름)는 칸 나눔 경계의 지금 관례를 따른다.

## 지켜야 할 제약

- 앞 설계의 「지켜야 할 제약」 은 그대로다(탭 줄 DOM, 탭 끌기, 테마 변수, `accept_first_mouse`).
- 사이드바 내용은 지금처럼 `--sidebar-width` 로 너비를 지킨다. 너비를 바꿀 때 이 변수를 쓴다(내용이 접히는 동안 재배치되지 않게 하던 것과 같은 변수).
- 코어 스펙(`docs/superpowers/specs/2026-10-07-tote-note-core-design.md`) 「창 배치」·「세션」 을 이 문서에 맞게 고친다. 화면 확인 문서(`docs/superpowers/reports/2026-10-29-tote-notes-titlebar-tabs-smoke.md`)에 전체 화면 자리와 너비 조절 항목을 더한다.

## 만드는 사람에게 맡기는 것

- 신호등 버그의 원인과 고치는 자리.
- 전체 화면 여부를 페이지에 전하는 방법.
- 손잡이를 DOM 어디에 두는지, 너비 상태를 어느 모듈이 갖는지.
