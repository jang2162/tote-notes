# tote-notes 마크다운 미리보기 보강 설계 — 체크박스, 코드 블록 색, 링크

2026-11-14. 2026-11-13 점검 끝에 추천된 기능 묶음 가운데 하나다. 사용자가 설계 확인 없이 바로 진행하라고 했으므로(2026-11-14) 동작은 **코디네이터의 판단**(작업 브리프)이고, 브리프가 비워 둔 세부는 **구현자의 판단**이다. 결정마다 둘 중 어느 쪽인지 붙인다.

미리보기의 기본 구조(탭마다 편집 ↔ 미리보기, 번들 뷰어가 샌드박스 iframe 에서 `marked` 로 그린다)는 코어 설계 「마크다운 미리보기」·「뷰어」 절 그대로다. 이 문서는 그 위에 얹는 셋과 그것을 위한 뷰어 API 추가를 다룬다.

## 목적

지금 미리보기는 읽기만 하는 그림이다. 할 일 목록(`- [ ]`)은 체크박스가 아예 보이지 않고(정화기가 `input` 을 걷는다), 링크는 눌러도 아무 일이 없고, 코드 블록은 색이 없다. 메모 앱에서 가장 자주 쓰는 셋을 미리보기 안에서 쓸 수 있게 한다.

## 동작 (사람이 보는 것)

### 체크박스

- GFM 할 일 항목(`- [ ] 할 일`, `- [x] 한 일`, 번호 목록·중첩 목록·인용 안의 것 포함)이 체크박스로 그려진다(코디네이터의 판단).
- 체크박스를 누르면 **원본 텍스트의 그 항목 줄의 `[ ]` ↔ `[x]` 가 바뀐다.** 미리보기는 바뀐 텍스트로 다시 그려지고, 보던 스크롤 자리는 그대로다(코디네이터의 판단).
  - 체크된 쪽은 `[x]` 로 쓰고, `[X]` 를 풀면 `[ ]` 가 된다(구현자의 판단: GFM 은 둘 다 체크로 읽는다. 새로 쓰는 것은 GitHub 이 쓰는 소문자로).
  - 바꾸는 것은 대괄호 안의 한 글자뿐이다. 줄의 나머지·줄바꿈(CRLF 메모 포함)은 그대로다.
- 바꾼 것은 편집기 문서에 한 번의 편집으로 들어간다. **편집으로 돌아가 ⌘Z 를 누르면 되돌아간다.** 체크 하나가 실행 취소 한 단계다(구현자의 판단: 앞뒤의 타이핑과 한 단계로 묶이지 않게 `isolateHistory`). 저장은 보통 편집처럼 자동 저장(메모)·⌘S(외부 파일) 길을 탄다(코디네이터의 판단).
- **읽기 전용 탭에서는 바꿀 수 없다**(코디네이터의 판단). 지금 읽기 전용 탭은 휴지통 메모 탭 하나이고, 이 탭은 처음부터 미리보기가 열리지 않는다(메모 휴지통 설계 「내용 보기」 — 뷰어가 읽을 파일이 없다). 그래도 뷰어에 읽기 전용을 알려 체크박스를 누를 수 없게(비활성) 그리고, 호스트도 읽기 전용 상태(`EditorState.readOnly`)의 문서에는 바꾸기를 거절한다(구현자의 판단: 나중에 다른 읽기 전용 탭이 미리보기를 열어도 이 두 겹이 지킨다).
- 미리보기를 그린 뒤 원본이 바뀌었으면(다른 앱이 파일을 바꿔 탭이 다시 읽은 경우 등) 그 누름은 **아무 줄도 바꾸지 않고**, 미리보기를 지금 원본으로 다시 그린 뒤 상태 표시줄에 「미리보기가 원본과 달라 다시 그렸습니다. 다시 눌러 주세요」 를 띄운다(판 확인은 코디네이터의 판단, 다시 그리기와 문구는 구현자의 판단).

#### n 번째 할 일 ↔ 원본 줄 (구현자의 판단)

뷰어는 「n 번째 체크박스를 바꿔 달라」 와 그린 판(버전)을 보낸다. 줄은 **호스트가 정한다**(뷰어가 고른 줄을 믿지 않는다).

1. 호스트는 그 판을 그릴 때 넘긴 텍스트를 기억한다. 받은 판이 마지막으로 넘긴 판이 아니거나, 편집기 문서가 그 텍스트와 한 글자라도 다르면 거절한다(위 「원본이 바뀌었으면」).
2. 같은 텍스트를 뷰어와 **같은 `marked`**(같은 패키지·같은 판·같은 옵션 `gfm: true`)로 읽어, marked 자신의 순회(`walkTokens`, 렌더러가 그리는 순서)와 같은 순서로 상자들의 체크 상태 목록을 얻는다. 코드 블록·HTML 블록 안의 `- [ ]` 는 `checkbox` 토큰이 아니므로 목록에 없다.
   - 순회는 `marked.walkTokens` 를 부르지 않고 같은 순서(표의 머리 칸 → 행, 목록의 항목, 그 밖의 토큰의 자식)로 직접 돈다(구현자의 판단, 2026-11-14 후속). `marked.walkTokens` 는 콜백의 답을 단계마다 `Array.concat` 으로 모아 비용이 토큰 수의 제곱으로 는다 — 12,000줄·할 일 3,750개 메모에서 누르기 한 번이 약 0.9초였고 직접 돌면 약 33ms 다(`node` 로 `toggleTask` 만 잰 값, 부하 9.5). 확장의 `childTokens` 는 따르지 않는다 — 호스트의 `marked` 에는 확장이 없다. 확장을 들이면 이 순회도 고친다.
   - 누르기 한 번이 글을 읽는 것은 둘이다: 바꾸기 전 한 번(상자 목록과 짐작할 줄을 같은 토큰에서 얻는다)과 확인마다 한 번.
3. **바꿀 자리는 다시 읽어서 확인한다.** 원본의 `[ ]`·`[x]`·`[X]` 하나의 가운데 글자를 바꾼 글을 다시 읽어, **n 번째 상자만 뒤집히고 나머지 상자·개수는 그대로**일 때만 그 자리를 바꾼다. 이 확인을 지난 자리는 정의상 n 번째 상자의 것이다 — 누른 상자와 바뀐 글자가 다른 할 일일 수 없다.
   - 어느 자리부터 확인할지는 토큰의 `raw` 줄바꿈 수로 센 줄(`taskLines`)로 짐작한다. 흔한 꼴(인용 안 목록, 중첩, 느슨한 목록, 코드 블록, CRLF)에서는 맞아 다시 읽기 한 번으로 끝난다. 그러나 marked 의 `raw` 가 원본과 다른 꼴이 있다(`>` 없이 이어지는 게으른 줄이 인용을 가르면 `raw` 에 원본에 없는 줄바꿈이 끼고, 인용 안의 참조 정의는 줄바꿈 하나가 빠진다). 그때 짐작한 줄은 다른 할 일이거나 할 일처럼 보이는 문단 줄이다 — 그래서 짐작만으로는 바꾸지 않는다.
   - 짐작한 줄의 자리가 확인을 지나지 못하면 줄이 가까운 순서로 다른 자리를 확인한다. 한 번 확인이 글 전체를 다시 읽는 것이라 횟수에 한도가 있다: 64번, 그리고 글 길이 × 횟수가 400만 자를 넘지 않게(구현자의 판단). 한도 안에서 찾지 못하면 **아무것도 바꾸지 않고** 상태 표시줄에 「이 할 일을 원본에서 찾지 못했습니다」. 틀린 자리를 고치는 것보다 아무것도 안 하는 쪽으로 틀린다.
   - `marked` 는 CRLF·CR 을 LF 로 바꿔 읽는다. 바꾸는 것은 대괄호 안 한 글자이므로 줄바꿈 종류는 그대로다.
4. 원본의 HTML 에 손으로 쓴 `<input type="checkbox">` 가 n 을 밀지 않게, 뷰어는 렌더러가 그린 체크박스에만 그 판의 무작위 값(nonce)을 붙이고 정화 단계에서 그 값이 맞는 것만 새 `input` 으로 바꿔 남긴다. 나머지 `input` 은 지금처럼 걷는다.

호스트는 `marked` 를 체크박스를 처음 누를 때 따로 불러온다(동적 `import`, 구현자의 판단: 앱의 첫 화면 번들을 키우지 않는다). 그래서 `marked` 를 `devDependencies` 에서 `dependencies` 로 옮겼다(판은 그대로 18.1.0).

### 코드 블록 색

- 펜스에 언어가 적힌 코드 블록(` ```ts `)은 **편집기와 같은 TextMate 문법·같은 테마 색**으로 칠한다(코디네이터의 판단).
- 언어 이름은 레지스트리에서 언어 id → 별칭 → 파일 확장자 순으로 찾는다(대소문자 무시, 구현자의 판단: `ts`·`py`·`rs`·`sh` 처럼 펜스에 흔히 쓰는 것이 확장자이고, `typescript`·`TypeScript` 는 id·별칭이다). 모르는 언어, 문법이 없는 언어는 지금처럼 색 없이 둔다.
- **첫 그림을 늦추지 않는다**: 뷰어는 먼저 색 없이 그리고, 코드 블록 목록(언어·글자)을 호스트에 보낸다. 호스트가 하이라이트 워커(`src/highlight/`)로 토큰을 만들어 보내면 그때 색을 입힌다(코디네이터의 판단).
- 호스트가 보내는 것은 HTML 이 아니라 **구조**다: 블록마다 줄의 목록, 줄마다 조각 `{ 글자, 색, 글꼴 모양(기울임·굵게·밑줄·취소선) }`. 뷰어는 조각마다 `span` 을 만들고 `textContent` 로 글자를 넣는다(`innerHTML` 을 쓰지 않는다). 받은 조각의 글자를 이어 붙인 것이 그 블록의 지금 글자와 다르면 그 블록은 칠하지 않는다(구현자의 판단).
- 테마가 바뀌면 뷰어가 색을 다시 청한다(구현자의 판단). 호스트는 같은 뷰어의 더 새 색 요청(`req`)을 받으면 앞 요청의 남은 블록을 워커에 보내지 않고 그 답도 보내지 않는다 — 판이 바뀐 것과 같게 다룬다(구현자의 판단, 2026-11-14 후속: 옛 테마의 색을 칠하느라 새 테마의 요청과 편집기의 색 요청이 뒤에 줄 서지 않게).
- 한 번에 칠하는 양에 한도가 있다: 블록 200개, 글자 합 50만 자(구현자의 판단: 그보다 큰 문서의 코드 블록 색은 워커를 오래 붙잡는 값어치가 없다). 넘는 블록은 색 없이 둔다.

### 링크

- `http:`·`https:`·`mailto:` 링크를 누르면 **시스템 기본 앱(브라우저·메일)으로 연다**(코디네이터의 판단). 백엔드 명령 `open_link` 하나가 macOS `open` 을 부른다. 이 세 스킴이 아니면 **백엔드도** `bad-request` 로 거절한다.
- 같은 워크스페이스의 메모를 가리키는 상대 경로 링크(`[회의](회의%20준비.md)`, `[회의](<회의 준비.md>)`, `./회의 준비.md`)는 **그 메모를 탭으로 연다** — 이미 열려 있으면 그 자리로 간다(「한 메모는 한 자리에」, 코디네이터의 판단).
  - 경로는 퍼센트 인코딩을 풀고 `?…`·`#…` 를 떼어 낸 뒤 이 탭의 파일이 있는 폴더를 기준으로 푼다. 메모 탭은 워크스페이스 폴더, 외부 파일 탭은 그 파일의 폴더다(구현자의 판단: 외부 파일이 워크스페이스 폴더에 있으면 그 링크도 메모로 연다).
  - 워크스페이스는 평평하므로(코어 설계 「워크스페이스」) 푼 경로의 폴더가 워크스페이스 폴더 자체여야 하고, 그 이름(NFC 로 맞춘 것)이 메모 목록에 정확히 있어야 한다. 확장자를 짐작해 붙이지 않는다.
  - 워크스페이스 밖이면 「워크스페이스 밖의 파일은 열지 않습니다」, 없는 메모면 「워크스페이스에 없는 메모입니다: <이름>」 을 상태 표시줄에 띄우고 아무것도 하지 않는다(코디네이터의 판단, 문구는 구현자의 판단).
- `#제목` 링크는 미리보기 안에서 그 제목으로 스크롤한다(코디네이터의 판단). 제목의 앵커는 GitHub 방식으로 만든다(소문자, 글자·숫자·`-`·`_`·공백 밖은 지우고 공백은 `-`, 같은 것이 또 나오면 `-1`, `-2` … 구현자의 판단). 맞는 제목이 없으면 `id`·`name` 이 같은 요소로, 그것도 없으면 아무것도 하지 않는다.
- 그 밖의 스킴(`file:`, `ftp:`, `javascript:` 등)·`//` 로 시작하는 주소·`/` 로 시작하는 절대 경로는 열지 않고 상태 표시줄에 「열 수 없는 링크입니다」 를 띄운다(구현자의 판단). `javascript:` 는 뷰어의 정화기가 `href` 째 걷으므로 눌러도 호스트에 아무것도 가지 않는다.
- 링크에 마우스를 올리면 주소가 툴팁으로 보인다: 링크에 `title` 이 없으면 퍼센트 인코딩을 푼 주소를 `title` 로 단다(구현자의 판단: 원래 `title` 이 있으면 그것을 지킨다).

### 단축키·메뉴·설정

없다. 새 메뉴 항목·단축키·settings.json 키를 더하지 않는다.

## 뷰어 API 추가 (postMessage)

모든 새 메시지는 호스트가 검증한다: 보낸 쪽이 그 iframe 인지(`event.source`, 기존과 같다), 값의 꼴(형, 정수, 문자열 길이), 범위. 맞지 않으면 조용히 버린다.

| 방향          | 메시지             | 값                                                                              |
| ------------- | ------------------ | ------------------------------------------------------------------------------- |
| 호스트 → 뷰어 | `init` (추가 필드) | `version`(판, 그릴 때마다 1씩), `readOnly`                                      |
| 호스트 → 뷰어 | `update`           | 새 `text`·`version`. 스크롤 자리를 지키며 다시 그린다                           |
| 호스트 → 뷰어 | `highlighted`      | `version`, `req`, `blocks: [{ index, lines: [[{ text, color?, fontStyle }]] }]` |
| 뷰어 → 호스트 | `toggleTask`       | `version`, `index`(0 이상 정수)                                                 |
| 뷰어 → 호스트 | `highlight`        | `version`, `req`, `blocks: [{ index, lang, code }]`                             |
| 뷰어 → 호스트 | `openLink`         | `href`(8 KiB 까지)                                                              |

- 판이 마지막으로 보낸 것과 다른 `toggleTask`·`highlight` 는 버린다. 색을 칠하는 중에 판이 바뀌면 남은 블록은 워커에 보내지 않는다(편집기의 색 요청이 그 뒤에 줄 서지 않게). 뷰어도 지금 판·마지막 `req` 가 아닌 `highlighted` 를 버린다.
- 뷰어는 부모 창(호스트)이 보낸 메시지만 받는다. 같은 페이지의 다른 프레임이 가짜 글을 그리게 해 사람이 그 n 번째 상자를 누르면 진짜 글의 n 번째가 바뀌는 길을 막는다.
- 색은 `#` 와 16진수 3·4·6·8자리만 넘긴다(테마 파일의 다른 값은 색 없이).
- 이 메시지들은 미리보기 뷰어를 위한 것이지만 `ViewerHost` 는 모든 뷰어에 같다. 주 뷰어(미디어)에는 이 처리기를 주지 않으므로 보내도 버려진다.

## 백엔드

- 새 명령 `open_link { url }` (`Backend.openLink(url)`). `http`·`https`·`mailto` 스킴(대소문자 무시)만, 공백·제어 문자가 없고 8 KiB 이하일 때만 `open <url>` 을 부른다. 아니면 `bad-request`. macOS 밖에서는 `io`(지원하지 않음). 검사는 Rust 단위 시험으로 고정한다.
- 가짜 백엔드는 받은 URL 을 검사 **전에** `FakeData.openedLinks` 에 남기고(개발 메모 「일어나지 않음」 은 호출 기록으로), 같은 검사로 거절한다.

## 데이터·저장

settings.json·세션에 더하는 것은 없다. 체크박스는 편집기 문서를 바꾸고, 저장은 기존 길이다.

## 하지 않는 것 (코디네이터의 판단)

나란히 미리보기, 수식·mermaid, 원격 이미지, `[[링크]]`·백링크, 미리보기 안 편집(체크박스 밖). 링크한 메모의 `#제목` 으로 그 메모 안을 스크롤하는 것도 하지 않는다(구현자의 판단: 메모 탭은 편집기로 열리고, 그 제목 줄로 가는 길은 이 묶음의 범위 밖이다).
