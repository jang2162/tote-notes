# tote-notes 메모 목록·휴지통 목록의 키보드 조작과 여러 개 선택

2026-11-14. 사용자가 2026-11-13 점검 끝에 추천받은 기능 묶음을 설계 확인 없이 진행하라고 했다. 동작·키 가운데 코디네이터가 브리프로 정한 것은 **(코디네이터의 판단)**, 브리프가 비워 둬서 만드는 사람이 정한 것은 **(구현자의 판단)** 으로 표시한다. 사용자가 읽고 바꿀 수 있게 각 결정에 버린 대안을 함께 적는다.

이 문서는 메모 목록 설계(`docs/superpowers/specs/2026-10-30-tote-notes-memo-list-features-design.md`)와 휴지통 설계(`docs/superpowers/specs/2026-11-01-tote-notes-memo-trash-design.md`)의 「하지 않는 것」 가운데 「여러 메모를 골라 한꺼번에 …」 를 거두고, 두 목록의 누르기·키 동작을 더한다.

## 왜

2026-11-13 점검에서 메모 목록·휴지통 목록·이전 버전 목록·언어 고르기·상태 표시줄의 언어 표시가 **마우스로만** 된다는 것이 확인됐다. 행이 `div`·`li`·`span` 에 `click` 만 걸려 있고 Tab 이 닿지 않으며, 역할(role)도 이름도 없어 VoiceOver 가 목록으로 읽지 못한다. 그리고 메모 여러 개를 한꺼번에 휴지통으로 옮기거나 고정하는 길이 없어 하나씩 문맥 메뉴를 열어야 한다.

## 목표

1. 메모 목록과 휴지통 목록을 **키보드만으로** 옮겨 다니고, 열고, 지우고, 문맥 메뉴를 연다.
2. 두 목록에서 **여러 행을 골라** 문맥 메뉴의 동작을 고른 것 전체에 한 번에 적용한다.
3. 이전 버전 목록·언어 고르기·상태 표시줄의 언어를 키보드로 쓴다.
4. 보조 기술이 목록의 역할·이름·선택 상태를 읽는다.

## 하지 않는 것

**(코디네이터의 판단)**

- 목록에서 바로 이름 고치기(인라인 편집), 끌어서 순서 바꾸기.
- 여러 메모를 한꺼번에 열기. 열기는 언제나 지금 행 하나다.
- 워크스페이스 검색 결과의 여러 개 선택.
- 메뉴 막대에 새 항목. ⌘⌫ 는 목록 안의 키 처리이고 앱 명령·단축키 표에 들지 않는다. 그래서 설정 「단축키」 화면에도 나오지 않고 바꿀 수 없다.
- 선택을 세션에 남기는 것. 창을 다시 열면 아무것도 고르지 않은 목록으로 시작한다.

**(구현자의 판단)**

- 여러 개의 「경로 복사」(줄바꿈으로 이은 경로). 클립보드는 네이티브 쪽이 경로 하나로 쓴다(`copy_file_path`). 여럿을 쓰려면 명령을 하나 더 두어야 하는데, 여러 경로를 한꺼번에 붙여 넣을 곳이 드물다. 여럿을 고르면 항목이 빠진다(아래 「문맥 메뉴」).
- 글자를 쳐서 그 이름의 행으로 가기(type-ahead). 필터 칸이 그 몫이다.
- Esc 로 선택 풀기. 고른 것은 다른 행을 그냥 누르거나 ↑↓ 로 옮기면 풀린다.

## 메모 목록

### 자리와 역할

- 고정 구역·구분선·나머지 목록을 감싼 상자 하나가 **Tab 순서의 한 자리**다(`tabindex="0"`). 역할 `listbox`, 이름 「메모 목록」, `aria-multiselectable="true"` **(코디네이터의 판단: 한 자리)**. 행은 `option` 이고 이름은 파일 이름이다(`aria-label`). 행의 고정 표시·미리보기는 이름에 들지 않는다.
- Tab 순서: 필터 칸 → 정렬 버튼(버튼이라 macOS 「키보드 탐색」 이 꺼져 있으면 ⌥Tab 으로만) → 메모 목록.
- **지금 행은 `aria-activedescendant` 로 알린다. 키는 목록 상자에 그대로 있다 (구현자의 판단).** 목록은 보이는 행만 그리므로(가상 스크롤) 행 요소는 스크롤하면 생기고 없어진다. 버린 대안 — 로빙 tabindex(행 자신이 포커스를 받음): 지금 행이 스크롤로 화면 밖에 나가 요소가 빠지면 포커스가 `body` 로 떨어진다. 키로 행을 옮기면 그 행이 보이게 스크롤하므로 지금 행은 늘 그려져 있다. 마우스 휠로 지금 행을 화면 밖으로 보내면 `aria-activedescendant` 를 거둔다. 다시 키를 누르면 그 행으로 스크롤한다.
- 목록 상자에 키가 있으면 지금 행에 강조색(`--accent`) 테두리가 보인다.
- 고정 구역과 나머지 목록은 **하나의 순서**다: 고정 구역의 마지막 행에서 ↓ 는 나머지 목록의 첫 행 **(코디네이터의 판단)**.

### 키

목록 상자에 키가 있을 때만 받는다 **(코디네이터의 판단)**. 편집기의 ⌘⌫(줄 머리까지 지우기)는 그대로다.

| 키                | 동작                                                                                                                                                             |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ↑ ↓               | 지금 행을 한 칸 옮기고 그 행 하나만 고른다. 지금 행이 없으면(처음 들어왔을 때) ↓·↑ 모두 첫 행                                                                    |
| Home · End        | 첫 행 · 마지막 행                                                                                                                                                |
| PageUp · PageDown | 나머지 목록 칸에 보이는 행 수에서 하나 뺀 만큼(최소 1) **(구현자의 판단: 한 화면을 넘기되 한 줄은 겹쳐 보이게)**                                                 |
| ⇧ + 위의 키       | 고르기 시작한 행(기준 행)부터 새 지금 행까지를 고른다 **(코디네이터의 판단: ⇧↑↓. ⇧Home·⇧End·⇧PageUp·⇧PageDown 은 구현자의 판단 — 같은 규칙을 다른 이동 키에도)** |
| 첫 행에서 ↑       | 필터 칸으로 **(코디네이터의 판단)**. 선택은 그대로                                                                                                               |
| Enter             | 지금 행의 메모를 포커스 칸에 연다. **키는 목록에 남는다**                                                                                                        |
| ⌘Enter            | 지금 행을 열고 키를 편집기로                                                                                                                                     |
| 열린 행에서 Enter | 지금 행이 이미 포커스 칸의 활성 탭이면 키를 편집기로                                                                                                             |
| ⌘⌫                | 고른 메모 전체(고른 것이 없으면 지금 행)를 **묻지 않고** 휴지통으로. 상태 표시줄 「N개를 휴지통으로 옮겼습니다」                                                 |
| ⇧F10 · 메뉴 키    | 고른 것의 문맥 메뉴(오른쪽 클릭과 같은 메뉴). 지금 행이 고른 것 밖이면 지금 행만 고르고 연다                                                                     |
| ⌘A                | 보이는(필터에 맞는) 행 전부를 고른다                                                                                                                             |

- **Enter 의 키 자리 (구현자의 판단, 브리프의 추천대로):** 키를 목록에 남겨 ↓ Enter ↓ Enter 로 메모를 차례로 훑어볼 수 있게 했다. 편집기로 가는 길은 ⌘Enter 와 「이미 열린 행에서 Enter 한 번 더」 둘이다. 버린 대안 — Enter 가 늘 편집기로: 다음 메모를 보려면 매번 목록으로 돌아와야 한다(사이드바로 돌아오는 단축키가 없다).
- 마우스로 행을 누르는 것(수식 키 없이)은 지금과 같다 — 열고 키는 편집기로.
- 내용으로 맞은 행(필터 「필터가 내용도 찾는다」)은 Enter·⌘Enter 도 누르기와 같이 첫 일치 자리에 커서를 두고 연다.
- **필터 칸에서 ↓** 는 목록 상자로 키를 옮기고 첫 행을 지금 행으로 골라 둔다 **(코디네이터의 판단)**. 목록이 비었으면 아무것도 하지 않는다. 한글 조합 중의 ↓ 는 조합의 몫이라 옮기지 않는다.
- ⌘⌫·⇧F10 이 끝난 뒤 키는 목록에 남는다. 휴지통으로 옮긴 메모가 열려 있던 탭이 닫히며 편집기가 키를 가져가도 목록으로 되돌린다 **(구현자의 판단: 연달아 지울 수 있게)**.
- 지금 행이 휴지통으로 가거나 필터에서 빠지면 **같은 자리(같은 순번)의 행**이 지금 행이 되고, 고른 것이 비면 그 행을 고른다 **(구현자의 판단: ⌘⌫ 를 이어 누르면 다음 행이 지워진다. Finder 의 목록 보기와 같다)**. 목록이 비면 지금 행이 없다.

### 누르기

- **⌘클릭** — 그 행을 고른 것에 더하거나 뺀다. 열지 않는다 **(코디네이터의 판단)**. 그 행이 지금 행이 되고, 더한 행이면 기준 행도 된다. 뺀 행은 기준 행이 되지 않는다 — 기준 행은 그 전 자리 그대로다 **(구현자의 판단: 방금 뺀 행부터 ⇧ 범위를 잡으면 뺀 것이 도로 들어간다)**.
- **⇧클릭** — 기준 행부터 그 행까지를 고른다. 열지 않는다 **(코디네이터의 판단)**. 기준 행은 그대로다.
- 그냥 클릭 — 그 행만 고르고 연다(지금처럼). 지금 행·기준 행이 된다.
- 오른쪽 클릭(⌃클릭) — 고른 것 안의 행이면 고른 것 전체의 메뉴, 밖의 행이면 그 행만 고르고 그 행의 메뉴 **(구현자의 판단: Finder 와 같다)**.
- 누르기·키 어느 쪽이든 행 요소는 그 행의 모양(이름·미리보기·고정·활성)이 바뀔 때만 새로 만든다. **선택·지금 행 표시는 그려진 요소의 속성만 바꾼다** — 누른 채 행이 새로 만들어지면 놓을 때 `click` 이 오지 않는다(`placeChildren`, `src/ui/dom.ts`).

### 선택의 모양

- 고른 행은 `aria-selected="true"` 이고 배경이 텍스트 선택색(`--selection`, 테마 변수)이다 **(코디네이터의 판단: 테마 변수. 어느 변수인지는 구현자의 판단 — 편집기의 선택과 같은 뜻의 색)**.
- 다만 **목록 상자에 키가 없고 하나만 골랐으면 선택색을 칠하지 않는다 (구현자의 판단).** 그냥 클릭은 그 행을 고르고 키를 편집기로 보내므로, 칠하면 마우스만 쓰는 사람의 목록이 지금과 달라진다(활성 행 위에 선택색). 여럿을 골랐으면 키가 어디 있든 칠한다.
- 필터·정렬이 바뀌어 보이지 않게 된 행은 고른 것에서 빠진다 **(코디네이터의 판단)**. 다른 창이 그 메모를 지우거나 옮긴 때도 같다.

### 문맥 메뉴

메뉴는 **고른 것 전체에** 적용된다 **(코디네이터의 판단)**. 하나만 골랐으면 지금 메뉴(편의 기능 설계 「메뉴」) 그대로다. 둘 이상이면:

```
맨 위에 고정            (고른 것이 모두 고정이면 「고정 해제」)
복제
다른 워크스페이스로 옮기기  ▸
─────────
휴지통으로 이동
```

- 「이름 바꾸기…」·「Finder 에서 보기」·「경로 복사」 는 **빠진다** **(코디네이터의 판단: 하나일 때만. 끄지 않고 빼는 것은 구현자의 판단 — 팝업 항목에 `enabled` 가 없고, 편의 기능 설계가 옮길 곳 없는 「옮기기」 를 뺀 것과 같은 방식)**. 그 둘이 있던 구분선 묶음도 함께 빠진다.
- **고정:** 고정 안 된 것이 하나라도 섞여 있으면 「맨 위에 고정」 이고 고른 것 전부를 고정한다. 모두 고정이면 「고정 해제」 로 전부 푼다 **(코디네이터의 판단)**.
- **복제:** 고른 순서(목록 순서)대로 하나씩. 상태 표시줄 「N개를 복제했습니다」(하나면 지금처럼 「복제했습니다: <이름>」).
- **다른 워크스페이스로 옮기기:** 하나씩 옮긴다. 상태 표시줄 「N개를 <워크스페이스>로 옮겼습니다」. 열린 탭을 저장하지 못했거나 충돌 배너가 떠 있는 메모는 옮기지 않고(편의 기능 설계 「다른 워크스페이스로 옮기기」 그대로) 「N개를 …로 옮겼습니다 · M개는 옮기지 못했습니다」 를 오류로 알린다 **(구현자의 판단)**.
- **휴지통으로 이동:** 하나씩 옮긴다. 「N개를 휴지통으로 옮겼습니다」. 저장하지 못한 탭의 메모가 섞이면 「N개를 휴지통으로 옮겼습니다 · M개는 저장하지 못해 옮기지 않았습니다」 를 오류로, 하나도 못 옮겼으면 지금 문구(「저장하지 못해 휴지통으로 옮기지 않았습니다」) **(구현자의 판단)**. **하나를 옮길 때도 「1개를 휴지통으로 옮겼습니다」 를 알린다 (구현자의 판단: ⌘⌫ 는 묻지 않으므로 무엇이 일어났는지 말해야 하고, 메뉴로 옮길 때만 조용하면 두 길이 다르게 보인다).** 다른 창이 연 메모라 그 창으로 넘긴 것(`onTrashRequest`)은 이 창이 옮긴 수에 들지 않는다.
- 하나씩 하는 동안 한 메모에서 오류가 나도 나머지는 계속하고, 끝난 뒤 첫 오류를 지금처럼 알린다 **(구현자의 판단)**.

## 휴지통 목록

메모 목록과 같은 키·누르기·선택이다. 다른 점만 적는다.

- 목록 상자의 이름은 「휴지통 목록」. Tab 순서: 「← 메모」 → 휴지통 목록 → 「휴지통 비우기」.
- 필터 칸이 없으므로 첫 행의 ↑ 는 아무것도 하지 않는다.
- **Enter** 는 그 메모를 읽기 전용 탭으로 연다(행을 누를 때와 같다). 키 자리 규칙(목록에 남음, ⌘Enter·열린 행에서 Enter 는 편집기로)은 메모 목록과 같다.
- **⌘⌫ 는 영구 삭제다 — 되돌릴 수 없으므로 묻는다 (코디네이터의 판단).** 하나면 지금 문구 「「회의록.md」 를 영구 삭제할까요? 되돌릴 수 없습니다.」, 여럿이면 「고른 메모 N개를 영구 삭제할까요? 되돌릴 수 없습니다.」 **(구현자의 판단: 「휴지통 비우기」 의 「휴지통의 메모 N개를 …」 와 갈리게)**. 버튼은 「취소」(키를 받는다) 와 위험 스타일 「영구 삭제」. 닫히면 키는 목록 상자로 돌아온다.
- 문맥 메뉴: 하나면 지금(「복구」, 「Finder 에서 보기」, 구분선, 「영구 삭제」). 여럿이면 「복구」, 구분선, 「영구 삭제」 — 「Finder 에서 보기」 는 빠진다. 「영구 삭제」 는 위와 같이 한 번 묻고 고른 것 전부를 지운다.
- 휴지통 목록은 가상 스크롤이 아니다(행을 모두 그린다). 휴지통이 바뀔 때마다 행을 다시 만들지만 고른 것·지금 행은 메모 ID 로 이어진다.

## 이전 버전 목록 (대화상자)

- 왼쪽 목록이 `listbox`(이름 「버전」)이고 대화상자가 열리면 키를 받는다. 행은 `option`, 보이는 버전이 `aria-selected="true"`.
- ↑↓·Home·End 로 버전을 고르면 그 버전의 글이 오른쪽에 보인다(누를 때와 같다). **Enter 는 「이 버전으로 되돌리기」** 와 같다 — 글을 다 읽기 전에는 아무것도 하지 않는다 **(구현자의 판단: 되돌리기는 편집기의 실행 취소로 되돌릴 수 있다)**. Esc·「취소」 는 지금처럼 닫는다.

## 언어 고르기 (대화상자)

- 입력 칸이 `combobox`, 목록이 `listbox`(이름 「언어」), 행이 `option`. 키는 입력 칸에 그대로 있고 지금 고른 행은 `aria-activedescendant` 로 알린다(빠른 열기와 같은 꼴).
- **고른 행(강조):** 칸이 비어 있으면 지금 언어의 행, 글자가 있으면 보이는 첫 행이다. 이것은 지금 Enter 가 고르는 것과 같다 — 그래서 ↑↓ 를 누르지 않은 Enter 의 동작은 바뀌지 않는다. 칸이 비었고 지금 언어가 목록에 없으면 고른 행이 없고, ↓ 는 첫 행을 고른다.
- ↑↓ 로 고른 행을 옮기고 Enter 로 정한다. 고른 행은 목록에서 보이게 스크롤한다.

## 상태 표시줄

- 언어 표시는 `<button>` 이다. 접근 이름 「언어: <이름>」, `title` 은 지금처럼 「언어 바꾸기」. 누를 수 없을 때(휴지통 탭, 텍스트가 아닌 탭 — 휴지통 설계 「내용 보기」)는 `disabled` 다. 표시할 것이 없으면(열린 탭 없음) 빈 버튼이 `disabled` 로 남고 상태 표시줄이 숨는 규칙은 그대로다.
- 메시지 자리는 `role="status"` 다 — 상태 표시줄의 알림(「N개를 휴지통으로 옮겼습니다」 등)을 보조 기술이 읽는다.

## 겹치지 않는 키

- ⌘⌫·⌘A·⌘Enter·⇧F10 은 목록 상자(또는 대화상자의 목록)에 키가 있을 때만 받고 그때 기본 동작을 막는다. 앱 단축키 기본값(`src-tauri/src/shortcuts.rs`)과 편집기 키맵(`src/shortcuts/keys.ts`)에 이 조합이 쓰이지 않는다. ⌘A 는 메뉴 「편집 › 모두 선택」(네이티브 `selectAll:`)과 같은 조합이지만, WKWebView 는 키를 페이지에 먼저 주고 페이지가 막은 키는 메뉴로 넘기지 않는다. 그래서 목록 밖(편집기·필터 칸)의 ⌘A 는 그대로 「모두 선택」 이다.
- ⇧F10 은 macOS 의 시스템 단축키가 아니다. 다만 Mac 키보드는 기본 설정에서 맨 윗줄이 밝기·소리 키라(F10 은 음소거) **fn 과 함께** 눌러야 F10 이 앱에 온다(⇧fn F10). 시스템 설정 「F1, F2 등의 키를 표준 기능 키로 사용」 을 켜면 fn 없이 된다. 메뉴 키(`ContextMenu`)는 Mac 키보드에 없지만 외장 키보드를 위해 받는다.
- **키를 누르고 있으면(키 반복) 옮기는 키만 이어서 먹는다 (구현자의 판단, 리뷰 권고).** ↑↓·Page 를 누르고 있으면 계속 옮겨 가지만, ⌘⌫·Enter·⌘Enter·⇧F10·⌘A 는 누를 때 한 번만 하고 반복(`repeat`)은 받아 버린다. 반복을 받으면 ⌘⌫ 한 번마다 다음 행이 지금 행이 되므로, ⌘⌫ 를 0.5초쯤 누르고만 있어도 묻지 않고 메모 여러 개가 휴지통으로 간다. 휴지통 목록의 ⌘⌫ 는 첫 누름에 확인 창이 키를 가져가 반복이 목록에 오지 않는다.
- **키는 글자가 아니라 자리(`code`)로 읽는다 (구현자의 판단, 리뷰 권고).** 한글 입력기가 켜져 있으면 ⌘A 가 `key` 「ㅁ」 로 온다. 단축키 녹음(`acceleratorFromEvent`, `src/shortcuts/keys.ts`)과 같은 방식이다. ⌫·Enter·F10·화살표는 입력기가 글자를 바꾸지 않지만 같은 규칙으로 읽는다.
- 키로 연 문맥 메뉴는 마우스 포인터 자리에 뜬다 — 네이티브 팝업(`showPopupMenu`)이 자리를 받지 않는다. 지금 행 옆에 띄우는 것은 이번 범위 밖이다(보고서 「넘기는 것」).

## 데이터·저장

없다. 설정 키·세션 필드·백엔드 명령을 더하지 않는다. 선택은 창의 메모리에만 있다.
