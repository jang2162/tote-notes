# tote-notes 전역 「빠른 메모」 단축키·메뉴 막대 아이콘 설계

2026-11-14. 2026-11-13 점검 끝에 추천받은 기능 묶음의 하나다. 사용자는 설계 확인 없이 바로 진행하라고 했다. 그래서 결정마다 출처를 붙인다 — **코디네이터의 판단**(작업 지시서가 정한 것)과 **구현자의 판단**(지시서가 비워 둬서 만드는 사람이 정한 것). 바꾸고 싶으면 그 줄만 고친다.

## 왜

앱의 성공 기준은 「아무 때나 막 적고, 앱을 닫아도 그대로 남는 가벼운 메모 앱」 이다. 그런데 메모를 적으려면 tote 로 넘어와야 한다. 다른 앱을 쓰다가 바로 적는 길이 없다 — 단축키는 전부 메뉴(muda)의 앱 안 단축키라 tote 가 앞에 있을 때만 듣는다(`src-tauri/src/shortcuts.rs`, `src-tauri/src/app/menu.rs`). 앱은 창을 다 닫아도 macOS 관례대로 살아 있으므로(`src-tauri/src/lib.rs` 의 `RunEvent::ExitRequested` 에서 `prevent_exit`), 살아 있는 앱이 시스템 전체에서 키 하나를 들으면 된다.

## 하지 않는 것

코디네이터의 판단:

- 떠 있는 작은 빠른 메모 창. 빠른 메모는 보통 창의 보통 탭이다.
- 클립보드 내용을 바로 메모로.
- 메뉴 막대 아이콘의 최근 메모 목록.
- 앱 시작 시 자동 실행(로그인 항목). 앱이 꺼져 있으면 전역 단축키도 없다.

구현자의 판단:

- 전역 단축키를 「빠른 메모」 말고 더 두는 것. 표와 화면은 줄 여럿을 받게 짰지만 지금은 한 줄이다.
- 메뉴 막대 메뉴의 「빠른 메모」 항목에 전역 단축키를 표기하는 것. 메뉴 항목에 단축키를 걸면 그 메뉴가 열린 동안 키로도 실행되는데, 같은 키를 전역으로 이미 잡고 있어 무엇이 받는지 가르는 일이 생긴다.

## 동작

### 빠른 메모(코디네이터의 판단)

전역 단축키를 누르거나 메뉴 막대 메뉴의 「빠른 메모」 를 고르면, 다른 앱이 앞에 있든 tote 가 앞에 있든:

1. **가장 최근에 포커스된 워크스페이스 창**을 고른다(`AppCore::latest_window`, 메뉴 명령이 창 없이 실행될 때 고르는 창과 같다). 그 창을 앞으로 가져온다(최소화돼 있으면 펴고, 앱을 활성화한다 — `windows::focus`).
2. 창이 하나도 없으면 **가장 최근 워크스페이스**를 연다(`windows::open_latest` — Dock 아이콘을 눌렀을 때와 같다. 처음 실행이면 기본 워크스페이스를 만든다). 그 창에서 이어 간다.
3. 그 창에 「새 메모」 를 맡긴다. 창은 ⌘N(메뉴 「새 메모」)과 **같은 길**(`AppController.onMenu("new-memo")`)로 포커스 칸에 새 메모를 만들어 열고 편집기에 키를 준다.

맡기는 길은 `tote` 명령이 쓰는 대기열이다(구현자의 판단): Rust 가 그 창의 대기열에 `PendingOpen::NewMemo` 를 넣고 `tote://pending` 을 보낸다. 창이 막 열려 아직 페이지가 뜨지 않았거나 워크스페이스를 바꾸는 중이어도, 페이지가 준비되면 대기열을 가져가 그때 만든다(`AppCore::take_pending`). 버린 대안: `tote://menu` 로 `new-memo` 를 바로 보내는 것 — 막 연 창은 아직 듣지 않아 메모가 생기지 않는다.

- **⌘N 과 같은 규칙을 그대로 받는다**(구현자의 판단): 그 창에 대화상자(설정·확인 질문 등)가 떠 있으면 ⌘N 처럼 아무것도 만들지 않는다 — 창만 앞으로 온다. 대화상자에 친 글을 잃지 않게 하는 기존 규칙(`onMenu` 의 모달 가드)이다.
- **저장·닫기는 보통 메모와 같다**(코디네이터의 판단). 아무것도 적지 않은 채 닫으면 지금 규칙대로 파일도 지운다(`MemoDoc.startEmpty`).
- **창이 떠나는 중**(닫히는 중·종료 중)인 창이 가장 최근 창이면 그 창의 대기열은 버려진다. 이것은 `tote` 명령과 같은 한계다(구현자의 판단으로 받아들인다: 닫히는 몇백 ms 안에 누른 경우뿐이고, 다시 누르면 된다).

### 전역 단축키(코디네이터의 판단)

- 기본 키 **⌃⌥N**(`Ctrl+Alt+N`). ⌥⌘N 은 앱 안의 「새 창」 이다.
- 설정 › 단축키에 **「전역」 묶음**을 새로 둔다. 앱 명령 목록 위, 검색 칸 아래다(구현자의 판단: 전역 키는 다른 앱에도 걸리므로 먼저 보이게). 줄의 꼴은 앱 명령 줄과 같다 — 이름 「빠른 메모」, 그 오른쪽에 작게 「다른 앱에서도」(구현자의 판단: 앱 명령 줄의 메뉴 이름 자리), 지금 단축키(없으면 「없음」), 「기본값」(바뀐 줄은 「기본값 ⌃⌥N」), 바뀐 줄의 「되돌리기」.
- 단축키 칸을 누르면 앱 명령과 **같은 녹음기**로 녹음한다(같은 키 받기 규칙, Esc 취소, Backspace·Delete 는 「없음」, 녹음 중 메뉴 단축키 떼기). 「없음」 으로 저장하면 전역 단축키가 없다.
- 검색 칸은 전역 줄도 거른다(이름·단축키 표기, 앱 명령과 같은 규칙).
- **막는 키**(저장하지 않고 줄 아래에 이유):
  - 앱 명령이 지금 쓰는 키: 「〈명령 이름〉 에 쓰고 있는 단축키입니다」. **바꾸기는 없다**(코디네이터의 판단: 「앱 안 단축키와 같은 키는 막는다」).
  - 고정 단축키: 「〈이름〉 에 고정된 단축키입니다」(앱 명령과 같은 문구).
- **편집기 키와 겹치면** 저장하고 앱 명령처럼 경고한다: 「편집기의 〈명령〉 을 가립니다」(구현자의 판단: 전역 키는 tote 안에서도 먼저 잡히므로 편집기가 그 키를 받지 못하는 것이 사실이다).
- **거꾸로, 앱 명령 줄에서 전역 단축키가 쓰는 키를 녹음하면** 막는다: 「전역 단축키 〈빠른 메모〉 에 쓰고 있습니다」(구현자의 판단: 전역 키는 tote 안에서도 메뉴보다 먼저 잡혀 그 앱 명령이 키로 실행되지 않는다. 바꾸기는 없다 — 전역 줄에서 먼저 지우면 된다).
- **등록 실패**: macOS 가 키를 받아 주지 않으면 그 줄 아래에 「다른 앱이 쓰고 있어 등록하지 못했습니다」 를 보인다. 앱은 그대로 돌고, 다른 키를 녹음하면 다시 등록을 시도한다. 저장된 값은 그대로 둔다(구현자의 판단: 다른 앱이 키를 놓으면 다음 실행에서 등록된다).
  - 한계(구현자의 판단으로 받아들인다): macOS 의 `RegisterEventHotKey` 는 다른 앱이 같은 키를 **독점**(exclusive)으로 잡았을 때만 실패를 돌려준다. 독점 없이 잡은 앱과는 둘 다 등록되고 어느 쪽이 받는지는 macOS 가 정한다. 그때는 안내가 뜨지 않는다.

### 메뉴 막대 아이콘(코디네이터의 판단)

- 설정 「일반」 에 **「메뉴 막대에 아이콘 보이기」** 확인란. 기본 **끔** — 업데이트만으로 메뉴 막대가 바뀌지 않게.
- 켜면 메뉴 막대에 tote 아이콘이 생긴다. 끄면 바로 사라진다(모든 창에 바로 적용되는 다른 설정과 같다).
- 아이콘은 **템플릿 이미지**다 — macOS 가 라이트·다크 메뉴 막대에 맞게 칠한다. 앱 아이콘(`src-tauri/icons/icon.png`, 고리 두 개)의 불투명한 부분을 검정 한 색으로 바꾼 36×36 PNG(`src-tauri/icons/tray-template.png`, 메뉴 막대 높이 18pt 의 2배)다. 만든 법(구현자의 판단): 512px 원본의 알파를 그대로 두고 색을 검정으로 바꾼 뒤 36px 로 줄였다(Pillow, `Image.LANCZOS`). 원본 아이콘이 바뀌면 같은 방법으로 다시 만든다.
- 아이콘을 누르면 **메뉴만** 뜬다(macOS 관례). 메뉴:
  - 「빠른 메모」 — 위 「빠른 메모」 와 같다.
  - 「Tote Notes 열기」 — 가장 최근에 포커스된 창을 앞으로, 창이 없으면 가장 최근 워크스페이스를 연다(구현자의 판단: Dock 아이콘을 누른 것과 같은 결과).
  - 구분선
  - 「종료」 — 메뉴 「Tote Notes 종료」 와 같은 길(쓰지 못한 편집을 쓰고 끝낸다, `lifecycle::begin(…, FlushGoal::Quit)`).
- 메뉴 항목 id 는 `tray:quick-note`·`tray:open`·`tray:quit` 이다. 메뉴 이벤트는 앱 메뉴와 같은 처리기(`menu::on_event`)로 오므로 `tray:` 로 시작하는 id 는 메뉴 막대 항목으로 실행하지 않고 트레이로 보낸다(구현자의 판단: 「종료」 가 앱 메뉴의 `quit` 과 이름이 겹치지 않게).

## 권한과 개인정보(코디네이터의 판단, 구현자가 확인)

- 전역 단축키는 Tauri 공식 `tauri-plugin-global-shortcut`(2.x, Rust 쪽만)으로 건다. 그 밑의 `global-hotkey`(0.8)는 macOS 에서 Carbon `RegisterEventHotKey` 로 키를 건다(`platform_impl/macos/mod.rs`) — **손쉬운 사용·입력 모니터링 권한이 필요 없고 권한 대화상자가 뜨지 않는다.**
  - 예외: 미디어 키(재생·다음 곡 등)는 `CGEventTap` 으로 잡아 입력 모니터링 권한이 든다. 그래서 **미디어 키는 전역 단축키로 받지 않는다**(구현자의 판단) — 녹음기는 미디어 키를 받지 않고(웹뷰에 오지 않는다), settings.json 을 손으로 고친 미디어 키 항목은 버린다.
- JS 패키지(`@tauri-apps/plugin-global-shortcut`)는 넣지 않는다. 등록은 Rust 가 하므로 페이지가 부를 플러그인 명령이 없다. 그래서 `capabilities/default.json` 에 권한을 **하나도 더하지 않는다**(구현자의 판단: 권한 최소).
- 메뉴 막대 아이콘은 `tauri` 의 `tray-icon` 기능으로 만든다. 권한이 필요 없다.

## 데이터·저장

settings.json(구현자의 판단: 이름과 꼴. 기존 `shortcuts` 를 본떴다):

```json
{
  "globalShortcuts": { "quick-note": "Ctrl+Alt+Shift+N" },
  "tray": { "visible": true }
}
```

- `globalShortcuts`: 전역 명령 id → 단축키 문자열 또는 `null`(없음). **기본값과 다른 것만** 적는다. 없으면 기본값. 문자열은 앱 단축키와 같은 Tauri accelerator 표기다.
- 읽을 때 **항목마다** 검사하고 그 항목만 버린다(`lenient`): 모르는 id, 문자열도 `null` 도 아닌 값, 파싱할 수 없는 것(muda 와 `global-hotkey` 의 파서 둘 다 읽어야 한다), 녹음 규칙(⌘·⌃·⌥ 중 하나 + 키, 또는 보조키 없는 F1~F12)에 맞지 않는 것, 미디어 키, 고정 단축키, **앱 명령이 쓰는 키**(그 앱 명령의 키가 기본값이든 저장값이든). 필드 모양 자체가 틀리면 `globalShortcuts` 만 기본값이다. 앱 명령과의 겹침은 두 필드를 다 읽은 뒤에 본다(`Settings::load_with_aside`).
- **기본값 ⌃⌥N 은 앱 명령에 양보한다**(구현자의 판단): 이 판 전에 사람이 ⌃⌥N 을 앱 명령에 걸어 두었으면 그 키가 이기고 빠른 메모는 전역 키 없이 시작한다(표의 `yielded`). 양보하지 않으면 업데이트만으로 사람이 쓰던 앱 단축키가 tote 안에서 실행되지 않게 된다(전역 키가 먼저 잡는다). 그 앱 명령의 키가 풀리면 ⌃⌥N 으로 돌아온다. 앱 명령의 `yielding` 과 같은 규칙이다.
- `tray.visible`: 기본 `false`. 잘못된 값은 `false`.
- 패치(`SettingsPatch`): `globalShortcuts`(전체 맵 — 빠진 id 는 기본값으로), `trayVisible`. 패치를 적용한 뒤의 상태에서 **저장된 전역 항목 하나라도** 위 규칙으로 버려질 것이면 패치 전체를 거절한다(`bad-request` 「전역 단축키를 저장할 수 없습니다: quick-note」). 앱 명령 맵만 바꾸는 패치가 저장된 전역 키를 가져가려 해도 같이 거절된다. 기본값(저장 항목 없음)인 전역 키를 앱 명령이 가져가는 패치는 받는다 — 전역 키가 양보한다(설정 화면은 이 경우도 막는다, 위 「막는 키」).
- 설정이 바뀌면(`patch_settings`) 전역 키를 다시 건다(바뀌지 않았으면 그대로 둔다)와 메뉴 막대 아이콘을 맞춘 뒤 `tote://config` 를 보낸다. 설정 화면은 그것을 듣고 전역 표를 다시 읽는다.
- 전역 표: 새 명령 `global_shortcut_table`(`Backend.globalShortcutTable`)이 줄마다 `id`·`label`·`default`·`current`·`yielded`(양보했을 때만)·`problem`(등록 실패 문구, 없으면 빠짐)을 준다.

## 시험

- Rust(`src-tauri/src/global_shortcuts.rs`): 기본값, 지움, 잘못된 항목만 버려짐(`lenient`), 앱 명령 키·고정 키·미디어 키 거절, 기본값의 양보, 패치 거절(전역 패치, 앱 명령 패치가 전역 키를 가져갈 때), 미디어 키가 아닌 키는 `global-hotkey` 로 읽힘.
- Rust(`src-tauri/src/appdata.rs`): `tray.visible` 기본 끔·잘못된 값, `globalShortcuts` 를 읽을 때 앱 명령과 겹친 항목이 버려짐.
- Rust(`src-tauri/src/app/quick_note.rs`): 빠른 메모가 고르는 창 — 가장 최근 포커스 창, 창이 없으면 최근 워크스페이스 열기. 대기열에 `NewMemo` 가 들어가고 JSON 이 `{"kind":"newMemo"}` 다.
- Rust(`src-tauri/src/app/tray.rs`): 메뉴 항목의 id·이름·순서, `tray:` id 의 경로.
- e2e(`tests/e2e/global-shortcut.spec.ts`, 가짜 백엔드): 설정 › 단축키의 전역 줄 녹음·지우기·되돌리기, 앱 명령 키·고정 키 거절 문구, 앱 명령 줄에서 전역 키 거절, 등록 실패 문구, 「빠른 메모」 이벤트(가짜의 `quickNote()`)로 새 메모가 열리고 편집기에 키, 대화상자가 떠 있으면 만들지 않음, 「일반」 의 메뉴 막대 확인란 저장.
- 사람 확인(실기기): 다른 앱이 앞일 때 ⌃⌥N, 창을 다 닫았을 때 ⌃⌥N, 다른 앱이 독점으로 잡은 키의 등록 실패 문구, 메뉴 막대 아이콘의 라이트·다크와 메뉴 세 항목.

## 겹침 확인(구현자의 판단으로 확인한 것)

- ⌃⌥N 은 앱 명령의 기본 단축키(`shortcuts::COMMANDS`)·고정 단축키(`shortcuts::FIXED`)와 겹치지 않는다 — Rust 시험 `the_default_is_no_app_or_fixed_key` 가 본다. 편집기 키맵에도 없다 — vitest `src/shortcuts/global.test.ts` 가 `conflict()` 로 본다.
- macOS 시스템 전역 키: ⌃⌥N 은 macOS 기본 단축키(시스템 설정 › 키보드 › 단축키)에 없다. 손쉬운 사용의 VoiceOver 키(⌃⌥ 조합)는 VoiceOver 를 켰을 때만 ⌃⌥ 를 가져간다 — VoiceOver 사용자는 다른 키로 바꾸거나 지우면 된다.
