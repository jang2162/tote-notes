# 워크트리가 함께 쓰는 자원

## 머신 전역 자원은 워크트리가 공유한다 — 포트를 잡는 것은 줄 세운다

포트·소켓처럼 머신 하나에 하나뿐인 자원은 워크트리를 나눠도 나뉘지 않는다.

- **Why:** 고정 포트를 잡는 프로세스가 두 워크트리에서 동시에 뜨면, 늦게 뜬 쪽이 **조용히 다른 포트로 옮겨 바인딩되는** 경우가 있다. 예외도 경고 로그도 없이 시작에 성공하므로, 상대를 고정값으로 찾는 코드는 영원히 상대를 못 찾는다. 증상은 **「불안정한 시험」**으로 보인다 — 따로 돌리면 통과하고, 전체를 돌리면 가끔 떨어지고, 다른 트리에서 돌리면 안 떨어진다. 그래서 「부하에서 대기가 모자라다」로 오진하기 쉬운데 실제로는 **대기 시간과 무관하다.**
- **How to apply:**
  - 개발 서버처럼 워크트리마다 포트를 나눌 수 있는 것은 **워크트리별 포트를 할당**한다. 프로젝트에 그 장치가 있으면 워크트리를 만든 직후 돌린다.
  - ⚠ **포트만 갈라서는 부족하다 — 쿠키는 포트를 구분하지 않는다.** 세션 쿠키는 **호스트 단위**라, 이름을 그대로 두면 두 인스턴스가 **한 칸을 두고 서로를 덮는다.** 한쪽에 로그인하는 순간 다른 쪽 세션이 끊기고 반대도 같으며, **끊긴 탭은 자동 로그인으로 되살아나지 않을 수 있다.** 포트를 바꿀 때 **세션 쿠키 이름도 함께 가른다**(포트를 붙여 지으면 충돌하지 않는다). 자기 주소를 되돌려 주는 설정(공개 포트·포털 URL 등)이 따로 있으면 **그것도 같이 바꾼다** — 하나만 바꾸면 링크와 리다이렉트가 옛 인스턴스로 넘어간다.
  - 고정 포트를 잡는 전체 시험은 **한 번에 한 워크트리에서만** 돌린다. 여러 워커에게 시켜야 하면 전체 실행만 줄 세우고 나머지 작업은 겹쳐도 된다.
  - 떨어진 직후 그 포트를 잡고 있는 것이 있는지 본다. 다른 워크트리가 잡고 있으면 그것이 원인이다.
    ```bash
    lsof -nP -iTCP:<포트> -sTCP:LISTEN
    ```
  - ⚠ **브랜치 비교에 이 조건을 통제하지 않으면 결론이 뒤집힌다.** 「기준 브랜치는 3회 통과, 이 브랜치는 1회 실패」를 근거로 브랜치를 의심하게 되는데, 실제로 갈린 것은 **그때 옆에서 무엇이 돌고 있었는가**다.
